1. Ünite: İnternet ve Web

Ünitenin Amacı: E-ticaretin teknik temelini oluşturan İnternet ve World Wide Web (WWW) kavramlarını ayırt etmek, İnternet'in başlangıç noktası olan ARPANET'in ve paket anahtarlama teknolojisinin tarihçesini incelemek, TCP/IP katmanlı iletişim mimarisini, IP adresleme ve alan adı (DNS) sistemini, Web tarayıcıları ile URL yapısını kavramaktır.

1.1. Temel Kavramlar

İnternet, Türkçeleşmiş bir terim olmakla birlikte kökeni "ağlar arası çalışma" anlamına gelen internetworking sözcüğünden gelir. Esas karşılığı, pek çok ağı birbirine bağlayan küresel bir ağdır. Ağa doğrudan bağlı bazı bilgisayarların sürekli aktif olması sayesinde, sıradan bir kullanıcı her bağlandığında istediği veriye erişebilir. Günümüzde yüz binleri aşan ağ ve yüz milyonlarla ifade edilen bireysel kullanıcı, İnternet Hizmet Sağlayıcıları (İSS) aracılığıyla internete bağlanmaktadır.

İnternet'in temeli, 1970'li yılların başlarında ABD Savunma Bakanlığı tarafından bilgisayarların zarar görmesi durumunda dahi haberleşmeyi sürdürebilmek ve bilim insanlarını birbirine bağlamak amacıyla yürütülen bir araştırmaya dayanır. Bu doğrultuda ARPANET adı verilen küçük bir ağ üzerinde denemeler yapılmış; ardından ABD Ulusal Bilim Kurulu (National Science Foundation - NSF) ülkenin farklı yerlerine yerleştirdiği çok pahalı 6 adet süper bilgisayarı araştırmacıların hizmetine sunmuştur (Gökçen, 2005; Laudon ve Laudon, 2006).

Amerika Federal Ağ Oluşturma Konseyi'nin (1995) İnternet Tanımı:
Konsey, interneti aşağıdaki üç temel karakteristiğe göre açıklanabilen küresel bir enformasyon sistemi (ES) olarak tanımlamıştır:
  • İnternet Protokolü'nü (IP) temel alarak, eşsiz birer adresle birbirine bağlı bilgisayarlar ve diğer cihazlardan oluşan bir ağdır.
  • Ağ cihazlarının (bilgisayarlar, yönlendiriciler, göbekler vb.) TCP/IP veya buna uyumlu protokolleri kullanarak haberleşebildiği bir ağdır.
  • Haberleşme ve ağ altyapısında üst seviyede yer alan hizmetleri sağlayan bir ağdır.

İnternet Teknolojileri ve İşletme Performansı: Soto-Acosta ve Merono-Cerdan (2008) tarafından yapılan araştırmaya göre, internet teknolojileri ile işletme performansı arasında doğrudan pozitif bir ilişki tespit edilememiştir. Ancak internet teknolojileri ile işletme içi işlemler ve tüketiciye yönelik e-ticaret arasında pozitif bir ilişki; ayrıca e-ticaret ile işletme performansı arasında da pozitif bir ilişki saptanmıştır. Dolayısıyla internet teknolojileri, e-ticaret kullanımı sayesinde dolaylı yoldan işletme performansını olumlu etkilemektedir.

Web (World Wide Web) ve Tarayıcıların Gelişimi: Web, internetin en yaygın kullanılan hizmetidir. İstemci-sunucu ilişkisi içerisinde biçim uyuşmazlıklarını önlemek amacıyla evrensel standartlar geliştirilmiştir (HTTP, HTML, XML, FTP, RSS, Blog, Podcasting, Anında Mesajlaşma ve Çerezler). Bu standartlar ilk olarak 1989 yılında belirlenmiştir ve başlangıçta Web yalnızca metin temelliydi. Web tarayıcılarının tarihsel gelişimi şöyledir:

Yıl Tarayıcı Önemi

Web sayfaları yardımlı metin (hypertext) ile biçimlendirilir ve içlerine gömülmüş bağlar (link) aracılığıyla ses, resim, görüntü ve animasyon gibi diğer doküman ve nesnelere erişim sağlar.

1.2. ARPANET

Gelişmiş Araştırma Projeleri Ajans Ağı (ARPANET), dünyanın ilk operasyonel paket anahtarlama ağlarından olan ve TCP/IP'yi uygulayan ilk ağdır; küresel internetin öncüsüdür. Başlangıçta ABD Savunma Bakanlığı projelerinde ve araştırma laboratuvarlarında kullanılmak üzere ARPA (daha sonra DARPA) tarafından finanse edilmiştir. Paket anahtarlama tasarımı Amerikalı mühendis Paul Baran, İngiliz bilim adamı Donald Davies ve Lincoln Laboratuvarı'ndan Lawrence Roberts'ın konseptlerine dayanır. TCP/IP iletişim protokolleri ise bilgisayar bilimcileri Robert Kahn ve Vinton Cerf tarafından ARPANET için geliştirilmiştir.

1.2.1. TCP/IP

İletim Kontrol Protokolü (TCP) ve İnternet Protokolü (IP), internet iletişiminde üst üste geçmiş katmanlar halinde çalışan temel protokollerdir:

  • Uygulama Katmanı: Kullanıcı düzeyindeki protokollerdir. HTTP Web sayfalarının tarayıcı aracılığıyla aktarımını, FTP ise yazılımlar vasıtasıyla dosya aktarımını sağlar.
  • Taşıma Katmanı (TCP / UDP): Uygulama katmanından gelen veri alt katmana iletilir. Yaygın olarak kullanılan TCP, veriyi parçalara ayırır ve her parçanın başına alıcıda doğru birleştirilebilmesi için sıra numarası ekler. Aynı amaçla kullanılan UDP (Kullanıcı Veri Bloğu Protokolü) ise veriyi parçalara ayırmadığından yalnızca kısa verilerin gönderilmesinde kullanılır.
  • Ağ / IP Katmanı: TCP katmanında düzenlenen verinin gideceği adres ve rota IP katmanında belirlenir.
Ana Sistem (Host), Yerel Ağ ve Statik / Dinamik IP:
İnternete doğrudan bağlı olan bilgisayara ana sistem (host) veya sunucu denir. Bir yerel ağdaki (LAN) istemci bilgisayarlar internete doğrudan değil, çıkış noktasındaki bir ana sistem veya yönlendirici (router) üzerinden bağlanır. Tüm yerel ağ tek bir dış IP ile internete çıkabilir; yönlendirici yerel ağ IP numaralarını saklayarak gelen veriyi doğru iç bilgisayara iletir. Sunucuların adreslerinin bilinebilmesi için kalıcı yani statik IP numarasına sahip olması gerekirken, ev kullanıcıları gibi istemciler genellikle İSS tarafından her bağlantıda değiştirilebilen dinamik (değişken) IP numaraları alır.

1.2.2. Tarihçe

Paket anahtarlama öncesinde hem ses hem veri iletişimi, geleneksel telefon şebekelerinde olduğu gibi iki istasyon arasında özel ve uçtan uca tek bir elektronik bağlantı tahsis edilen devre anahtarlama mantığına dayanıyordu; veri parçalara ayrılmadan bütün olarak aktarılırdı. Paket anahtarlama ise verileri hat boşaldıkça paketler halinde hatta aktararak tek bir iletişim linkinin birden fazla makine tarafından paylaşılmasını ve her paketin diğerlerinden bağımsız yönlendirilmesini mümkün kıldı.

Genel bilgisayar ağına ilişkin ilk fikirler Nisan 1963'te bilgisayar uzmanları Licklider, Bolt, Beranek ve Newman tarafından "Galaksiler Arası Bilgisayar Ağı" konsepti tartışılırken yazıldı. Licklider'ın ardından Ivan Sutherland ve Bob Taylor bu vizyonu sürdürdü. Bob Taylor, her biri ayrı ARPA bilgisayarına bağlı üç farklı terminale (Santa Monica'da SDC Q-32, Berkeley'de Project Genie, MIT'de Multics) sahipti ve üç ayrı komut seti kullanmak yerine tek bir terminalden her yere bağlanabilme fikrini ortaya attı—bu fikir ARPANET oldu. Bağımsız olarak paket anahtarlama üzerinde çalışan Ulusal Paket Laboratuvarı (NPL) ise ilk halka açık sunumunu 5 Ağustos 1968'de Büyük Britanya'da gerçekleştirdi.

1.3. İnternet Adresleri

İnternet, veri ve bilginin doğru hedefe ulaşması için benzersiz bir adresleme sistemine dayanır:

  • IP Adresi (IPv4 ve IPv6): İnternete bağlı her bilgisayarı veya cihazı benzersiz şekilde tanımlayan sayıdır. Geleneksel IPv4 adresleri noktalarla ayrılmış 4 sayı grubundan oluşur ve her gruptaki sayı 0 ile 255 arasındadır (ör. 72.14.207.99). İlk kısım ağı, son kısım belirli bilgisayarı tanımlar. İnternetin büyümesiyle IP adreslerinin yetersiz kalması üzerine, mevcut adres sayısını artıran IPv6 (altı sayı grubu / yeni nesil adresleme biçimi) kullanılmaya başlanmıştır.
  • Alan Adı (Domain Name): Sayısal IP adreslerini hatırlamak zor olduğundan kullanılan metin karşılığıdır (ör. www.google.com ↔ 72.14.207.99). İlk noktaya kadar olan www sunucu türünü (Web sunucusu), son kısım ise üst seviye alan adını (ör. com = ticari kuruluş) gösterir. ABD dışındaki ülkelerde iki harfli ülke kodu (ör. Türkiye için tr) eklenir.
  • ICANN ve Registrar: Üst seviye alan adlarını atayan ve denetleyen kuruluş ICANN (İnternet Tahsisli Sayılar ve İsimler Kurumu)'dur. biz, com, info, name, net, org gibi alan adlarını satan ve yöneten kuruluşlara registrar denir.
  • DNS (Alan Adı Sistemi): Alan adlarını ve bunlara karşılık gelen IP adreslerini depolayan ve alan adını ilişkili IP adresine çevirerek veriyi doğru bilgisayara yönlendiren sistemdir.

1.4. Dünya Çapında Ağ (World Wide Web)

World Wide Web (WWW), internetle eş anlamlı değildir; internetin (1960'ların sonu) üzerinde 1990'ların başında ortaya çıkmış bir hizmetidir. Metin, grafik, animasyon, ses ve video içeren dünya çapındaki elektronik belgeler (Web sayfaları) koleksiyonudur.

  • Statik Web Sayfaları: Sabittir; tüm ziyaretçiler aynı içeriği görür.
  • Dinamik Web Sayfaları: Değişkendir; ziyaretçiler hisse senedi fiyatları, hava durumu veya uçak bileti müsaitliği gibi içeriğin bir kısmını ya da tamamını özelleştirebilir.
  • Web Sitesi ve Web Sunucusu: Web sitesi, bir Web sunucusunda depolanan ilgili Web sayfaları ve resim/belge ögelerinin toplamıdır. Bir Web sunucusu istenen sayfaları istemciye iletir ve aynı sunucu birden fazla Web sitesini barındırabilir.
  • Web 2.0: Kullanıcıların kişisel bilgi paylaşmalarına (sosyal ağlar), içeriği değiştirmelerine (wikiler) ve site içi uygulama yazılımlarını (e-posta, kelime işlem) kullanmalarına olanak tanıyan Web sitelerini ifade eder.

1.4.1. Web'de Gezinme

Kullanıcıların Web sayfalarına erişmesini ve Web 2.0 programlarını kullanmasını sağlayan uygulama yazılımına Web tarayıcısı denir (Internet Explorer, Firefox, Opera, Safari, Google Chrome). Akıllı telefon gibi küçük ekranlı ve sınırlı işlem güçlü mobil cihazlar ise mikro tarayıcı adı verilen özel tarayıcıları kullanır.

Ana Sayfa (Giriş Sayfası) terimi iki anlamda kullanılır: (1) tarayıcı açıldığında görüntülenen ilk başlangıç sayfası; (2) bir Web sitesinin içindekiler tablosu/kitap kapağı işlevi gören ilk sayfası (ör. iGoogle gibi kişiselleştirilebilir giriş sayfaları). Sayfalar arasındaki yerleşik bağlantılara bağ (hiperlink) denir. Bir Web sayfasının sunucudan bilgisayara alınması işlemine indirme denir; indirme süresi internet hızına ve grafik miktarına bağlıdır.

1.4.2. Web Adresleri

Her Web sayfasının URL (Uniform Resource Locator - Tek Tip Kaynak Bulucu) adı verilen benzersiz bir adresi vardır (ör. http://www.istanbul.edu.tr/tr/content/yonetim/rektorluk). Bir Web adresi üç ana bileşenden oluşur:

URL = Protokol (http://) + Alan Adı (www.istanbul.edu.tr) + Yol (/tr/content/yonetim/rektorluk)

Tarayıcıların çoğu adres çubuğuna http:// ve www kısımlarının yazılmasını zorunlu tutmaz. Sık ziyaret edilen sayfalara hızlı erişmek için tarayıcılarda kaydedilen adreslere yer imi (bookmark) veya favori denir. Ayrıca bazı Web sunucuları spor sonuçları veya hava durumu gibi güncellemeleri düzenli aralıklarla kullanıcı ekranına gönderebilir.

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Dikkat Edilmesi Gereken Temel Noktalar:
  1. İnternet vs. Web: İnternet, internetworking (ağlar arası çalışma) kavramından gelir ve 1960'ların sonu/1970'lerin başında ABD Savunma Bakanlığı'nın ARPANET araştırmasıyla doğmuştur. Web (WWW) ise internetin 1990'ların başında ortaya çıkan bir hizmetidir.
  2. Tarih ve İsimler: İlk ağ fikri Nisan 1963'te Licklider, Bolt, Beranek ve Newman'ın "Galaksiler Arası Bilgisayar Ağı" tartışmasına dayanır. ARPANET paket anahtarlama mimarisinde Paul Baran, Donald Davies ve Lawrence Roberts; TCP/IP protokollerinde ise Robert Kahn ve Vinton Cerf öne çıkar. İlk grafik tarayıcı Mosaic (1993), ilk ticari tarayıcı Netscape Navigator (1994), Chrome (2008).
  3. IP Adresi Kuralı: IPv4 dört sayı grubundan oluşur ve her grup 0–255 aralığındadır! Örneğin 257.14.207.99 (257 > 255 olduğu için) veya 72.14.207.99.40.44.10 (7 grup olduğu için) geçerli bir IPv4 adresi değildir; 72.14.207.99 geçerlidir.
  4. TCP vs. UDP: TCP veriyi parçalara ayırır ve sıra numarası ekler; UDP parçalara ayırmaz, kısa verilerde kullanılır.
  5. Alan Adı ve DNS: Alan adlarını denetleyen kurum ICANN, satan kuruluş registrar, alan adlarını IP'ye çeviren sistem DNS'tir.

2. Ünite: HTTP, HTTPS, HTML ve XML I

Ünitenin Amacı: Web enformasyonunun iletimini sağlayan HTTP protokolünün temel özelliklerini, istemci-sunucu mimarisini ve protokol parametrelerini (sürüm, URI, tarih/saat, karakter kümesi, içerik/transfer kodlama, medya türleri, ürün belirteçleri, kalite değerleri, dil, varlık ve menzil birimleri) öğrenmek; güvenli iletişim sağlayan HTTPS protokolünü, simetrik ve açık anahtarlı şifreleme yöntemlerini, SSL/TLS ile Açık Anahtar Altyapısı (PKI) ve Onay Makamlarının (CA) işleyişini kavramaktır.

2.1. Temel Kavramlar

Web enformasyonunu aktarmak için kullanılan protokole Hiper Metin Aktarım Protokolü (HTTP), güvenlik açısından geliştirilmiş sürümüne ise Güvenli Hiper Metin Aktarım Protokolü (HTTPS) denir. Her Web sunucusunun bir örnek kaynak bulucu (URL) adı verilen adresi vardır. Arka planda bu adres sayısal bir IP numarasıdır; ancak akılda kalıcı olması için harflerle ifade edilen eşsiz alan adları (domain name) kullanılır.

Alan adı hiyerarşisinde en üst seviyede temsili olarak "." işaretiyle gösterilen kök alan yer alır. Üst seviye alanda ülke kısaltmaları bulunur (ör. Türkiye için tr). Bunun tek istisnası ABD'dir; ABD için ülke kısaltması kullanılmaz. Hiyerarşinin sonunda ana sistem (host) olan bilgisayar gösterilir ve gerekli olmamakla birlikte çoğu alan adının başında www yer alır. Girişimciler alan adının anlamlı olmasını çok önemli görse de geçmiş deneyimler Amazon.com ve Google.com gibi ilk bakışta anlamı bilinmeyen alan adlarının da küresel ölçekte başarıya ulaşabildiğini göstermiştir.

2.2. Hipermetin Aktarım Protokolü (HTTP)

HTTP, dağıtılmış, işbirlikçi hiper medya bilgi sistemleri için uygulama düzeyinde bir iletişim protokolüdür ve 1990'dan beri World Wide Web veri iletişiminin temelidir. İstek yöntemlerinin uzantılarını, hata kodlarını ve başlıklarını kullanan genel ve durum denetimsiz bir protokoldür. TCP/IP tabanlı olup HTML dosyaları, resim dosyaları ve sorgu sonuçlarını sunmak için kullanılır; varsayılan bağlantı noktası TCP 80'dir.

Kitap, RFC-2616 teknik özellikleriyle tanımlanan HTTP/1.1 sürümünü temel alır. Orijinal HTTP/1.0 ile HTTP/1.1 arasındaki temel fark şudur:

HTTP/1.0 vs. HTTP/1.1 Farkı:
HTTP/1.0 her istek-yanıt alışverişi için yeni bir bağlantı açarken; HTTP/1.1 tek bir bağlantıyı bir veya daha fazla istek-yanıt alışverişi için kullanabilir (kalıcı bağlantı).

2.2.1. Temel Özellikler

HTTP'yi basit ama güçlü kılan üç temel özellik vardır:

  1. Bağlantısızdır (Connectionless): İstemci (tarayıcı) bir HTTP isteği başlatır ve yanıtı bekler; sunucu isteği işleyip yanıtı döndürdükten sonra bağlantı kesilir. Sonraki talepler yeni bağlantılar üzerinden yapılır.
  2. Medyadan Bağımsızdır (Media Independent): Hem istemci hem sunucu veri içeriğinin nasıl işleneceğini bildiği sürece herhangi bir veri türü HTTP üzerinden gönderilebilir (içerik türü belirtilmek şartıyla).
  3. Durum Denetimsizdir (Stateless): Bağlantısız yapının doğrudan bir sonucudur. Sunucu ve istemci yalnızca geçerli bir istek süresince birbirinden haberdardır; sonrasında birbirlerini unuturlar ve farklı istekler arasındaki durum bilgisi protokol düzeyinde korunmaz.

2.2.2. Temel Mimari

HTTP, tarayıcıların, robotların ve arama motorlarının istemci; Web sunucusunun ise sunucu gibi davrandığı istemci-sunucu tabanlı bir istek-yanıt protokolüdür. Temel Web uygulaması mimarisinde (Çizim 2) dört ana bileşen etkileşim içindedir: Web İşlemci (İstemci) ↔ Web Sunucusu ↔ Sunucudaki Komut Dosyası ↔ Veri Tabanı.

  • HTTP İsteği Biçimi: İstemci sunucuya bir istek yöntemi, URI ve protokol sürümü biçiminde bir istek gönderir; ardından istek düzenleyicileri, istemci bilgileri ve TCP/IP bağlantısı üzerinden gövde içeriğini içeren mesaj gelir.
  • HTTP Yanıtı Biçimi: Sunucu, mesajın protokol versiyonunu ve bir başarı veya hata kodunu içeren bir durum satırıyla yanıt verir; ardından sunucu bilgileri, varlık meta bilgileri ve gövde içeriğini içeren mesaj gelir.

2.2.3. Protokol Parametreleri

HTTP istemci ve sunucu yazılımlarında istek/yanıt mesajlarının doğru oluşturulabilmesi için 12 temel protokol parametresi tanımlanmıştır:

# Parametre Temel Kural, Sözdizimi ve Örnek
2.2.3.1 HTTP Versiyonu <major>.<minor> biçimindedir. Mesaj formatı değişirse major, ayrıştırmayı bozmayan yeni özellik/semantik eklenirse minor artar. Ayrı tam sayılardır: HTTP/2.4 < HTTP/2.13 < HTTP/12.3. Baştaki sıfırlar gönderilmez ve göz ardı edilir.
2.2.3.2 Tek Tip Kaynak Tanımlayıcıları (URI) URI = URL (Tek Tip Kaynak Belirleyicisi) + URN (Tek Tip Kaynak Adı) birleşimidir. URN kaynağı bir isim alanında ada göre tanımlar ancak nasıl elde edileceğini belirtmez (XML Şemalarında görülür). URL ise kaynağın ağ konumunu ve nasıl elde edileceğini belirtir (http://ornek.com, ftp://ornek.com, smb://ornek.com).
2.2.3.3 Tarih / Saat Biçimleri 3 format kabul edilir: (1) Sun, 06 Nov 1994 08:49:37 GMT (RFC 1123 - standart olarak tercih edilen ve üretilmesi gereken biçim), (2) Sunday, 06-Nov-94 08:49:37 GMT (eski RFC 850), (3) Sun Nov 6 08:49:37 1994. Tüm tarihler istisnasız GMT (= UTC) ile temsil edilir; büyük/küçük harfe duyarlıdır ve özel karakter içermez.
2.2.3.4 Karakter Kümesi MIME tanımını kullanır; 1 byte veriyi karakter dizisine dönüştüren tablo eşlemesidir (ASCII'den ISO-2022'ye). En yaygın küme ISO-8859-1'dir. Alıcının tahmin etmesini engellemek için Content-Type başlığında karakter kümesi açıkça belirtilmelidir.
2.2.3.5 İçerik Kodlama Bir varlığa (belgeye) ortam türünün kimliğini kaybetmeden ve bilgi kaybı olmadan uygulanan sıkıştırma veya dönüşümü belirtir; kodlanmış halde saklanıp doğrudan iletilir.
2.2.3.6 Transfer Kodlama Ağ üzerinden "güvenli taşıma" sağlamak için varlık/gövde üzerine uygulanır. Orijinal varlığın değil mesajın bir özelliğidir. Değerleri büyük/küçük harf duyarsızdır.
2.2.3.7 Medya Türleri Content-Type ve Accept başlıklarında RFC 1590'a göre IANA'ya kayıtlı medya türleri (application, audio, image, video) kullanılır. Tür, alt tip ve öznitelik adları büyük/küçük harf duyarsızdır.
2.2.3.8 Ürün Belirteçleri Yazılım adını ve sürümünü belirtir (ör. Server: Apache/0.8.4). Önem sırasına göre boşlukla ayrılır; reklam/gereksiz bilgi içermez, yalnızca sürüm tanımlayıcısı olarak kullanılır.
2.2.3.9 Kalite Değerleri Parametrelerin göreceli önemini (ağırlığını) 0 (kabul edilemez) ile 1 (en yüksek) arasında gösterir. HTTP/1.1 ondalık noktadan sonra en fazla 3 basamak kabul eder.
2.2.3.10 Dil Etiketleri Accept-Language ve Content-Language alanlarında insan dillerini tanımlar (bilgisayar dilleri hariç, RFC 1766). Boşluk içermez, büyük/küçük harf duyarsızdır: en (ISO-639 dil), en-US (ISO-3166 ülke), en-cockney, i-cherokee, x-pig-latin.
2.2.3.11 Varlık Etiketleri ETag, If-Match, If-None-Match, If-Range başlıklarında aynı kaynaktan varlıkları karşılaştırır. Güçlü varlık etiketi bayt-bayt tam eşitlik gerektirir; W/ önekli zayıf varlık etiketi ise anlam bilimde önemli değişiklik olmadan eşdeğerliği ifade eder.
2.2.3.12 Menzil Birimleri Range ve Content-Range başlıklarında yanıtın yalnızca belirli bir kısmının istenmesini sağlar. HTTP/1.1'de tanımlanan tek aralık birimi byte'tır. Örn: Range: bytes=0-500, -500 (ilk 500 ve son 500 bayt). Çakışan aralıklar reddedilebilir.

2.3. Güvenli Hipermetin Aktarım Protokolü (HTTPS)

HTTPS, HTTP ile birlikte kullanılmak üzere tasarlanmış güvenli, mesaj odaklı bir iletişim protokolüdür. HTTP'nin işlem modelini korurken istemci ve sunucuya simetrik güvenlik yetenekleri sunar ve HTTP ile geriye dönük uyumludur (ancak HTTP sunucuyla iletişimde HTTPS güvenlik özellikleri devreye girmez).

HTTPS, yalnızca simetrik anahtar işlem modlarını da destekleyebildiği için bireysel kullanıcı tarafında yerleşik bir açık anahtar sertifikası gerektirmez ve ağ üzerinden hassas verilerin (kullanıcı adı, şifre gibi form verileri) açık halde gönderilmesini önleyerek uçtan uca güvenli işlem sağlar. HTTPS şifreleme algoritmaları, modları ve parametrelerinin tam esnekliğini; seçeneklerin görüşülmesi, istemcilerin ve sunucuların işlem modları, kriptografik algoritmaları (imzalama için RSA, DSA; şifreleme için DES ve RC2 vb.) ve sertifika seçimiyle sağlar.

2.3.1. Şifreleme ve Açık Anahtar Altyapısı (PKI)

Şifreleme, açık metin veya verinin, gönderici ve istenilen alıcıdan başka kimse tarafından okunamayacak biçimde şifreli metne (cipher text) dönüştürülmesi sürecidir. Bu dönüşüm şifreleme anahtarı adı verilen gizli bir dijital kod ile yapılır ve alıcı tarafından deşifre edilir.

Web trafiğini şifrelemek için kullanılan başlıca protokoller SSL (Güvenli Yuva Katmanı), halefi TLS (Ulaşım Katmanı Güvenliği) ve HTTPS'dir. İstemci tarayıcı ve sunucu güvenli bir oturum başlatırken hangi anahtar ve güvenlik seviyesinin kullanılacağı konusunda anlaşır; oturum kurulduktan sonra tüm mesajlar şifrelenir. İki temel şifreleme yöntemi vardır:

  • Simetrik Anahtar Şifrelemesi: Gönderici ve alıcı tek bir şifreleme anahtarı yaratıp aynı anahtarı paylaşır (günümüzde tipik uzunluk 256 bit). Temel sorunu, anahtarın taraflar arasında paylaşılması zorunluluğunun anahtarı dışarıdakilere açık etme riski taşımasıdır.
  • Açık Anahtar (Asimetrik) Şifrelemesi: Matematiksel olarak ilişkili iki anahtar kullanılır: paylaşılan (açık) anahtar ve tamamen saklı (gizli) anahtar. Bir anahtarla şifrelenen veri yalnızca diğeriyle deşifre edilebilir. Gönderici mesajı alıcının açık anahtarıyla şifreler; alıcı ise kendi saklı anahtarıyla deşifre eder.

Dijital Sertifikalar ve Onay Makamı (CA): Çevrim içi işlemlerde kullanıcıların ve elektronik varlıkların kimliklerini doğrulamak için dijital sertifikalar kullanılır. Bir dijital sertifika sistemi, Onay Makamı (CA - Certification Authority) adı verilen güvenilir üçüncü taraflardan (ör. VeriSign, IdenTrust, KeyPost) yararlanır. CA, kullanıcının kimliğini çevrim dışı onayladıktan sonra sahibinin kimlik bilgilerini ve açık anahtarının kopyasını içeren şifreli bir dijital sertifika üretir. Alıcı, CA'nın açık anahtarını kullanarak sertifikayı deşifre eder, kimliği doğrular ve güvenli yanıt gönderir. Bir CA ile birlikte çalışan açık anahtar şifreleme sistemine Açık Anahtar Altyapısı (PKI) denir ve e-ticarette yaygın olarak kullanılır.

Sınav İpuçları ve Kritik Noktalar

Sınavlarda En Çok Sorulan Kavramlar:
  1. HTTP'nin 3 Temel Özelliği: Bağlantısızdır, medyadan bağımsızdır, durum denetimsizdir (stateless).
  2. HTTP/1.0 vs. HTTP/1.1: HTTP/1.0 her istek-yanıt için yeni bağlantı açar; HTTP/1.1 tek bağlantıyı birden fazla istek-yanıt için kullanabilir (RFC 2616, varsayılan port TCP 80).
  3. HTTP İstek ve Versiyon Biçimi: İstek: istek yöntemi + URI + protokol sürümü; Versiyon: <major>.<minor> (2.4 < 2.13 < 12.3).
  4. URL vs. URN: URI ikisinin birleşimidir. URN yalnızca isim alanında ad tanımlar; URL ağ konumunu ve kaynağın nasıl elde edileceğini belirtir.
  5. Şifreleme Farkı: Simetrik şifrelemede gönderici ve alıcı tek bir anahtar paylaşır (tipik 256 bit); açık anahtar şifrelemesinde matematiksel ilişkili açık + saklı iki anahtar vardır. Kimlik doğrulamasını güvenilir 3. taraf olan CA yapar (PKI).

3. Ünite: HTTP, HTTPS, HTML ve XML II

Ünitenin Amacı: Web belgelerinin sunumunu ve bağlantılanmasını sağlayan HTML işaretleme dilinin yapısını, ana komutlarını, özniteliklerini, form/tablo/bağlantı etiketlerini öğrenmek; veri değişimi ve tanımlaması için W3C tarafından geliştirilen XML standardını, sözdizimi koşullarını, bildirim yapısını ve DTD kavramını HTML ile karşılaştırmalı olarak kavramaktır.

3.1. Temel Kavramlar

Hiper Metin Biçimlendirme Dili (HTML), belgelerde metnin nasıl sunulması gerektiğini ve belgelerin birbirine nasıl bağlandığını gösteren etiketlerle işaretleme sistemidir. HTML bir programlama dili değildir ve bir HTML belgesi bilgisayar programı değil, veridir. Tarayıcılara belgeyi nasıl sunacağına ilişkin dil bilgisi ve söz dizimi talimatları verir. Web, biçimlendirilmiş metin, resim ve ses içeren birbirine bağlı canlı belgeler koleksiyonudur ve bir Web alanının ana sayfası HTML ile yazılır.

Genişletilebilir İşaretleme Dili (XML) ise World Wide Web Consortium (W3C) tarafından geliştirilen ve korunan, Web üzerinde veri değişimi için standart haline gelmiş metin tabanlı bir biçimlendirme dilidir. Verileri resmi olarak tanımlamak için DTD (Document Type Definition - Belge Türü Tanımı) kullanır.

3.2. HTML Etiketleri

HTML, dik açılı parantezler (<...>) ile sınırlandırılmış bir etiket (eleman) sistemi olarak çalışır. Etiketler tek başına (ör. <P>, <BR>) veya başlangıç-bitiş çifti (ör. <B>Dikkat!</B>) halinde bulunur. Özel semboller (varlıklar / entities) ise & işareti ve tırnak işaretleri gibi kod noktalama işaretleridir. HTML büyük/küçük harfe duyarlı değildir.

Temel bir Web sayfası <HTML>...</HTML> ile başlar ve biter. İlk olarak tarayıcı başlık çubuğunda görünen <TITLE> etiketini barındıran <HEAD>...</HEAD> bölümü, ardından sayfanın tüm içeriğini ve metin/arka plan renk özelliklerini kapsayan <BODY>...</BODY> bölümü gelir.

HTML belgeleri arasında veya aynı belgenin farklı bölümleri arasında <A> etiketiyle hiper metin bağlantıları kurulur. Bağlantı metni tarayıcıda genellikle mavi renkte görünür.

3.3. XML

XML, verileri HTML'den ayrı tutarak farklı uyumsuz bilgisayar sistemleri ve veri tabanları arasında internet üzerinden veri alışverişini kolaylaştırır. Veriler ayrı bir .xml dosyasında saklanabileceği gibi HTML belgelerinin içinde veri adaları şeklinde de depolanabilir. Böylece temel verideki değişiklikler HTML sunum kodunu değiştirmeyi gerektirmez.

Bir XML Belgesi İçin Yerine Getirilmesi Gereken 5 Koşul (Şekil 1):
  1. Tüm XML öğelerinin mutlaka bir kapanış etiketi olmalıdır.
  2. XML etiketleri büyük / küçük harf duyarlıdır (<BOOK> ve <book> iki farklı etiket olarak yorumlanır).
  3. Tüm XML öğeleri düzgün bir şekilde iç içe geçmiş olmalıdır.
  4. Tüm XML belgelerinin yalnızca bir kök etiketi (root element) olmalıdır (ağaç yapısı).
  5. Öznitelik değerleri her zaman tırnak içine yazılmalıdır.

Her XML belgesinin ilk satırı XML bildirimi olmalıdır:

<?xml version="1.0" standalone="yes" encoding="ISO-8859-1"?>
<!-- Bu bir XML yorumudur -->
  • <? ... ?>: İşleme talimatını başlatır ve sonlandırır.
  • version="1.0": Geçerli XML sürümünü belirtir.
  • standalone="yes|no": Dosyanın tek başına yeterli olup olmadığını gösterir; no değeri harici bir DTD (Belge Türü Tanımı) gibi dosyanın içe aktarılması gerektiğini bildirir.
  • encoding="ISO-8859-1": Kullanılan uluslararası karakter setini belirtir (varsayılan İngilizce karakter seti).

Kitapta XML'in yapısal gücünü göstermek için <Kutuphane> kök etiketli kitap kataloğu (her <Kitap> bloğu Excel tablosundaki bir satıra karşılık gelir) ve p(x,y) = 2x³y² - 4y⁵ polinomunun <Polinom><Terim><katsayi>... etiketleriyle kodlanması örneklenmiştir.

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Dikkat Edilmesi Gereken Temel Noktalar:
  1. HTML vs. XML Tanım Farkı: HTML belgelerde metnin nasıl sunulacağını ve belgelerin nasıl bağlandığını gösteren işaretleme sistemidir; XML ise Web üzerinde veri değişimi için standart hale gelmiş, veriyi tanımlamaya odaklı biçimlendirme dilidir.
  2. Kritik HTML Etiketleri: <TITLE> tarayıcı üst çubuğundaki sayfa başlığını taşır; <H1> birinci seviye başlık oluşturur; ALIGN içeriği merkeze/sola/sağa hizalar; <BLINK> metni yanıp söndürür; <A HREF="#Sorular"> aynı sayfadaki NAME="Sorular" kısmına gider.
  3. XML'in 5 Zorunlu Koşulu: Tek bir kök etiket (en fazla 1 adet!), kapanış etiketi zorunluluğu, büyük/küçük harf duyarlılığı, düzgün iç içe geçme, özniteliklerde tırnak zorunluluğu.
  4. XML İlk Satır Bildirimi: <?xml version="1.0" standalone="yes" encoding="ISO-8859-1"?> biçimindedir (<?html veya <?xhtml değildir!).

4. Ünite: FTP, RSS, Blog, Podcasting, Anında Mesajlaşma ve Çerezler

Ünitenin Amacı: E-ticarette ve bireysel/kurumsal Web uygulamalarında kritik rol oynayan dosya aktarım protokolünü (FTP), XML tabanlı otomatik içerik bildirim sistemi RSS'i, ters kronolojik Web günlüklerini (Blog) ve geri besleme mekanizmasını, ses yayımcılığı (Podcasting) türlerini, anında mesajlaşmanın (IM) iş dünyasındaki kullanımını ve çerezlerin (Cookies) e-ticaretteki işlevleriyle gizlilik risklerini öğrenmektir.

4.1. Temel Kavramlar

Evden veya tek başına yürütülenler de dâhil olmak üzere pek çok e-ticaret girişiminin temelinde altı önemli Web teknolojisi yer alır: FTP (dosya aktarımı), RSS (otomatik güncelleme takibi), Blog (ters kronolojik Web günlüğü), Podcasting (XML/RSS tabanlı ses ve video dağıtımı, bazı sitelerde netcasting), Anında Mesajlaşma (IM) (gerçek zamanlı iletişim) ve Çerezler (Cookies) (tarayıcıda saklanan küçük metin dosyaları).

4.2. Dosya Aktarımı (FTP)

Dosya Aktarım Protokolü (FTP), bir FTP sunucusu ile internet üzerindeki bir FTP istemci bilgisayarı arasında dosya aktarmak için kullanılan standart protokoldür. Dosya indirmek ve yüklemek için HTTP'ye alternatif bir seçimdir. 1970'lerin başında icat edilmiş, İnternet Mühendisliği Görev Gücü (IETF) tarafından 1971'de RFC 114 olarak yayımlanmış, 1985'te ise mevcut standart şartname olan RFC 959 halini almıştır. Günümüzde tüm Web tarayıcılarında gömülü olarak bulunur.

FTP Kullanım Alanları (Şekil 2):
  • İnternette yayımlanmak üzere Web sayfalarını Web sunucularına yükleme,
  • Genel yazılım sitelerindeki dosyalara göz atma ve indirme,
  • E-posta ekleri için çok büyük olan dosyaları iki taraf arasında aktarma,
  • Kurum içi görevlendirmeler gibi içerikleri bir FTP sunucusu üzerinden indirme ve yükleme,
  • Programların en son sürümlerinin yazılım geliştiriciler tarafından dağıtılması (güncellemeler, donanım sürücüleri, ürün kılavuzları, ücretli müzik ve film dosyaları).

İşletmeler FTP sayesinde büyük yazılımları fiziksel saklama ortamlarına kopyalama, ambalajlama ve kullanıcıya kargolama gibi maliyetlerden ve zaman kaybından kurtulur.

4.3. Gerçekten Basit Dağıtım (RSS)

RSS (Really Simple Syndication), XML ailesinin bir parçası olan ve kullanıcının abone olduğu Web sitelerindeki güncellemeleri otomatik olarak takip eden bir teknolojidir. XML sayesinde veri paylaşımı kolaylaştığından, RSS hizmetinden yararlanan kullanıcıya ilgili Web sayfasındaki güncellemeler XML biçiminde gönderilir (sorguyu kullanıcının bilgisayarı onun adına yapar). Denetim tüm sayfayı değil, yalnızca belirlenen veri alanlarını (ör. bir haber sitesinde yalnızca hava durumu verisini) izler.

4.3.1. Neden E-posta Bildirimi Yerine RSS?

Çok sayıda kişiye fatura veya durum değişikliği için sürekli e-posta göndermek, göndericinin kolayca spamcı olarak etiketlenmesine ve kara listeye alınmasına yol açabilir. RSS böyle bir riski tamamen ortadan kaldırır.

4.4. Web Günlüğü (Blog)

Blog ("Web log" teriminin kısaltması), girişlerin (gönderilerin) ters kronolojik sıraya göre düzenlendiği, genellikle herkese açık, bireysel veya grupça oluşturulabilen ve okuyucularla etkileşime izin veren basit bir Web sayfasıdır. Tasarım imkânı oldukça sınırlıdır ve genellikle metin yerleştirmeye dayanır.

  • Kurum İçi Kullanım: Bazı organizasyonlar çalışanların katılımını teşvik ederek yararlı fikirler elde etmek amacıyla şirket içi bloglar oluşturur; ancak aşırı gayri resmi ve denetimsiz oldukları için bazen amaçlarından sapabilmektedir.
  • Geri Besleme (Trackback): Blogun konusuna başka Web sitelerinde değinildiğinde, o sitelerin de blogda listelenmesini/gösterilmesini sağlayan mekanizmadır.
  • Marka ve Ürün İzleme: Örgütler ürün ve markaları hakkındaki yorumları yakalamak için blogları tarayan yazılımlar kullanır. Örneğin isimsiz bir blog yazarının Kryptonite bisiklet kilitlerini kalemle kırabildiğini paylaşması üzerine firma birkaç hafta içinde kilitleri geri çağırmıştır (Oz, 2006).

4.5. Ses Yayımcılığı (Podcasting)

Podcasting (bazı sitelerde netcasting), XML tabanlı bir RSS beslemesi kullanarak ses (ve artan bant genişlikleriyle video) dosyalarının internet üzerinden dağıtılmasıdır. Kısaca bir ses kaydının bir Web sitesinden temin edilerek dinlenmesi olarak tanımlanabilir. Genellikle MP3 biçimindedir ve abone olan kullanıcı yeni bölümleri otomatik olarak bilgisayarına veya taşınabilir cihazlara (iPod, MP3 çalar, cep telefonu, PDA) indirebilir. Eğitim kurumları ders kayıtlarını öğrencilere herhangi bir radyo lisans ücreti ödemeden bu yolla sunabilmektedir.

4.5.1. Podcasting Türleri (Şekil 3)

  1. Sadece Ses: Radyo gibidir; genellikle MP3 formatındadır, dosya boyutu küçüktür ve oluşturması kolaydır.
  2. Sesli ve Hareketsiz Görüntüler (Gelişmiş Podcast'ler): En yaygın eğitim kullanımı sesli anlatım içeren PowerPoint veya Keynote sunumlarıdır. Videoya göre dosya boyutları küçüktür ve bölümlendirilebilirler (izleyici istediği slayta doğrudan atlayabilir).
  3. Video: TV'ye benzer, dosya boyutları büyüktür. Hem PC hem Mac'lerde oynatılabilmesi için sıkıştırma teknolojilerine ve dosya formatına dikkat edilmelidir.

4.6. Anında Mesajlaşma (IM)

Anında Mesajlaşma (Instant Messaging - IM) e-posta ile haberleşmeye benzer; ancak en önemli farkı karşı taraftaki alıcının çevrim içi olması ve anında yanıt verebilmesidir. Her iki tarafta da yazılım bulunmasını gerektirir ve yalnızca metin değil dosya, mikrofon/kamera desteğiyle ses ve görüntü de aktarabilir; iki kişi veya grup arasında gerçekleşebilir.

İlk gayri resmi ses/video iletişim araçları maliyet, gizlilik ve uygulama zorlukları nedeniyle benimsenemezken (Whittaker, 1995), IM gayri resmi iletişimi başarıyla destekleyerek yaygınlaşmıştır (Nardi, Whittaker ve Bradner, 2000). AIM, Yahoo! Messenger, MSN Messenger, ICQ ve akıllı telefonlarda WhatsApp bunun başlıca örnekleridir. İş dünyasında IM; farklı bölgelerdeki çalışanların çevrim içi toplantı yapmasını hızlandırır, çağrı merkezi telefon maliyetlerini azaltır ve e-ticaret sitelerinde müşterilerin satın alma öncesi sorularını anında sorabilmesini sağlayarak satış personeli eksikliğini giderir.

4.7. Çerezler (Cookies)

Çerezler, bir Web sitesinden kullanıcının terminaline (tarayıcısına) gönderilen ve aynı site tekrar ziyaret edildiğinde kullanılmak üzere kullanıcı bilgisayarındaki çerez klasöründe depolanan küçük metin dosyalarıdır. Tarayıcılar varsayılan olarak çerezlere izin verir. Bir çerez kullanıcının sabit diskinden veri okuyamaz, bilgisayar virüsü geçiremez ve e-posta adreslerini yakalayamaz; her çerez kullanıcının Web tarayıcısına özgüdür.

E-Ticaret Açısından Önemi ve İşlevleri:

  • Kullanıcının aynı bilgileri (ad, adres vb.) her ziyarette defalarca girmesine gerek kalmaz (ancak bankalar gibi yüksek güvenlikli ortamlarda şifreler genellikle çerezde tutulmaz; oturum çerezleri oturum sonunda silinir).
  • Kullanıcının daha önce ziyaret ettiği sitede hep aynı reklamı görmesini engellemek için kullanılır.
  • Önceki tercihlere göre ürün önerileri sunar (ör. bir kitap satıcısının, kullanıcının daha önce incelediği kitapları açılış sayfasında göstermesi).
  • Çoklu Site Takibi ve Casus Programlar (Spyware): Çerezler yalnızca tek bir siteyle ilişkiyi değil, bir organizasyona abone birçok Web sitesindeki kullanıcı davranışlarını da saklayabilir. Bu yaklaşım, kullanıcı hareketlerini ağ üzerinden başka yerlere aktaran kötü amaçlı casus programların (spyware) öncülüğünü yapabilmektedir; güncel antivirüs yazılımları bunların önemli kısmını engeller.

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Dikkat Edilmesi Gereken Temel Noktalar:
  1. FTP vs. E-posta: E-posta ekleri FTP ile değil e-posta protokolüyle gönderilir; FTP'nin en önemli işlevlerinden biri e-posta ek sınırını aşan büyük dosyaları sunuculara aktarmaktır.
  2. RSS ve XML İlişkisi: XML ile veri paylaşımı kolaylaştığından, RSS hizmetinden yararlanan kullanıcıya ilgili sayfadaki güncellemeler XML biçiminde gönderilir.
  3. Bloglar: Gönderiler ters kronolojik sıralanır. Başka sitelerin blog konusuna değinmesini gösteren mekanizma geri besleme (trackback)'tir. Şirketler çalışanlardan yararlı fikirler elde etmek için kullanır.
  4. Podcasting: Kısaca bir ses kaydının bir Web sitesinden temin edilmesidir. 3 türü vardır: Sadece ses, ses ve hareketsiz görüntü, video.
  5. Çerezler (Cookies): Bilgiler sunucuda veya bulutta değil, kullanıcı bilgisayarında saklanır.

5. Ünite: Bir Web Sitesinin Kurulması I (Makro ve Mikro Tasarım)

Ünitenin Amacı: Bir e-ticaret girişiminin vitrini olan Web sitesinin stratejik ve kavramsal düzeydeki makro tasarımını, sık yapılan web tasarım hatalarını (otomatik ses, pop-up, kötü arama, 404 vb.) ve sayfa içi yapı taşlarını oluşturan mikro tasarım ögelerini (metin, arka plan, düğme ve görsel formatları, RGB/hex renkler, site gezintisi ve müzik etiketleri) ayrıntılarıyla öğrenmektir.

5.1. Temel Kavramlar

Web sitesi, bir kuruluşun farkındalığını artıran, çalışanlara/gönüllülere bilgi aktaran ve günümüzde adeta bir kartvizit işlevi gören en temel e-ticaret unsurudur. Öyle ki yalnızca Web sitesi üzerinden faaliyet gösteren işletmeler olduğu gibi, bireysel kullanıcılar da kendi Web sitelerini kurarak kendilerine iş imkânları yaratabilmektedir. Arama motorları sayesinde site içeriğindeki anahtar sözcükler üzerinden müşterilerle kolayca iletişim kurulabilir. Ancak önemli bir gerçek unutulmamalıdır: birkaç kod satırı ve resim ile basit bir web sitesi oluşturmak kolaydır, fakat onu kârlı hale getirmek zordur.

5.2. Web Sayfalarının Makro Tasarımı

Web tasarımı, içeriğin (genellikle hiper metin veya hipermedya — kullanıcı girdilerine cevap verebilen interaktif grafik, ses, video, metin ve hiperbağlantılar topluluğu) Web üzerinden son kullanıcıya sunulma biçimini kapsar. Genel olarak üç ana bileşeni içerir: bilgi mimarisi (navigasyon şemaları ve adlandırma kuralları), düzen/sayfaların yapısı ile ögeleri (sayfa şemaları dâhil) ve markalandırma ile kavramsal tasarım.

Her web sitesi açık bir strateji ile başlatılmalıdır. Tasarımda en sık düşülen hata, tasarımcıların kendi aşina oldukları arayüzü doğru sanarak siteyi kullanıcı bakış açısıyla deneyimlememeleridir.

5.3. Web Sayfalarının Mikro Tasarımı

Web sitesini oluşturan temel elemanların tasarımı ve üretimi mikro tasarım aşamasıdır.

5.3.1. Görsel ve İşitsel Ögeler (Şekil 4)

Tarayıcılar PNG, JPG, GIF görselleri ile FLV, SWF videoları doğrudan işleyebilir; ancak MP3 gibi dosyalar için harici oynatıcı veya eklentiler gerekebilir. Multimedya eklentileri arasında Microsoft IE'nin OLE-ActiveX teknolojisi ile platform bağımsız ve daha küçük uygulamalarda kullanılan Java Applet yer alır. Şekil 4'e göre görsel ve işitsel ögeler 6 alt başlıktan oluşur:

5.3.1.1. Metin: Birincil işlevi bilgiyi iletmek ve hedefe ulaşmaktır; karmaşık bozukluktan kaçınılmalıdır. Yazı tipi boyutunda piksel yerine yazdırma birimine dönüşüm avantajı nedeniyle punto önerilir. Sayfa gövdesi için en uygun boyut 12 punto, yoğun metinli sayfalarda 9 puntodur. İdeal satır aralığı oranı 10:12 (10 punto yazıya 12 punto satır aralığı) şeklindedir. Metin ve bağlantılarda soğuk/sıcak renk kontrastı okunabilirlik ve tasarım etkisi açısından kritiktir.

5.3.1.2. Arka Plan: İyi bir arka plan yalnızca iyi izlenim bırakmakla kalmaz, ziyaretçilerin içeriği kabul etmesini de etkiler. <body bgcolor="color"> etiketiyle İngilizce adlar veya onaltılık kodlar (#0000FF, #FFFF00, #000000) kullanılabilir. Başlıca arka plan türleri:

  • Düz renk arka plan: En basit ve ekran hızı açısından en avantajlı yöntemdir.
  • Dalgalanma arka planı: Küçük bir görselin (ör. kum taneciği) hem yatay hem dikey yönde tekrarlanmasıdır; küçük dosya boyutuyla indirme süresini azaltır.
  • Şerit arka planı: Dalgalanmaya benzer ancak yalnızca tek yönde (yatay veya dikey) tekrarlanır.
  • Fotoğraf arka planı: Sayfa arka planına doğrudan fotoğraf eklenebilir.

5.3.1.3. Resimler (Düğmeler, Simgeler): Düğmeler yüksek kontrastlı, parlak ve belirgin renklerde olmalı; ekranın sol üst kısmı, başlık veya gezinme alanı gibi kolay bulunabilecek yerlere konmalıdır. Üzerindeki metin açık, kısa olmalı ve mutlaka kayıt ol, indir, dene gibi bir fiil ile başlamalı ("ÜCRETSİZ" gibi çekici kelimeler kullanılabilir); düğme boyutu önem derecesiyle orantılı olmalıdır. Ekran çözünürlüğüne (DPI - inç başına nokta) göre simgeler uyarlanmalıdır.

Resim ve simgelerin dosya boyutu indirme hızını doğrudan etkiler. JPG (JPEG) ve GIF formatları aynı görsel kalitede diğer formatlara göre daha yüksek sıkıştırma (daha küçük dosya boyutu) sağlar; GIF az renkli görseller için uygundur. PNG formatının tercih edilmesinin temel nedeni ise saydam (şeffaf) arka plan desteklemesidir.

5.3.1.4. Renkler: Bilgisayar ekranları kırmızı, yeşil ve mavi (RGB) nokta üçlülerinden oluşur. Her kanal için 0–255 arası değer seçilerek 256 × 256 × 256 = 16 milyondan fazla renk üretilir. Tarayıcı tutarsızlıklarını önlemek için renk isimleri yerine onaltılık (hexadecimal) RGB kodları tercih edilir (00 en düşük, FF en yüksek ton): Kırmızı ff0000, Yeşil 00ff00, Mavi 0000ff, Mor 990099. CSS'te <span style="..."> veya tablo etiketlerine (table, tr, td, th) uygulanabilir; sayfa karmaşasını önlemek için az sayıda renk kullanılmalıdır.

5.3.1.5. Web Sitesi Gezintileri: İyi yapılandırılmış, basit ve sezgisel gezinme, erişilebilir ve kullanılabilir bir Web sitesi oluşturmanın en önemli unsurudur.

5.3.1.6. Müzik: Bir Web sayfasına müzik eklemenin iki temel yolu vardır:

  1. <bgsound> etiketi: En yaygın arka plan müziği yöntemidir (MP3, WAV, MID). 5 özelliği vardır: balance (sol/sağ kanal dengesi), delay (gecikme), loop (tekrar sayısı), volume (ses seviyesi) ve src (dosya yolu).
  2. <embed> etiketi: Müzik eklentileriyle web oynatıcı görünümü verebildiğinden <bgsound>'dan daha güçlüdür ve daha fazla özelliğe sahiptir. Örnek: 
    <embed src="music.mp3" autostart="true" loop="true" hidden="true"></embed>

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Dikkat Edilmesi Gereken Temel Noktalar:
  1. Makro Tasarım Unsurları: Bilgi mimarisi + düzen/sayfaların yapısı ile ögeleri + markalandırmayla kavramsal tasarım.
  2. Düğme Tasarım Kuralları: Sol üst/başlık/gezinme alanında olmalı, metni fiille başlamalı, boyutu önemiyle orantılı olmalı.
  3. Görsel Formatları: JPG ve GIF dosya boyutunu küçültüp indirme hızını artırır; PNG saydam arka plan sağlar.
  4. Yazı Tipi ve Satır Aralığı: Gövde için ideal boyut 12 punto, yoğun sayfalarda 9 punto; düzenli satır aralığı oranı 10:12.
  5. Müzik Etiketleri: Sayfaya müzik eklemenin iki temel yolu <bgsound> ve <embed> etiketleridir (<include> değildir!).

6. Ünite: Bir Web Sitesinin Kurulması II (Planlama ve Fiziksel Kurulum)

Ünitenin Amacı: Başarılı bir Web sitesinin kurulum sürecindeki planlama adımlarını, alan adı ve uzantı seçimini, Web geliştirme yazılımları ile İçerik Yönetim Sistemlerini (CMS), tema ve içerik oluşturma esaslarını kavramak; ayrıca Web sitesinin fiziksel kurulum alternatiflerini (kendi sunucusunu kurma vs. 4 farklı Web hosting modeli) ve Oz (2006) tarafından önerilen 10 ana sistem seçim unsurunu öğrenmektir.

6.1. Temel Kavramlar

Basit bir Web sitesinin nasıl oluşturulduğunu öğrenmek kolay olsa da ziyaretçilerin dikkatini çeken, sağlam kullanıcı deneyimi sunan ve işi en iyi biçimde temsil eden bir Web sitesi kurmak ciddi planlama ve fiziksel altyapı gerektirir.

6.2. Planlama

Tasarım adımlarına geçmeden önce dört temel soru yanıtlanmalıdır: (1) Web sitesinin amaçları nelerdir? (2) Web sitesinin ana konusu nedir? (3) Neden bir Web sitesi yapmak istiyorsunuz? (4) Hedef kitlenizin Web sitesine karşılık olarak ne yapmasını istiyorsunuz? Ayrıca içerik sık sık güncellenerek devam edegelen bakım sağlanmalıdır.

Aktif Bir Web Sitesi Yürütmek İçin Gereken 5 Unsur (Şekil 5): (1) Bir alan adı edinin, (2) Sitenizi barındırmak için bir Web sunucusunu güvenlikli hale getirin, (3) Web sitesi oluşturmak için güvenli bir yazılım edinin, (4) Web sitesini tasarlayın ve oluşturun, (5) Web sitesi kullanımını takip edin (Web Analytics belgesini düzenli inceleyin).

6.2.1. Alan Adı Edinme

Alan adı, internet sunucusu için "hatırlanması kolay bir takma ad" ve Web adresinin bir parçasıdır. Şekil 6'ya göre uygun bir alan adı kısa, açıklayıcı, hatırlanması kolay (kuruluş adına mümkün olduğunca benzer), tire içermeyen, sayı içermeyen, anlamlı, benzersiz ve anahtar kelimeleri kullanan nitelikte olmalıdır. Ticari markalı kelimelerin kullanılması dava riski doğuracağından kuruluşun kendi adı ideal tercihtir.

Seçilen alan adı ICANN'e kayıtlı bir kayıt şirketi (ör. Register.com, GoDaddy.com) üzerinden yıllık ödeme ile tescil edilir. Yaygın uzantılar (Şekil 7): ticari ve en yaygın siteler için .com, kâr amacı gütmeyen kuruluşlar için .org, İSS/altyapı şirketleri ve kurumsal intranetler için .net (ziyaretçilerin siteyi bulmasını kolaylaştırmak için üç uzantının da kaydedilmesi önerilir).

6.2.2. Web Sunucusunu Güvenli Kılma

Site dosyalarının erişilebilir olacağı bir ana sistem hizmet sağlayıcısında yer sağlanmalıdır: ya kendi sunucunuzu barındırır ya da çevrim içi bir Web barındırma hizmetinden alan kiralarsınız.

6.2.3. Güvenli Yazılım Edinme ve CMS'ler

Web sitesi üç yolla oluşturulabilir: (1) Notepad gibi basit metin editörleriyle doğrudan HTML kodlama (tam özelleştirme sağlar ama uzmanlık ve zaman ister), (2) Adobe Dreamweaver (PC/Mac, karmaşık siteler için güçlü ama pahalı) veya Microsoft Expression Web (daha ucuz, basit PC siteleri için uygun) gibi görsel kod üreten Web geliştirme yazılımları, (3) İçeriği veri tabanında saklayıp grafik tasarımdan ayıran İçerik Yönetim Sistemleri (CMS).

6.2.4. Web Sitesinin Tasarlanması ve Oluşturulması

  • Tema Tasarlama (6.2.4.1): Tüm sayfaları birbirine bağlayan uyumlu bir görünüm sağlar; takvim, anket, sosyal medya ve alışveriş sepeti gibi yetenekler için eklentiler (bileşenler) kullanılır. Görseller aşırıya kaçılırsa gezinmeyi yavaşlatır.
  • İçerik Ekleme (6.2.4.2): İçerik, ziyaretçilerin siteye gelme sebebidir ve Web tasarımının en önemli yanıdır. Tüm sayfaların listesini gösteren bir site haritası (ör. Ana Sayfa, Hakkımızda, Misyon ve Tarihçe, Bağışlar, Gönüllü Fırsatlar, Personel, İletişim vb.) oluşturulmalıdır.
  • Temel Web Tasarım Konuları (6.2.4.3): Kuruluşun misyonu ana sayfada kenarlık, başlık ve büyük resimlerle hemen anlaşılmalı; site diğer kurumsal materyallerle tutarlı olmalı; her sayfaya "Şimdi Bağış Yapın!" gibi eylem düğmeleri konabilmeli ve ziyaretçinin önemli bilgi için sayfayı aşağı kaydırmasına gerek kalmayacak kadar özlü, özgün ve arama motorlarınca taranabilir içerik hazırlanmalıdır.

6.3. Bir Web Sitesinin Fiziksel Olarak Kurulması

Tang ve Huang (2008), tüketici merkezli dört Web sitesi fonksiyonunun (ürün kataloğunun sunulması, ürünle ilgili yorumların sunulması, tüketici tercihlerine yönelik özelleştirme imkânı ve hesap yönetimi) daha çok kullanıcı çekerek müşteri tatminini ve dolayısıyla işletme performansını artırdığını göstermiştir. Nantel ve Glaser (2008) ise sitelerin çeviri yerine doğrudan kullanıcıların ana dilinde tasarlanmasının kültürel mesafeyi ortadan kaldırarak kullanılabilirliği artırdığını (ancak dilin önemsiz olduğu teklif değerlendirmelerinde satın alma kararına etkisi olmadığını) ortaya koymuştur.

Bir Web sitesi için ana sistem sağlama ihtiyacı iki temel yöntemle karşılanır:

  1. Ana Sistemin Organizasyon Tarafından Satın Alınıp İnternete Bağlanması: Çok maliyetlidir. Yüksek bant genişliği, donanım/yazılım bakımı için uzman istihdamı, jeneratör gibi güç kaynakları ve alan adı gerektirir. Kesintisizlik ve yük azaltma için yük dengeleme (load balancing) yapılır ve ana sistemin birden fazla kopyası olan ikizler (mirror) oluşturulur; trafik en düşük yüklü ikize yönlendirilir.
  2. Ana Sistem Hizmet Sağlayıcısından Yararlanma (Web Hosting): Maliyetleri ciddi ölçüde düşürür. Şekil 8'e göre dört gruba ayrılır:
Web Hosting Türü Özellikleri ve Maliyet Düzeyi
Paylaşımlı Ana Sistemler (Shared Hosting) Aynı fiziksel ana sistem üzerinde diğer sitelerle paylaşılır; alt alan adı gerekebilir veya yönlendirici yazılımla kendi alan adı kullanılır. Küçük işletmelerin tercihidir.
Sanal Ana Sistemler (VPS) Altyapı paylaşımlıdır ancak tek ana sistem sanal olarak birden fazla bağımsız sunucu gibi görünür; müşteri kendi sunucusuna sahipmiş hissi edinir.
Adanmış Ana Sistemler (Dedicated Hosting) Fiziksel bir sunucu tamamen tek müşteriye tahsis edilir (kimseyle paylaşılmaz); ancak sunucunun idaresi hizmet sağlayıcıdadır. Daha maliyetlidir.

  • Trafik kısıtları: Belirli veri transferi veya ziyaretçi sayısı aşıldığında ek ücretlendirme.

  • Sayfa tasarım desteği: Küçük firmaların tasarım konusunda sağlayıcıdan destek alabilmesi.
  • Güvenlik: İnternetten gelebilecek saldırılara karşı koruma ve fiziksel konumun gizli tutulması.

7. Ünite: Elektronik Ticaretin Sınıflandırılması I (B2B E-Ticaret)

Ünitenin Amacı: Elektronik ticaretin taraflarına göre oluşturulan 9'lu sınıflandırma matrisini (B2B, B2C, C2C, B2G, C2G, G2G, G2B, G2C, C2B) öğrenmek; dünya genelindeki e-ticaret hacminin büyük çoğunluğunu oluşturan İşletmeden İşletmeye (B2B) e-ticaretin ekonomik işleyişini, piyasa yapıcılarını, çevrim içi reklamcılığı ve ölçütlerini, mübadeleler ile müzayedeleri ve çevrim içi işletme birleşmelerini kavramaktır.

7.1. Temel Kavramlar

Elektronik ticaret genellikle ticarete dâhil olan üç ana tarafa göre sınıflandırılır: İşletme (Business - B), Tüketici (Consumer - C) ve Devlet (Government - G). Devlet doğrudan mal/para alışverişi yapmasa bile e-ticaret ekosisteminde diğer taraflarla etkileşime girer (Gökçen, 2005). Janssen ve ark. (2008) iş modelini kısaca "organizasyonun stratejisiyle e-ticaret sistemi arasındaki ilişkinin şekillendirilmesi" olarak tanımlamıştır.

Üç tarafın ikili kombinasyonuyla ortaya çıkan 9 sınıf elektronik ticaret (Şekil 10) şöyledir:

Kısaltma E-Ticaret Türü Kapsam ve Örnekler
B2B İşletmeden İşletmeye Yalnızca işletmelerin taraf olduğu ticaret (toptan satış, tedarik, hizmet, sermaye ekipmanı vb.). Hacimce en büyük türdür.
B2C İşletmeden Tüketiciye İşletmelerin son tüketicilere Web üzerinden perakende satış yapması (ör. Amazon, CDNow).
C2C Tüketiciden Tüketiciye Bir tüketicinin başka bir tüketiciye Web üzerinden satış yapması (ör. eBay veya ikinci el araba ilanı siteleri). Aracı işletme komisyon aldığında bazı yazarlarca B2C sınıfına da dâhil edilir (Oz, 2006).
B2G İşletmeden Devlete Devletin Web'de ilan ettiği ihalelere işletmelerin Web aracılığıyla ön başvuru yapması.
C2G Tüketiciden Devlete Vergi ödemeleri, ehliyet/pasaport başvuruları, sigorta prim ödemeleri gibi işlemlerin Web üzerinden yapılması.
G2G Devletten Devlete Bir devlet kurumunun başka bir devlet kurumuna Web'den satış yapması (ör. Devlet Malzeme Ofisi'nin diğer kamu kurumlarına yaptığı satışlar).
G2B Devletten İşletmeye Devletin elektronik ortamda yalnızca bilgilendirme yapması (ör. devletin ihale ilanını yayımlaması G2B'dir; işletmenin buna başvurması ise B2G'dir).
G2C Devletten Tüketiciye Devletin vatandaşlara sunduğu bilgilendirme ağırlıklı elektronik hizmetler (ör. taşıt vergi borcu veya T.C. kimlik numarası sorgulama).
C2B Tüketiciden İşletmeye Tüketicilerin Web aracılığıyla farklı işletmelerin ürünlerini karşılaştırması süreci.

7.2. İşletmeden İşletmeye Elektronik Ticaret (B2B)

B2B e-ticaret, son tüketicilerin yer almadığı, yalnızca işletmeler arasında gerçekleşen e-ticaret türüdür. İşlem hacmi bakımından B2C ticaretin yaklaşık on katını bulmaktadır (Oz, 2006). Sanayi Devrimi üretimi mekanikleştirirken, bilgi devrimi perakende, toptan ve girdi alımları gibi tüccar işlevlerini otomatikleştirerek işlem maliyetlerini düşürmüştür. 1999 yılında ABD'deki işletmeler arası 14 trilyon dolarlık işlemin yaklaşık 90 milyar doları internetten yapılırken (Uchitelle, 2000), günümüzde ABD'deki B2B e-ticaret hacmi 1 trilyon doların üzerine çıkmıştır (Forrester, 2019).

Kapsamı: B2B yalnızca toptan ticareti değil; şirketin hizmet alımlarını, kaynakları, teknolojiyi, üretilmiş parça ve bileşenleri, sermaye ekipmanlarını ve ayrıca reasürans (sigorta şirketlerinin risklerini yeniden sigortalatması), ticari kredi, ticari bono, menkul kıymet ve diğer finansal varlık işlemlerini de kapsar. Buna karşın perakende satış, müşteri değişimi ve istihdam gibi konuları içermez.

Aracılar, Piyasa Yapıcılar ve Merkezi Pazarlar: B2B şirketleri çoğu zaman alıcı ile satıcıyı buluşturan aracılar ve finansal piyasalara benzer borsalar kuran piyasa yapıcılar (talep-arzı toplayan, eşleştiren, fiyat mekanizması ve likidite sağlayan aktörler) olarak çalışır. B2B firmaları tedarik zincirlerini yeniden düzenleyerek merkezi olmayan ikili pazarlık yerine merkezi çevrim içi açık artırmalar ve resmi ihale mekanizmaları sunar; böylece arama ve zaman maliyetlerini azaltıp verimliliği artırır.

7.2.1. Reklamcılık

Çevrim içi B2B reklamcılık iki ana gruba ayrılır: Arama reklamcılığı ve Reklam bantları (Banner).

  • Arama Reklamcılığı: Genel veya özel amaçlı arama sitelerinde belirli anahtar kelimeler arandığında, ücret ödeyen işletmelerin sonuçlarının ilk sıralarda veya koyu/renkli gibi daha dikkat çekici biçimde sunulmasıdır (arama sitesi de bir işletme olduğu için B2B e-ticarettir).
  • Reklam Bantları (Banner): Çevrim içi dergi, gazete vb. sitelere yerleştirilen ve başka bir işletmenin afişini barındıran görüntülerdir.
Çevrim İçi Reklamcılık Ölçütleri:
  • Basım Sayısı (Impression): Tarayıcının reklam bandını içeren sayfayı her yükleyişinde artan sayaçtır (bazen tıklama sayısı anlamında da kullanılır).
  • Ay Başına Eşsiz Ziyaretçi Sayısı (Unique Visitors per Month): Bir ay içinde siteyi ziyaret eden farklı kullanıcı sayısıdır.
  • Eşsiz Ziyaretçi Sayfaları (Unique Visitor Pages): Tek bir kullanıcının aynı sitede ziyaret ettiği farklı sayfa sayısıdır (yüksekse kullanıcı farklı banner'ları görür).
  • Erişim Oranı: Bir önceki ay siteyi ziyaret edenlerin sayısının tüm Web kullanıcılarının sayısına bölünmesiyle bulunur.
Not: Ürün veya işletmelerin Web günlüklerinde (bloglarda) gündeme getirilmesi de bir anlamda ücretsiz reklam işlevi görür.

7.2.2. Mübadeleler (Exchanges) ve Müzayedeler (Auctions)

İktisatçıların tek bir alıcı/satıcının olmadığı ve bilginin hızlıca paylaşıldığı mükemmel pazar ideali, internet sayesinde gerçeğe dönüşebilmektedir.

Özellik Mübadeleler (Exchanges) Müzayedeler (Auctions)
Erişim Durumu Genellikle herkese açık değildir; sınırlı sayıda kullanıcıya izin verilir (Extranet B2B ortamı) ve giriş için genellikle üyelik aidatı ödenir. Genellikle herkese açıktır; her türlü alıcı veya satıcı girebilir (genellikle banka garantisi veya ön ödeme istenir).
İşleyiş ve Gelir Modeli Mal/hizmetler başka mal/hizmetle ya da parayla değiş tokuş edilir; alıcı ürünlere teklif verir. Bağımsız aracı site hem alıcıdan hem satıcıdan komisyon alır. Alıcı ürüne fiyat teklifi verir; belirli bir süre sonunda en yüksek fiyatı verene satış gerçekleşir.

7.2.3. Çevrim İçi İşletme Birleşmeleri

Geleneksel işletme birleşmelerinde firmalar tek bir gelir tablosu ve bilançoya sahip tek bir kimliğe dönüşürken, çevrim içi işletme birleşmeleri birbirine rakip olan birden fazla işletmenin mal ve hizmetlerini satmak ve satın almak için ortak bir Web sitesi altında yaptığı güç birliği veya ittifaktır.   1. Satın Almalarda Tek Alıcı Gücü: Benzer ihtiyaçlara sahip rakip işletmeler ortak siteden alım yaparak pazarlık ve maliyet avantajı elde eder.
  2. Satışta Tek Adres ve Hızlı Karar: Farklı satıcıların tek bir adreste toplanması tüketicinin alternatif aramak için başka yere gitmesini önler ve özellikle pahalı ürünlerde satın alma kararını hızlandırır (ör. emlak komisyoncularının başka komisyoncunun portföyündeki gayrimenkulü satıp/kiralayıp komisyonu paylaşması).

8. Ünite: Elektronik Ticaretin Sınıflandırılması II (B2C, Mobil Ticaret ve EDI)

Ünitenin Amacı: İşletmeden tüketiciye (B2C) elektronik ticaretin temel modellerini (internet perakendeciliği, müzayedeler ve ters müzayedeler, içerik sağlayıcılar, elektronik fatura ve ödeme sistemleri), kablosuz bilgi teknolojilerine dayanan mobil ticareti (m-ticaret) ve tedarik zincirinde kurumlar arası belge alışverişini standartlaştıran Elektronik Veri Değişimi (EDI) ile EDIFACT/ASC X12 mesaj standartlarını kapsamlı biçimde kavramaktır.

8.1. Temel Kavramlar

Elektronik ticaret hacminde en büyük parasal payı işletmeler arası (B2B) elektronik ticaret alsa da işlem sayısı bakımından ilk sırada işletmeden tüketiciye (B2C) elektronik ticaret yer almaktadır ve tutar olarak da B2B’nin hemen arkasından hızla büyümektedir. Örneğin ABD’de B2C e-ticaret gelirleri 2007 yılında 175 milyar dolar düzeyine ulaşmış; Mulpuru ve ark. (2008) tarafından bu tutarın 2012 yılına kadar 335 milyar dolara çıkacağı öngörülmüştür.

B2C Ticaret: Bir işletme ile nihai tüketici arasındaki mal ve hizmet alım satımına ilişkin perakende işlemlerdir. Buradaki temel “yenilik”, perakende işleminin geleneksel mağazalardaki “tuğla ve harç” (brick-and-mortar) fiziksel ortamı yerine internet üzerinden gerçekleştirilmesidir.

Yazılı Belgelerden EDI Standartlarına Tarihsel Evrim:
Ticaret yüzyıllar boyunca fatura, kredi notu ve sipariş gibi yazılı belgelerin hareketine dayanıyordu. İnsanlar bu belgeleri okuyup yorumlayabildiği için belgelerin standart bir düzende olması şart değildi. 1950’lerin başında bilgisayarlar muhasebe, bordro, üretim ve yönetim alanlarına girdi; ancak hâlâ standart olmayan formatlarda basılı belgeler üretiyorlardı. Alıcı şirketlerin bilgisayardan gelen çıktıları kendi sistemlerine yeniden girmek için personel çalıştırması gerekiyordu. Bu sorunu çözmek ve işlemleri otomatikleştirmek için özellikle B2B e-ticarette Elektronik Veri Değişimi (EDI) standartları doğmuştur.

8.2. İşletmeden Tüketiciye Elektronik Ticaret (B2C)

8.2.1. İnternet Perakendeciliği (E-Retailing / E-Tailing)

İnternet perakendeciliği (e-tailing) sayesinde tüketiciler bilgisayarları başından ayrılmadan yiyecekten beyaz eşyaya kadar pek çok sanal mağazayı gezebilir, kısa sürede geniş enformasyon toplayabilir ve farklı satıcılar arasında fiyat ile kalite karşılaştırması yapabilirler. Seçilen ürünün bedeli kredi kartı veya PayPal gibi aracı ödeme sistemleriyle ödendikten sonra ürün doğrudan tüketicinin adresine gönderilir.

İlk yıllarda kredi kartı bilgilerinin kötüye kullanılması korkusu tüketicileri uzak tutsa da zamanla oluşan güvenle birlikte internet perakendeciliğinin rağbet görmesinin başlıca nedenleri şunlardır:

  • Her an (7/24), herhangi bir mağazadan alışveriş yapabilme rahatlığı.
  • Sayısız çevrim içi mağazayı birkaç dakikada gezerek zaman kazanma.
  • Arama motorları ve karşılaştırma siteleri vasıtasıyla belirli bir ürünü kimin sattığını saniyeler içinde bulabilme imkânı.
  • Birçok satıcı arasında fiyat ve kalite karşılaştırmasını hızlıca yapabilme imkânı.
  • Ürünle ilgili diğer tüketicilerin ve bağımsız uzmanların yazdığı yorumları okuyabilme imkânı.

Satıcı Açısından Stratejiler ve Maliyet Avantajları:

  • Tüketici Takibi ve Kişiselleştirme: Satıcılar mağaza ziyaretçisini alıcıya, alıcıyı da sürekli müşteriye dönüştürmek için çerezler (cookies) yardımıyla kullanıcının hangi ürünü ne kadar incelediğini dahi kayıt altına alır. Bazı hukukçular kullanıcıdan habersiz veri toplanmasını ve verilerin başka şirketlere satılmasını hukuka aykırı bulmaktadır. Toplanan verilerle tüketicilere e-posta yoluyla kampanya, promosyon ve iskonto duyuruları gönderilir; ayrıca ziyaretçi siteye tekrar girdiğinde ilgi duyduğu ürünler açılış sayfasında öncelikli gösterilir.
  • Düşük İşletme Maliyetleri: Çevrim içi mağazanın merkezi bir konumda fiziksel mağaza kiralamasına gerek yoktur; şehir dışında bir depo yeterlidir. Hatta bazı işletmeler depo bile tutmayıp satış bilgisini doğrudan üreticiye ileterek ürünün alıcıya gönderilmesini (drop-shipping mantığı) sağlar. Satışçı ve kasiyer gideri yoktur; temel maliyetler paketleme elemanları ile paketleme-gönderim giderleridir.
  • İştirak (Affiliate) Pazarlaması: Reklam bantlarının (banner) başka Web sayfalarına yerleştirilmesidir (Web sayfası sahiplerine iştirak denir). Üç ücretlendirme kriteri vardır:
    1. Satış başına ödeme: Reklam bandından gelen ziyaretçi satın alma yaptığında ödenir (en fazla tercih edilen yöntemdir).
    2. Tıklama başına ödeme: Reklam bandına her tıklandığında ödeme yapılır.
    3. Üyelik başına ödeme: Ziyaretçi satın alma yapmasa bile perakendeci sitenin üyelik formunu doldurduğunda ödeme yapılır.
  • Rakiplere Komisyonlu Platform Sunma: Örneğin Amazon.com, kendi arama sonuçlarında rakiplerinin ürünlerini de listeleyip satış üzerinden komisyon almaktadır. Bu sayede hem tüketicilerin ilk başvurduğu adres hâline gelir hem de rakip satışlarından gelir elde eder.

8.2.2. Müzayedeler ve Ters Müzayedeler

Bireylerin sahip oldukları mal veya hizmetleri belirli bir süre boyunca teklif usulüyle sattığı Web siteleri ilk bakışta C2C e-ticaret gibi görünse de aracı Web sitesi (işletme); ürün yorumları, benzer ürün önerileri, ek enformasyon sunumu ve ödemenin doğrudan Web sitesi sahibine yapılması gibi kritik roller üstlenir. Bu yönüyle Web sitesi gerçek satıcı, ürünü sunan birey ise üretici konumundadır ve işlem aslında B2C e-ticaret niteliği taşır.

Ters Müzayede (Reverse Auction): Tüketicinin talep ettiği hizmet için ödemeyi düşündüğü ücreti özel tasarlanmış bir Web sitesinde ilan etmesi, ardından Web sitesinin ilgili hizmeti sunan işletmeleri davet etmesi yöntemidir. Teklifi ilk kabul eden satıcı ürünü/hizmeti satar; bazen hiçbir üretici fiyatı kabul etmeyebilir. Mal satışlarında nadir görülür; genellikle seyahat, konaklama ve araç kiralama gibi hizmet sektörlerinde yaygındır.

8.2.3. İçerik Sağlayıcılar

Web’de “içerik” kavramı; haberler, araştırma sonuçları ve çeşitli istatistikler gibi enformasyonlar ile müzik, resim ve video klip gibi sanatsal çalışmaları (ve bazı yazarlara göre seri ilanları) kapsar (Oz, 2006). Genel haberler çoğunlukla ücretsiz olsa da uzmanlık alanlarına yönelik nitelikli makaleler ve raporlar ücretlidir. İnternet kullanıcıları aradıkları özel bilgiye elektronik ortamda hızla erişebildikleri için bu tür içeriklere ücret ödemeye razıdır.

8.2.4. Fatura Gönderme ve Ödeme

Banka hesapları arası çevrim içi para transferinin ve e-posta ile bilgi paylaşımının kolaylaşmasıyla telefon, kablolu TV ve üyelik aidatı gibi düzenli ödemelerde elektronik fatura (e-fatura) yaygınlaşmıştır. İletişim şirketleri kâğıt/posta masraflarını düşürmek için e-faturayı kabul eden abonelere görüşme ücretlerinde indirim gibi teşvikler sunar.

Buna karşın tüketiciler fatura tutarlarının banka hesaplarından otomatik çekilmesine veya çevrim içi ödeme yapmaya aynı kolaylıkta yaklaşmazlar. Bunun en önemli nedeni internet üzerinden banka hesap bilgilerinin çalınması vakalarıdır. Şifre çalma (Phishing) adı verilen yasa dışı girişimlerde saldırganlar, bankanınkiyle birebir aynı tasarıma sahip sahte bir Web sitesine yönlendiren e-postalar gönderir (örneğin bağlantıda güvenli HTTPS görünümü verilip gerçekte güvensiz HTTP adresine yönlendirme yapılır) ve kullanıcının hesap numarası ile şifrelerini ele geçirir.

8.2.5. Mobil Ticaret (M-Ticaret)

Kablosuz bilgi teknolojileri sayesinde kullanıcıların ev veya ofis dışındayken de Web’e ve ağlara bağlanabilmesi mobil ticareti (m-ticaret) doğurmuştur. Örneğin kablosuz ağ kapsama alanındaki bir mağazaya 20–30 metre yaklaşan tüketicinin mobil cihazına anlık promosyon ve ilanlar iletilebilmektedir.

8.3. Elektronik Veri Değişimi (EDI)

Elektronik Veri Değişimi (Electronic Data Interchange — EDI), farklı kuruluşların bilgisayar uygulamaları arasında dünya çapında standart elektronik formatta veri değişimi yapmasını sağlayan yapıdır (Gökçen, 2005). Temel amacı; elektronik olarak sipariş alınması, ticari sözleşme ve faturaların hazırlanması ile gümrük, bankacılık ve benzeri işlemlerde tekrarların önlenmesi ve işlemlerin en az hatayla, en kısa zamanda tamamlanmasıdır.

EDI şu üç ana unsuru kapsar: (1) aktarılacak verinin biçimi için belirlenmiş standartlar, (2) veriyi tercüme edecek yazılım ve (3) verinin üzerinde akacağı ağ. Sipariş, ödeme ve fatura gibi belgeler standart biçimde kodlandığında alıcı tarafın yazılımı veriyi insan müdahalesine gerek kalmadan doğrudan okuyup kendi veri tabanına işleyebilir.

  • Ağ Yapısı ve Güvenlik: EDI genellikle tüm internete açık değildir; bunun yerine Extranet tercih edilir ve üzerindeki trafik ücrete tabi olarak bir uz iletişim işletmesi tarafından denetlenir. Bu yapı yüksek güvenlik ve gönderilen mesajın inkâr edilememesi anlamına gelen reddedilmeme (non-repudiation) avantajı sağlar.
  • Klasik EDI ve XML Karşılaştırması: Günümüzde ASC X12 ve EDIFACT gibi klasik EDI biçimleri sektörler arası veri değişiminde hâlâ güçlü bir yere sahipken, sektörel veri değişiminde XML tabanlı çözümler öne çıkmaktadır (Nurmilaakso, 2008). Ancak gizli verilerin açık Web sayfaları üzerinden XML ile paylaşılması güvenlik açısından sakıncalıdır.

8.3.1. Mesaj Standartları

Farklı sektörlerin kendilerine özgü jargonu ve belge düzeni olduğundan, telefonla konuşup aynı dili anlayan ancak içeriği yorumlayamayan taraflar gibi bir sorun doğar. Bunu aşmak için EDI modelinin kontrol kuruluşlarınca tanımlanan belge ve mesaj standartları katmanı oluşturulmuştur. Ortaklar veri değişimine başlamadan önce mesaj standartlarının tam anlamı ve içeriği konusunda anlaşma yapar ve büyük kuruluşlar kendi uygulama kılavuzlarını yayımlar.

Mesaj Standardı / Kuruluş Kullanım Alanı ve Kapsamı
EDIFACT Avrupa’da en yaygın kullanılan, belirli bir sektörle sınırlı olmayan genel kullanım standardıdır. EAN numaralandırma birlikleri ve Birleşmiş Milletler ile ilişkili EDIFACT kurulu tarafından yönetilir.
ASC X12 (ANSI X12) Klasik EDI veri değişiminde özellikle sektörler arası yaygın kullanılan temel standartlardan biridir.
ODETTE & VDA Otomotiv endüstrisi standartlarıdır. ODETTE 2000 yılından beri EDIFACT standartlarını benimsemiştir; VDA ise gerçek bir EDI standardı olmamakla birlikte pek çok benzerlik taşır.
CEFIC Kimya endüstrisine özel EDI standardizasyonudur.
TRADACOM Perakende endüstrisine özel EDI standardizasyonudur.
EDI Mesaj Segmenti Yapısı (EDIFACT NAD Örneği):
Her mesaj standardı bölümleri ve konumlarını gösteren bir yapı şeması ile tanımlanır. Örneğin EDIFACT’ta ad ve adresleri tanımlayan NAD segmenti şemasında üç temel durum/tekrar belirteci yer alır:
  • M (Mandatory — Zorunlu): Segmentin mesajda en az bir kez yer alması gerektiğini belirtir.
  • C (Conditional — Koşullu): Zorunlunun alternatifidir; içinde tutulacak bilgi yoksa mesajda yer alması gerekmez.
  • R (Repeatable — Yinelenen): Segmentin bir defadan fazla tekrar edebileceğini gösterir (ör. bir faturadaki birden çok kalem satırı). Alternatifi yalnızca 1 veya izin verilen maksimum tekrar sayısıdır.

9. Ünite: Veri Tabanı Yönetim Sistemleri I (Temel Kavramlar ve Modeller)

Ünitenin Amacı: Veri tabanı yönetim sistemlerinin (VTYS) temel işlevlerini, geleneksel dosyalama yaklaşımının yarattığı sorunları, varlık–özellik–anahtar (birincil, dışsal, birleşik) kavramlarını, veri tabanı yaklaşımının işletmelere sağladığı yararları ve başlıca dört veri tabanı modelini (Hiyerarşik, Ağ, İlişkisel ve Nesneye Dayalı Modeller) ayrıntılarıyla öğrenmektir.

9.1. Temel Kavramlar

Günümüz işletmelerinin yalnızca alacak, verecek ve stok verilerini değil; müşterilerin demografik bilgilerini, alışveriş alışkanlıklarını ve Web’de inceledikleri ürünleri de saklayıp hızla enformasyona dönüştürmesi gerekmektedir. Klasik dosyalama mantığında dosyalar yalnızca bir dizi byte olarak saklanır (1 Byte = 8 Bit). Bu yaklaşımın doğurduğu zorlukları aşmak için Veri Tabanı Yönetim Sistemleri (VTYS) kullanılır.

  • VTYS Tanımı: Verinin saklanması, çağrılması ve üzerinde işlemler yapılmasını sağlayan yazılımdır (Gökçen, 2005). Laudon ve Laudon (2006) ise VTYS’yi veriyi bir merkezde toplayan, etkin yöneten ve uygulama programlarının saklanan verilere erişmesine izin veren yazılım olarak tanımlar. Dördüncü nesil programlama dilleri arasında da değerlendirilebilir.
  • Ara Yüz Rolü: VTYS, veri ile uygulama programları veya doğrudan kullanıcı arasında ara yüz görevi görür.

Geleneksel Dosya Yaklaşımının Örneği ve Eksiklikleri:

Tablo 2’deki geleneksel personel dosyasında kolon başlıkları yoktur; her kayıt sabit byte pozisyonlarına göre okunur (1–2: Personel No, 3–7: Adı, 8–13: Soyadı, 14–21: Doğum Tarihi):

  • Program–Veri Bağımlılığı: Dosya biçimindeki en küçük değişiklikte program koduna müdahale edilmesi gerekir.
  • Veri Tekrarı ve Dosya Şişmesi: Aynı veriler (örn. ad, soyad) hem insan kaynakları hem satışlar dosyasında tekrar eder.
  • Hataya Elverişlilik: Pozisyon sayımındaki tek karakterlik kayma “Çağla” isminin “1Çağl” veya “ağlaC” biçiminde hatalı okunmasına yol açar.
  • Güncelleme Yavaşlığı ve Tutarsızlık: Bir personelin adındaki düzeltmenin tüm dosyalardaki tüm kayıtlarda tek tek yapılması gerekir.

9.2. Varlık (Entity), Özellik (Attribute) ve Anahtar

Veri tabanı yaklaşımında veriler fiziksel olarak yine dosyalarda tutulur; ancak dosyalara doğrudan uygulama yazılımı değil VTYS erişir. Bir veri tabanının hiyerarşik yapısı şu şekildedir: Veri Tabanı → Dosyalar → Kayıtlar (Varlıklar) → Özellikler.

  • Varlık (Entity): Dosyalar kayıtlardan meydana gelir ve her bir kayıt bir varlığı (çoğu zaman bir nesneyi) temsil eder. Örneğin öğrenciler dosyasındaki her kayıt bir öğrenciyi, satışlar dosyasındaki her kayıt bir satışı ifade eder.
  • Özellik (Attribute): Varlıkları birbirinden ayıran niteliklerdir (ör. öğrenci numarası, adı, soyadı, doğum tarihi, cinsiyet, ev adresi, telefon). Özellikler veri tabanında bölünebilen en ufak parçalar kabul edilir.
Anahtarlar (Birincil Anahtar ve Dışsal Anahtar):
  • Birincil Anahtar (Primary Key): Dosyadaki varlıkları birbirinden benzersiz biçimde ayırt eden bir veya birden fazla özelliktir (ör. Öğrenci No, Personel No). İki zorunlu şartı vardır:
    1. Dosyadaki diğer kayıtlarda aynı değeri almaması (tek/eşsiz olması) gerekir.
    2. Hiçbir zaman boş değer (null / nil) alamaz.
    Not: Boş değer (null), sıfır (0) girmek veya boşluk tuşuna basmak değildir; hiç veri saklanmaması demektir (değer var ama bilinmiyor ya da değer yok yorumuna yol açtığı için istenmez; Chen ve Huang, 2008). Doğal bir özellik birincil anahtar olamıyorsa VTYS tarafından rastlantısal eşsiz sayı üreten yapay bir alan eklenir.
  • Dışsal Anahtar (Foreign Key): Dışarıdaki bir dosyanın/tablonun birincil anahtar özelliğine bağımlı olan özelliktir. Örneğin İnsan Kaynakları dosyasında Personel No birincil anahtar iken, Satışlar dosyasında Personel No dışsal anahtardır. Bağımlı olduğu birincil anahtardaki değerler dışında değer alamaz; ancak bir personel birden fazla satış yapabileceği için dışsal anahtarda veri tekrarı olabilir.

Yarımağan (2000) ve Şekil 12 doğrultusunda veri tabanı yaklaşımının geleneksel dosya yaklaşımına kıyasla sağladığı altı temel yarar vardır:

Alt Başlık Sağladığı Avantaj ve Örnek
9.3.1. Veri Tekrarının Azalması Her alt sistem için verilerin kopyalanması önlenir; bellek tasarrufu ve tutarlılık sağlanır (ör. bir dosyada “Çağla”, diğerinde “Çagla” yazılmasının doğuracağı farklı kişi algısı önlenir).

9.3.4. Kullanımının Yaygınlaşması Eskiden yalnızca uzmanların erişebildiği verilere günümüzde her düzeyden kullanıcı çeşitli uygulama yazılımlarıyla erişebilmektedir.
9.3.5. Verilerin Gizliliğinin ve Güvenliğinin Sağlanması Kullanıcı hesapları, şifreler ve erişim yetkileri belirlenir. Bir tablonun bazı alanları gizlenebilir, bazı kullanıcılara yalnızca okuma yetkisi verilip değiştirme yasaklanabilir.
9.3.6. Standartların Uygulanabilmesi Veri Tabanı Yöneticisi (DBA) veya ekibin merkezi denetimi ve VTYS yapısı sayesinde veri yapısı, gösterimi ve adlandırmada kurum içi, kurumlar arası, ulusal veya uluslararası standartlar uygulanabilir.

9.4. Veri Tabanı Modelleri

Veri tabanı modelleri, varlıklar ve kayıtlar arasında bağlantılar kurarak aynı verinin farklı alt sistemlerde tekrarlanmasını önleyen yapısal yöntemlerdir.

9.4.1. Hiyerarşik (Ağaç) Model

Verilerin bir organizasyon şeması gibi yukarıdan aşağıya doğru ağaç yapısında organize edildiği modeldir (Gökçen, 2005). Ağacın en üstünde en fazla tekrarlanması beklenen veri tek olarak yer alır (birden fazla ağaç bulunabilir).

  • İlişki Türü: Yalnızca bire çok (1:N) ilişkilere izin verir; her çocuğun (child) tek bir ebeveyni (parent) vardır, bir ebeveynin ise birden fazla çocuğu olabilir.
  • Arama Mekanizması: Kayıtlar adres/işaretçilerle (pointers) bağlanır; her kayıt ilk çocuğunun ve aynı seviyedeki sonraki kaydın adresini tutar. Bu nedenle arama işlemleri oldukça hızlıdır.
  • Dezavantajları ve Örnekler: Esnek değildir (tasarım sonradan kolayca değiştirilemez) ve çoğa çok (N:N) ilişkilere izin vermediğinden gereksiz veri tekrarlarına yol açabilir. IBM IMS, FOCUS, RAMIS II bu modeli kullanan VTYS’lerdir.

9.4.2. Ağ Model (CODASYL)

Hiyerarşik modelle aynı dönemlerde ortaya çıkmış, ilk kez 1971 yılındaki Veri Sistemleri Dilleri Konferansı’nda (CODASYL) tanımlandığı için CODALYS veri tabanları olarak da anılan modeldir. Hiyerarşik modelin aksine çoğa çok (N:N) ilişkiyi destekler; yani bir kaydın birden fazla çocuğu olabildiği gibi birden fazla ebeveyni de olabilir. Örneğin ikinci bir satışçının sattığı aynı ürün için ürün kaydının tekrar oluşturulmasına gerek kalmaz; ürün kaydının iki ebeveyni olur. Adresleme yöntemleri farklılaşsa da her kayıt kendisine bağlı ilk ürünün ve aynı kişiye bağlı sonraki ürünün adresini tutarak gezinti yapabilir.

9.4.3. İlişkisel Model

İlk kez Edgar Frank “Ted” Codd tarafından 1970 yılında ortaya atılan (Codd 1981’de Turing Ödülü almıştır), günümüz VTYS’lerinin büyük çoğunluğunun temelini oluşturan modeldir. Kavramsal olarak tablolardan (ilişkilerden) oluşur ve teorik temeli ilişkisel cebire (relational algebra) dayanır.

  • Terminoloji: Kayıt → Tuple (satır), Kolon → Özellik / Alan (Field), Tablo → İlişki (Relation). Her tablo ve kolon benzersiz bir isme sahiptir.
  • Bağlantı Esnekliği: Hem 1:N hem de N:N bağlantıları destekler. Bağlantılar genellikle birincil ve dışsal anahtarlarla kurulur; ancak ortak en az bir kolonu bulunan tablolar anahtar şartı olmaksızın da bir araya getirilebilir (Laudon ve Laudon, 2006).
  • Birleşme Tablo (Join Table) ve Görüntü (View): Sorgu veya rapor anında birden fazla tablodan geçici olarak oluşturulan tablolara birleşme tablo denir; veri tabanında kalıcı tutulmazlar ve özel teknikler dışında veri girişine kapalıdırlar. VTYS tarafından sanal olarak gösterilen ve arka planda ilgili tablolara veri kaydı yapılabilen sanal tablolara ise görüntü (view) denir (Çubukçu, 1999); veri girişi yapılacak bir görüntüde ilgili tabloların birincil anahtarlarının yer alması gerekir.
  • Birleşik Anahtar (Composite Key): Tek bir alanın benzersiz olmadığı durumlarda birden fazla alanın birlikte birincil anahtar olarak tanımlanmasıdır (ör. merkezi üniversite veri tabanında Üniversite Adı + Fakülte Adı).

9.4.4. Nesneye Dayalı Model (NDV)

1980’lerin sonlarına doğru ortaya çıkan (Martin, 1993) ve nesneye dayalı programlamayı temel alan modeldir. Görüntü, resim, ses gibi çoklu ortam verilerinin satır-kolon biçiminde saklanması ve işlenmesi güç olduğundan, hem veriyi hem de veri üzerindeki işlemleri aynı nesne içinde barındırır; buna sarma (encapsulation) denir (Oz, 2006).

  • Sorgulama ve Adresleme: Çoklu ortam verileri (ör. konuşma diliyle “içinde araba olan görüntüleri listele” sorgusu — Erozel ve ark., 2008) sorgulanabilir. Nesneler arası bağlantılar dışsal anahtar olmadan, bir nesnenin diğer nesnenin adresini kapsamasıyla (iç içe görünüm) sağlanır.
  • Dezavantaj ve Melez Yapılar: NDV’de veriler kendi işlemleriyle birlikte istemciye iletildiği için veri tabanındaki bir değişiklik uygulama yazılımında da değişiklik gerektirir. Bu nedenle günümüzde melez (ilişkisel nesneye dayalı) VTYS’ler görülmektedir.

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Sık Sorulan Noktalar:
  1. Klasik dosyalama mantığı nedir? -> Verilerin dosyalarda bir dizi byte olarak saklanmasıdır.
  2. VTYS’nin özet görevi nedir? -> Veri ile uygulama programları veya doğrudan kullanıcı arasında ara yüz görevi yapmaktır.
  3. Varlık ve Özellik farkı: -> Dosyadaki her bir kayıt bir varlığı temsil eder; varlıkları birbirinden ayıran niteliklere ise özellik denir.

10. Ünite: Veri Tabanı Yönetim Sistemleri II (Normalizasyon, ERD ve Dağıtık VT)

Ünitenin Amacı: Veri tabanı tasarımının kavramsal ve fiziksel boyutlarını, gereksiz veri tekrarını önleyen normalizasyon kurallarını (1NF, 2NF, 3NF ve BCNF), Varlık-İlişki Diyagramlarını (ERD), dağıtık veri tabanı türlerini (bölümlendirilmiş ve çoğaltılmış), veri kalitesi sağlama yöntemlerini ve VTYS’nin üç ana bileşenini kavramaktır.

10.1. Temel Kavramlar

Bir veri tabanı tasarımı iki açıdan ele alınır (Laudon ve Laudon, 2006):

  • Fiziksel Tasarım: Verinin fiziksel olarak dosyalarda ve depolama aygıtlarında nasıl saklanacağını kapsar ve kullanılan VTYS tarafından doğrudan sağlanır.
  • Kavramsal (Mantıksal) Tasarım: İşletmenin ihtiyaçlarına bağlı olarak oluşturulan soyut modeldir; işletmede gereksinim duyulan enformasyonun ayrıntılı biçimde ortaya konulmasını gerektirir.

10.2. Veri Tabanının Tasarlanması (Normalizasyon)

Kavramsal tasarım veri ögelerinin (özelliklerin) tablolara nasıl gruplanacağını da belirler. Tüm özelliklerin tek bir tabloda toplanması büyük veri tekrarlarına yol açar. Bir ilişkinin bölünerek birden fazla ilişki oluşturulması yoluyla gereksiz veri tekrarını en aza indirme ve birbiriyle bağıntılı veri ögelerini bir araya getirme gayreti normalizasyon olarak adlandırılır (Yarımağan, 2000). Dört normal biçim ele alınmaktadır:

10.2.1. Birinci Normal Biçim (1NF)

İlişkisel modelde olması gereken en temel biçimdir; buna uymayan yapı tamamen hatalı tasarımdır. 1NF şartları:

  • Bir ilişkideki her özellik yalnızca tek (atomik) değer almalıdır (matris, vektör veya başka bir alt ilişki içeremez).
  • Aynı özellikler bir ilişki içinde tekrarlanmamalıdır.

Örnek (Çizim 9): Bölümler ilişkisinde Personel özelliği kendi içinde No, Adı, Soyadı, BNo içeren bir matris/alt ilişki olduğunda 1NF bozulur; bu alt ilişki açılarak tekrarlayan BNo tekilleştirilip BölümPers ilişkisine dönüştürüldüğünde 1NF sağlanır.

10.2.2. İkinci Normal Biçim (2NF)

2NF şartları: İlişki öncelikle 1NF olmalıdır ve birincil anahtar olmayan tüm özellikler, fonksiyonel olarak birincil anahtarın tümüne (birden fazla alandan oluşan birleşik anahtar varsa tamamına) bağlantılı olmalıdır.

Örnek (Tablo 4): BölümPers ilişkisinde birincil anahtar (BNo, No) ise Adı ve Soyadı bu bileşik anahtarın tümüne bağlıdır (farklı bölümlerde aynı personel no olabilir). Ancak bölümün Açıklaması yalnızca BNo’ya bağlıdır. Bu nedenle Açıklaması alanı ayrılarak BölümPers(BNo, No, Adı, Soyadı) ve Bölümler(BNo, Açıklaması) şeklinde iki 2NF ilişki oluşturulur.

10.2.3. Üçüncü Normal Biçim (3NF)

3NF şartları: İlişki öncelikle 2NF olmalıdır ve birincil anahtar dışında kalan tüm özellikler yalnızca birincil anahtarla bağlantılı olmalı, birbirleri arasında bağlantıları olmamalıdır (geçişli bağımlılık bulunmamalıdır).

Örnek (Çizim 10): İnsan Kaynakları tablosunda No birincil anahtar iken Şehir, İlçe ve Posta kodu birbirine bağlıdır (posta kodu şehir ve ilçeyi belirler). Şehir ve İlçe çıkarılıp Adresler(Posta kodu, Şehir, İlçe) ayrı bir tablo yapıldığında ve ana tabloda yalnızca Posta kodu bırakıldığında 3NF sağlanır.

10.2.4. Boyce Codd Normal Biçimi (BCNF)

Belirleyici (Determinant): Bir varlığı temsil etme (belirleme) yeteneğine sahip olan özelliktir. Her belirleyici her zaman birincil anahtar olarak seçilmeyebilir. BCNF şartı: Bir ilişkideki tüm belirleyiciler aynı zamanda birincil (aday) anahtar ise o ilişki BCNF’dedir. Genellikle 3NF ilişkiler aynı zamanda BCNF’dir; fark yalnızca birden fazla özelliğin birincil anahtar olabildiği durumlarda ortaya çıkar.

Normal Biçim Temel Koşul Örnek Dönüşüm (Tablo 5 → Tablo 6)
1NF Her özellik tek değer alır; aynı özellikler tekrarlamaz. İç içe matris/alt tablo düzleştirilir (Bölümler → BölümPers).
2NF 1NF + Anahtar dışı tüm özellikler birincil anahtarın tümüne bağlıdır. Bölüm açıklaması ayrılarak BölümPers ve Bölümler kurulur.
3NF 2NF + Anahtar dışı özellikler yalnızca birincil anahtara bağlıdır, birbirine bağlı değildir. Şehir/İlçe/Posta kodu ayrılarak Adresler tablosu oluşturulur.
BCNF İlişkideki tüm belirleyiciler aynı zamanda birincil (aday) anahtardır. EğitimProg(ÇalışanNo, Eğitim, Eğitmen) içinde Eğitmen de belirleyici olduğundan PersEğitmen(No, Eğitmen) ve EğitmenEğitim(Eğitmen, Eğitim) olarak ikiye bölünür.

10.3. Varlık-İlişki Diyagramları (ERD)

Veri tabanı tasarımcılarının veri modellerini kâğıt üzerine aktarıp belgelemek ve sonraki değişikliklerde referans almak için kullandıkları şemalardır (Çizim 11).

  • Varlık Gösterimi: Her varlık bir kutu ile temsil edilir; kutu içinde varlığın adı (örnek diyagramda altı çizili) ve özellikleri yer alır.
  • İlişki Bağlantıları (Kardinalite): Kutular arasındaki çizgilerin uçlarında daire (1 / bir) ve ok (N / çok) sembolleri kullanılır:
    • İki ucu daire: Bire bir (1:1) ilişki.
    • Bir ucu daire, diğer ucu ok: Bire çok (1:N) ilişki (ör. Bölüm — Personel).
    • İki ucu ok: Çoğa çok (N:N) ilişki.
  • Bazı ERD’lerde varlıklar doğrudan tablo olarak gösterilip birincil anahtarlar işaretlenir (Laudon ve Laudon, 2006); ayrıca ilişkisel olmayan modellere uyarlama çalışmaları da yapılmıştır (Yeh ve ark., 2008).

10.4. Veritabanlarının Dağıtılması

Farklı ülke veya kıtalarda faaliyet gösteren organizasyonlar veriye hızlı ve güvenli erişim için tek merkezi sunucu yerine birden fazla sunucu üzerinde hizmet veren dağıtık (distributed) veri tabanı yapısını kullanır (Çizim 12). Dağıtık yapıda da merkezi bir veri tabanı bulunur ve uzak veri tabanlarındaki güncellemeler buraya yansıtılır. Uz iletişim hatları yüksek kaliteli olmalıdır; ancak dağıtık veri tabanları yalnızca dev sistemlerle sınırlı değildir, Artail ve ark. (2009) cep bilgisayarları arasında Bluetooth üzerinden dağıtık veri tabanı kurabilmiştir. İki türü vardır:

Dağıtık Veri Tabanı Türü Çalışma Mantığı
Bölümlendirilmiş (Partitioned) Veri Tabanı Her uzak sunucu yalnızca kendi yerel ağında ihtiyaç duyulan verileri saklar; diğer veriler onda bulunmaz. Genellikle akşam saatlerinde uzak sistemlerin tamamı kopyalanmadan, yalnızca güncellemeler merkezi veri tabanına aktarılır.
Çoğaltılmış (Duplicate) Veri Tabanı Uzak veri tabanları birbiriyle haberleşerek güncellemeleri birbirlerine doğrudan aktarır. Bir uzak veri tabanında yapılan değişikliğin diğer uzak veri tabanlarına çok hızlı yansıtılması gerektiğinde tercih edilir; çalışma saatleri dışında tüm güncellemeler merkeze yansıtılır.

10.5. Veri Kalitesinin Sağlanması

Veri tabanı tasarımı kusursuz olsa bile saklanan veriler hatalı veya eksikse üretilen enformasyon da hatalı olur. Özellikle Web üzerinden tüketicilerin doğrudan veri girmesi hata ihtimalini artırmıştır. Verilerdeki hataların tespiti ve düzeltilmesi (veri kalitesinin sağlanması) için iki yöntem kullanılır:

  1. Veri Kalitesi Denetimi (Data Quality Audit): İstatistiksel tekniklerle seçilen örnek veriler işe yönelik kurallarla denetlenir (ör. “hesap tipi borç, süresi 30 günden fazla ve bakiyesi sıfırdan büyükse faiz ücreti sıfırdan büyük olmalıdır”).
  2. Veri Arıtma (Data Cleansing / Data Scrubbing): Hatalı verilerin yalnızca tespit edilmesini değil düzeltilmesini hedefler. Eksik/fazla veriler, kelime hataları, birden fazla kopya kayıtlar ve belirli süre güncellenmeyen veriler özel yazılımlarla temizlenir.

10.6. Veri Tabanı Yönetim Sistemlerinin Bileşenleri

Şekil 13’e göre bir VTYS üç ana bileşenden meydana gelir:

  • Veri Tanımlama Dili (DDL): Veri tabanının adı, tabloların adı, kolonlar, veri tipleri (sayısal/karakter) ve anahtarlar gibi yapısal tanımları yapmak için kullanılır.
  • Veri İşleme / İdare Dili (DML): VTYS’nin en sık kullandığı dildir; yeni veri girişi, mevcut verilerin güncellenmesi, silinmesi ve sorgulama işlemlerini gerçekleştirir. Günümüzde hem tanımlama hem işleme için en yaygın kullanılan dil, İngilizce konuşma diline benzeyen dördüncü nesil çok yüksek seviyeli SQL (Structured Query Language) dilidir. Büyük veri tabanlarında sorgu hızını artırmak için gelir düzeyini düşük–orta–yüksek biçiminde gruplayan özet veriler ve eşik değerlerini yumuşatan bulanık mantık (fuzzy logic) yaklaşımları da önerilmiştir (Ughetto ve ark., 2008).
  • Veri Sözlüğü (Data Dictionary): Veri tanımlama diliyle yapılmış tanımların yanı sıra verilerle ilişkili tablolar, kullanıcılar ve programlar hakkında ayrıntılı bilgilerin saklandığı dosyadır. Örneğin Adı alanının uzunluğu 5 karakterden 10 karaktere çıkarıldığında veri sözlüğü sayesinde bu değişikliği kullanan tüm uygulama programlarına da düzenleme yansıtılabilir (Gökçen, 2005).

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Sık Sorulan Noktalar:
  1. Normalizasyon nedir ve kaç normal biçim vardır? -> Gereksiz veri tekrarını en aza indirme ve bağıntılı veri ögelerini bir araya getirme gayretidir; kitapta 4 normal biçim (1NF, 2NF, 3NF, BCNF) tanımlanır.
  2. 1NF – 2NF – 3NF – BCNF ayrımı: -> 1NF: Tek değer + tekrarsız özellik; 2NF: 1NF + anahtar dışı özelliklerin birincil anahtarın tümüne bağlı olması; 3NF: 2NF + anahtar dışı özelliklerin birbirine bağlı olmaması; BCNF: Tüm belirleyicilerin aynı zamanda birincil anahtar olması.
  3. ERD sembolleri: -> Her varlık varlık adı ve özelliklerini içeren bir kutu ile temsil edilir; daire = 1, ok = N.
  4. Dağıtık VT türleri: -> Bölümlendirilmiş (Partitioned) ve Çoğaltılmış (Duplicate) olmak üzere iki türdür.
  5. Veri kalitesi yöntemleri: -> Veri kalitesi denetimi ve veri arıtma olmak üzere iki yöntem vardır.
  6. VTYS ana bileşenleri: -> Veri tanımlama dili, veri idare (işleme) dili ve veri sözlüğü olmak üzere üç bileşendir.

11. Ünite: Veri Tabanı Yönetim Sistemleri III (İlişkisel Cebir ve Veri Madenciliği)

Ünitenin Amacı: İlişkisel veri tabanı modelinin matematiksel temelini oluşturan ilişkisel cebir işlemlerini (Seçme, İz Düşüm, Kartezyen Çarpım ve Birleştirme), Web üzerinden veri tabanlarına güvenli erişim mimarisini (CGI, Servlet, ASP, PHP), çok boyutlu veri analizini (OLAP) ve veri ambarları ile veri madenciliği süreçlerini kavramaktır.

11.1. Temel Kavramlar

İlişkisel bir VTYS’den yararlanabilmek için VTYS’nin veri işleme diliyle yapılabilen işlemlerin temelini oluşturan ilişkisel işlemler gerçekleştirilir. İlişkisel işlemler gerçek tablo veya tabloların alt kümelerinden oluşan geçici tablolar üretir; kullanıcı bu geçici tablolarla koşullu raporlar veya yalnızca belirli özellikleri içeren listeler oluşturabilir (Oz, 2006).

Günümüzde e-ticaret ve çevrim içi bankacılık gibi Web uygulamalarının tamamı arka planda veri tabanlarına dayanır; kullanıcı bir ürünü satın almadan önce stok, fiyat, teknik özellik, ağırlık ve renk verilerini ya da bankacılık işlemlerinde kendi hesap bilgilerini veri tabanından çeker.

11.2. İlişkisel İşlemler ve İlişkisel Cebir

İlişkisel işlemler, ilişkisel modelin teorik temeli olan ilişkisel cebir işlemlerinin kısaltmasıdır. Matematiksel temsilde bir ilişki bir kümeye, her bir kayıt (satır) ise bir alt kümeye karşılık gelir. Kitaptaki örnek ilişkiler küme notasyonuyla şöyle ifade edilir (Connoly, 1999; Yarımağan, 2000):

PersEgitmen = {
  {No: 15, Egitmen: Ayhan Sel},
  {No: 11, Egitmen: Veli Nar},
  {No: 15, Egitmen: Nazan Zengin},
  {No: 11, Egitmen: Ayhan Sel},
  {No: 17, Egitmen: Cengiz Seymen}
}

EgitmenEgitim = {
  {Egitmen: Ayhan Sel, Egitim: NLP},
  {Egitmen: Veli Nar, Egitim: Risk Yönetimi},
  {Egitmen: Nazan Zengin, Egitim: Risk Yönetimi},
  {Egitmen: Cengiz Seymen, Egitim: NLP}
}

11.2.1. Seçme (Selection) İşlemi (σ)

Bir kümedeki alt-kümelerden (satırlardan) belirli bir koşulu sağlayanların seçilerek yeni bir küme oluşturulması işlemidir.

σkoşul(ilişki adı)
R = σegitmen = Ayhan Sel(PersEgitmen) ⇒ R = { {15, Ayhan Sel}, {11, Ayhan Sel} }

11.2.2. İz Düşüm (Projection) İşlemi (π)

Bir kümedeki alt-kümelerin tamamının yalnızca belirli elemanlarının (özelliklerinin / kolonlarının) seçilerek yeni bir küme oluşturulmasını sağlar. Birden fazla özellik virgülle ayrılır.

πözellik listesi(ilişki adı)
R = πegitmen(PersEgitmen) ⇒ R = { Ayhan Sel, Veli Nar, Nazan Zengin, Ayhan Sel, Cengiz Seymen }

11.2.3. Kartezyen Çarpım (Cartesian Product) İşlemi (×)

Birden fazla küme üzerinde uygulanan küme çarpımı işlemidir. Çarpıma giren her kümenin her alt-kümesi diğer kümenin her alt-kümesiyle birleştirilerek yeni kümenin alt-kümeleri oluşturulur; böylece birden fazla ilişkiden tek bir ilişki türetilir.

R = R1 × R2 × ... × Rn   |   R* = PersEgitmen × EgitimEgitmen

Kartezyen çarpım sonucu PersEgitmen’deki 5 kayıt ile EgitimEgitmen’deki 4 kaydın her biri eşleşerek 20 ikili oluşturur. Aynı isimli özelliklerin karışmaması için İlişki.Özellik notasyonu (nokta . “-in” anlamında) kullanılır; ardından seçme ve iz düşüm birlikte uygulanarak yalnızca eğitmen adlarının eşleştiği anlamlı kayıtlar süzülür:

R = πno, PersEgitmen.Egitmen, Egitim( σPersEgitmen.Egitmen = EgitimEgitim.Egitmen(R*) )

11.2.4. Birleştirme (Join) İşlemi (⋈)

Kartezyen çarpımla elde edilen tüm olası eşleşmeler çoğu zaman anlamsızdır; çünkü ilgisiz kayıtlar da yan yana gelir. Bunu önlemek amacıyla ortak özelliklerin belirtilen koşulu sağladığı kayıtların doğrudan birleştirilmesini kısa bir notasyonla ifade eden işlemdir. Burada θ işleci =, <, >, ≤ veya ≥ operatörlerinden birini (çoğunlukla =) temsil eder:

R1 ⋈R1.özellik θ R2.özellik R2 = σR1.özellik θ R2.özellik(R1 × R2)

11.3. Web Üzerindeki Veri Tabanları

Veri tabanlarının Web erişimine açılması büyük kolaylıklar sağlasa da dışarıdan veri çalınması veya mevcut verilerin bozulması gibi ciddi güvenlik riskleri taşır. Bu nedenle Web kullanıcılarının doğrudan veri tabanı sunucusuna bağlanmasına izin verilmez.

Ara Yüz Programları Aracılığıyla Erişim (Çizim 13):
Web sunucu üzerinde çalışan Ortak Geçit Ara Yüzü (CGI), Java Servlet, Aktif Sunucu Sayfaları (ASP) ve PHP (Hypertext Preprocessor) gibi ara yüz programları kullanılır (Oz, 2006). İşleyiş şu adımlarla gerçekleşir:
  1. Web sunucu kullanıcı bilgisayarına boş bir form gönderir.
  2. Kullanıcı formu doldurup Web sunucuya geri iletir.
  3. Web sunucu üzerindeki ara yüz programı (CGI, ASP vb.) veri tabanı sunucusuyla iletişim kurup gerekli sorgu/işlemleri yapar.
  4. Elde edilen sonuçlar Web sunucuda Web sayfası biçiminde hazırlanarak kullanıcıya gönderilir; böylece kullanıcı asla doğrudan veri tabanıyla bağlantı kurmaz.

11.4. Çok Boyutlu Veri Analizi (OLAP)

Yöneticiler bazen klasik satır-kolon tablolarının ötesinde, verileri aynı anda birçok açıdan karşılaştıran analizlere ihtiyaç duyar (ör. Yıllar × Ürünler × Satışçılar). Çizim 14’te gösterildiği gibi verilerin bir küp yapısında modellendiği ve küpün 90° veya 180° döndürülmesiyle farklı boyutlardan (yıllara göre ürün satışları, yıllara göre satışçı performansı gibi) enformasyon elde edildiği yaklaşıma çok boyutlu veri analizi veya çevrim içi analitik işleme (OLAP — Online Analytical Processing) denir (Laudon ve Laudon, 2006).

OLAP sistemlerinin amacı veriyi işlemek (güncellemek) değil, karar destek sistemleri ve raporlama için analiz etmektir. Klasik VTYS’ler veriyi küp biçiminde saklamadığından özel OLAP araçları veya çok boyutlu VTYS’ler kullanılır.

11.5. Veri Madenciliği

Günlük operasyonel veri tabanları güncel verileri tutar; eskiyen kayıtlar yavaş/ucuz ortamlara yedeklenir veya silinir. Oysa sağlıklı karar alma analizleri çok geriye dönük veriler gerektirir.

  • Veri Ambarı (Data Warehouse): Analiz amaçlı kullanılacak verilerin (iç ve dış kaynaklardan toplanarak) aynen ya da özetlenmiş olarak saklandığı büyük veri tabanlarıdır.
  • Veri Marketi (Data Mart): Bir veri ambarının alt-kümesidir; belirli bir kullanıcı grubu için yalnızca ilgili konuya odaklanılmış özet verileri (ör. sadece satış verilerini) barındırır (Oz, 2006).
Veri Ambarı Oluşturma Aşaması (Çizim 15) Açıklama
1. Veri Çekme (Extract) İşletmenin iç veri tabanlarından veya dış kaynaklardan gerekli veriler alınıp veri ambarına aktarılmak üzere dosyalanır.
2. Veri Dönüştürme (Transform) Çekilen veriler arıtılır (data cleansing) ve standartlaştırılır; kelime hataları elenir. Örn. “TC”, “T.C.” ve “Türkiye Cumhuriyeti” ifadelerinin hepsi tek bir standarda dönüştürülür.
3. Veri Yükleme (Load) Dönüştürülmüş veriler veri ambarına aktarılır ve hata olup olmadığını denetlemek için kaynak veri tabanındakilerle karşılaştırılır.

Veri Madenciliği (Data Mining): Veri ambarları üzerinde sunulan sorgulama/raporlama, OLAP ve veri madenciliği araçlarıyla büyük veri havuzundaki saklı örüntüleri ve ilişkileri ortaya çıkarma ve geleceğe yönelik tahminler yapabilmek için kurallar üretme sürecidir (Fayyad ve ark., 2002; Hirji, 2001). Örneğin aynı alışverişte birlikte satın alınan ürünlerin analiziyle pazarlama stratejileri belirlenebilir veya müşteri özelliklerine göre hedef kitle tahmini yapılabilir.

12. Ünite: JSF ve Web Uygulamaları (JavaServer Faces Mimarisi)

Ünitenin Amacı: Java tabanlı web uygulamalarında sunucu tarafı kullanıcı arayüzü bileşenlerini yönetmeyi kolaylaştıran JavaServer Faces (JSF) iskeletinin temel özelliklerini, geliştirme ortamı kurulum adımlarını (JDK, Eclipse IDE, Maven, Apache Tomcat), MVC tabanlı JSF mimarisini ve altı aşamalı JSF uygulama yaşam döngüsünü öğrenmektir.

12.1. Temel Kavramlar

JavaServer Faces (JSF), web tabanlı kullanıcı arayüzlerinin geliştirme ve entegrasyon sürecini basitleştirmeyi amaçlayan, Java tabanlı bir web uygulama iskeletidir (framework). Java Topluluğu Süreci (Java Community Process — JCP) ile bir spesifikasyon olarak resmileştirilmiş standart bir ekran teknolojisidir.

12.2. JSF Nedir?

JSF, bir sayfada yeniden kullanılabilir Kullanıcı Arabirimi (UI) bileşenlerini kullanan sunucu tabanlı uygulamalar için arayüz yapımını kolaylaştıran bir MVC (Model–Görüntü–Kontrolör) web iskeletidir. UI bileşenlerini veri kaynaklarına ve sunucu tarafı olay işleyicilerine bağlama olanağı tanır; bir dizi standart UI bileşeni ve yeni bileşenler geliştirmek için bir Uygulama Programlama Arayüzü (API) sunar.

JSF’in Web Uygulaması Geliştirmeyi Kolaylaştırdığı Beş Temel Alan:

  • Yeniden kullanılabilir UI bileşenleri sağlama,
  • UI bileşenleri arasında kolay veri aktarımı yapma,
  • Birden çok sunucu isteğinde UI durumunu (state) yönetme,
  • Özel bileşenlerin uygulanmasını sağlama,
  • Sunucu tarafı uygulama koduna istemci tarafı olaylarını (events) gönderme.

Ayrıca JSF; HTML tarayıcısı, kablosuz cihaz veya WAP cihazı gibi farklı istemci türlerine göre kendini uyarlayabilen bileşen koleksiyonları oluşturmaya imkân tanır. Şekil 14’e göre JSF şu üç ana imkânı sağlar:

  1. Çekirdek kütüphane: Temel kullanıcı arabirimi bileşenleri kümesi ve standart HTML giriş ögeleri.
  2. Genişletilebilirlik: Ek UI bileşen kitaplıkları oluşturmak veya mevcut bileşenleri zenginleştirmek için temel bileşenlerin genişletilmesi.
  3. Çoklu oluşturma (multi-rendering) yetenekleri: İstemci türlerine bağlı olarak JSF UI bileşenlerinin kendilerini farklı biçimlerde oluşturabilmesi.

12.4. JSF Mimarisi

JSF teknolojisi, iş ve algoritma mantığını sunum katmanından ayırmak için Model–Görünüm–Kontrolör (MVC) tasarım desenine dayanır (Şekil 15):

MVC Katmanı Görevi ve Sorumluluğu
Model Projede kullanılacak nesnelerin oluşturulduğu kısımdır; günlük hayattaki somut nesnelerin bilgisayar ortamında modellenmesidir (ör. kütüphane otomasyonunda kitabın seri numarası, adı, yazarı, yayınevi). JSF’de JavaBeans / Yönetilen Bean’ler ile temsil edilir.
Görünüm (View) Kullanıcının gördüğü arayüzdür (web sayfası, masaüstü veya mobil tasarım). Web tasarımcıları yalnızca görünüm katmanına odaklanır. JSF’de JSP/XHTML sayfaları ve UI bileşenleridir.
Kontrolör (Controller) Veri tabanı işlemleri, hesaplamalar ve veri aktarımı gibi tüm işlemlerin yürütüldüğü; model ile görünüm arasındaki veri akışını yöneten ve kullanıcı eylemlerini işleyen bölümdür. JSF’de Faces Servlet ve faces-config.xml ile yönetilir.

Bir JSF Uygulamasının Temel Bileşenleri (Çizim 16): Bir Java servlet teknolojisi altında (Uygulama Sunucusu üzerinde) çalışan JSF uygulaması şunları içerir:

  • Uygulamaya özgü veri ve işlevselliği taşıyan JavaBeans / Yönetilen (Managed) Bean’ler (Model),
  • Olay işleyicileri ve doğrulayıcıları temsil eden özel etiket kitaplığı,
  • UI bileşenlerini oluşturmak için özel etiket kitaplığı (JSP/JSF sayfaları ve bileşenleri),
  • Sunucuda durum bilgisi nesneler olarak tutulan UI bileşenleri,
  • Sunucu tarafı yardımcı sınıfları, hata kontrolörleri, olay ve gezinti işleyicileri,
  • Uygulama kaynaklarını yapılandıran faces-config.xml yapılandırma dosyası ve istekleri yönlendiren Faces Servlet.

12.5. JSF Yaşam Döngüsü

Bir JSF uygulaması, istemciden gelen bir formu veya isteği altı aşamalı bir yaşam döngüsü (Şekil 16 ve Çizim 17) içinde işler:

Faz Aşama Adı Gerçekleşen İşlemler
1 Görünümün Geri Yüklenmesi (Restore View) JSF bir link veya düğmeye tıklandığında ve bir istek aldığında başlar. Görünümü (bileşen ağacını) oluşturur veya geri yükler; olay işleyicileri ve doğrulayıcıları UI bileşenlerine bağlar.
2 İstek Değerlerinin Alınması (Apply Request Values) Bileşen ağacındaki her bileşen, kod çözme yöntemiyle istemciden gelen istek parametrelerinden (ör. doğum tarihi alanı) kendi yeni değerini ayıklar ve yerel değer olarak saklar; olaylar yürütülür.
3 Süreç Doğrulamaları (Process Validations) Bileşen ağacında kayıtlı tüm doğrulayıcılar (validators) çalıştırılır (ör. boş bırakılmaması gereken telefon numarası kontrolü). Tanımlı kurallar yerel değerlerle karşılaştırılır; olaylar yürütülür.
4 Model Değerlerinin Güncellenmesi (Update Model Values) Doğrulama başarılıysa JSF bileşen ağacını dolaşarak istemci bileşenlerindeki geçerli yerel değerleri sunucu tarafındaki bean özelliklerine aktarır (günceller); olaylar yürütülür.
5 Uygulamanın Çağrılması (Invoke Application) Form gönderme veya başka bir sayfaya bağlantı verme/navigasyon gibi uygulama düzeyindeki olaylar ve iş metotları yürütülür.
6 Cevabı Oluşturma (Render Response) JSF sayfayı oluşturması için uygulama sunucusundan ister. İlk istekte bileşenler ağaca eklenir; sonraki isteklerde mevcut ağaç kullanılır. Etiketler ve bileşenler işlenerek HTML yanıt istemciye gönderilir.
Kısa Devre (Erken Sonlandırma) Yolları (Çizim 17):
Yaşam döngüsü sırasında dönüştürme hataları, geçerlilik sonuçları (doğrulama hataları) oluştuğunda veya “Cevap Tamamlandı” durumu tetiklendiğinde ara aşamalar atlanarak doğrudan 6. aşamaya (Cevabı Oluştur) geçilir ve Faces Cevabı istemciye döndürülür.

13. Ünite: JSF ile Uygulama Geliştirme (Eclipse, Managed Bean ve WAR)

Ünitenin Amacı: Maven kullanarak sıfırdan bir JSF web projesi oluşturmayı, projeyi Eclipse IDE’ye aktarmayı, web.xml içinde FacesServlet yapılandırmasını yapmayı, JavaBean kurallarına uygun bir Yönetilen Bean (@ManagedBean) ve XHTML JSF sayfası yazmayı, projeyi .war paketine dönüştürüp Apache Tomcat sunucusunda dağıtmayı (deploy) uygulamalı olarak kavramaktır.

13.1. Temel Kavramlar

JSF’ten önce Java geliştiricileri web uygulamalarında HTML kullanıcı arayüzü bileşenlerini genellikle servletlerle veya JavaServer Pages (JSP sayfaları) ile oluşturmaktaydı. Ancak standart HTML bileşenleri tarayıcıların desteklediği en düşük ortak payda olduğundan bağımsız masaüstü istemcilerine kıyasla düşük işlevsellik ve sınırlı kullanılabilirlik sunuyordu. Büyük ölçekli web sistemlerinde veri tabanı sorguları için tablo görüntüleyici gibi özel bileşenler geliştirmek ise yoğun uzmanlık ve zaman gerektiriyordu.

JSF, sunucu tarafında çalışan ve kullanıcı arabirimini istemciye geri yükleyen standart bir UI iskeleti sunarak bu zorlukları çözer; arayüz kodu istemcide tetiklenen olaylara yanıt verecek biçimde sunucu üzerinde çalışır (Mahmoud, 2019).

13.5. Servlet Yapılandırması (web.xml)

Servlet: Belirli bir ağ isteğine (genellikle HTTP isteğine) cevap veren bir Java sınıfıdır; sunucu tarafında çalışır, gelen istekleri dinler, anlamlandırır ve istemciye HTML biçiminde yanıtlar oluşturup gönderir. Servlet’ler ağ iletişimini yöneten bir servlet kabında (ör. en bilinen açık kaynaklı kap olan Apache Tomcat) çalışır.

Tarayıcıdan erişim sağlanabilmesi için webapp/WEB-INF/web.xml dosyasında iki temel yapılandırma yapılır:

  • <servlet>: Servlet’e bir ad ve sınıf adı (javax.faces.webapp.FacesServlet) verilir.   • <servlet-mapping>: Hangi URL desenlerinin (/faces/*, *.jsf, *.faces, *.xhtml) Faces Servlet’e yönlendirileceğini eşler.

13.6. Bir Yönetilen Bean Oluşturma

JavaBean, birçok nesneyi tek bir nesne içine alan ve şu üç kurala uyan Java sınıfıdır:

  1. Serileştirilebilir (Serializable) olmalıdır (içerdiği tüm verilerle diske kaydedilebilmelidir).
  2. Genel (public) ve argümansız bir kurucuya (constructor) sahip olmalıdır.
  3. Tüm özellikleri özel (private) olmalı; dışarıdan erişim için getter ve setter genel metotları bulunmalıdır.

Yönetilen Bean (Managed Bean): JSF’ye kayıtlı ve JSF iskeleti tarafından yönetilen düzenli bir Java Bean sınıfıdır; getter/setter metotlarını, iş mantığını ve hatta bir destek bean’ini içerebilir. src/main/java/com/ilkders/test/HelloWorld.java örneği:

package com.ilkders.test;

import javax.faces.bean.ManagedBean;

@ManagedBean(name = "helloWorld")
public class HelloWorld {
    public HelloWorld() {
        System.out.println("HelloWorld started!");
    }

    public String getMessage() {
        return "Hello World!";
    }
}

Sınıftan nesne oluşturulduğunda argümansız kurucu otomatik çalışarak sunucu terminaline "HelloWorld started!" yazar; getMessage() metodu ise çağrıldığı yere "Hello World!" metnini döndürür.

13.7. Bir JSF Sayfasının Oluşturulması

webapp klasörü altında oluşturulan home.xhtml sayfası içinde yönetilen bean’e erişmek için #{} ifadesi kullanılır:

<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.0 Transitional//EN"
  "http://www.w3.org/TR/xhtml1/DTD/xhtml1-transitional.dtd">
<html xmlns="http://www.w3.org/1999/xhtml">
<head>
  <title>JSF Örneği!</title>
</head>
<body>
  #{helloWorld.getMessage()}
</body>
</html>
#{} Etiketi (Ertelenen İfadeler): #{}, sayfanın yaşam döngüsüne bağlı olarak çözümlenen ertelenen ifadeler (deferred expressions) içindir; bir Bean’den veri okumak, ona veri yazmak veya bir yöntem çağrısı yapmak için kullanılır. Sunucu sayfayı oluştururken #{helloWorld.getMessage()} çalıştırılır ve dönen sonuç istemciye gönderilir.

14. Ünite: Yönetilen Bean'lar ve Sayfa Navigasyonu (EL ve Navigasyon Kuralları)

Ünitenin Amacı: JSF 1.2 XML yapılandırması ile JSF 2.0 ek açıklama (annotation) yaklaşımı arasındaki farkı, JSF İfade Dilinin (EL) sağladığı avantajları, @ManagedBean özelliklerini (name ve eager), yönetilen bean kapsamlarını (Request, None, View, Session, Application, Custom), @ManagedProperty ile Bağımlılık Enjeksiyonunu (DI) ve örtük ile koşullu sayfa navigasyonu mekanizmalarını kavramaktır.

14.1. Temel Kavramlar

Yönetilen Bean’ler, JSF’de UI bileşeni için Model olarak çalışır ve JSF arayüz sayfalarından doğrudan erişilebilir.

  • JSF 1.2 Yaklaşımı (XML): Yönetilen bean’lerin faces-config.xml dosyasına kaydedilmesi gerekiyordu: 
    <managed-bean>
  <managed-bean-name>helloWorld</managed-bean-name>
  <managed-bean-class>com.ilkders.test.HelloWorld</managed-bean-class>
  <managed-bean-scope>request</managed-bean-scope>
</managed-bean>
<managed-bean>
  <managed-bean-name>message</managed-bean-name>
  <managed-bean-class>com.ilkders.test.Message</managed-bean-class>
  <managed-bean-scope>request</managed-bean-scope>
</managed-bean>
  • JSF 2.0 ve Sonrası Yaklaşımı (Ek Açıklamalar / Annotations): Bean’ler ve kayıt bilgileri doğrudan Java sınıfının üzerinde @ManagedBean, @RequestScoped, @ManagedProperty gibi ek açıklamalarla tanımlanır; böylece yönetim çok daha kolay hâle gelir.

14.2. JSF İfade Dili (EL — Expression Language)

JSF, #{işlem-ifade} gösterimini kullanan zengin bir ifade dili sağlar. JSF İfade Dilinin altı temel avantajı vardır:

  • İstek, oturum veya uygulama kapsamında saklanan nesneler ya da yönetilen bean’lerin özelliklerine referans verebilir.
  • Bir list, map veya array (aynı tipten çok sayıda değişken tutan dizi) koleksiyonunun ögelerine kolay erişim sağlar.
  • İstemci tarafı veri ve bilgilerini taşıyan request gibi önceden tanımlanmış nesnelere kolay erişim sunar.
  • Aritmetik, mantıksal ve ilişkisel işlemleri doğrudan ifade içinde gerçekleştirebilir.
  • Otomatik tür dönüşümü sağlar (ör. bir tam sayı ek işlem gerektirmeden metne dönüştürülür).
  • Eksik değerlerde NullPointerException hatası fırlatmak yerine sonucu boş olarak gösterir.
#{} ile ${} İfade Söz Dizimi Karşılaştırması:
  • #{ifade} (Ertelenen / Deferred Değerlendirme — JSF EL): Ders kitabının temel aldığı JSF sözdizimidir. Sayfanın yaşam döngüsüne bağlı olarak gerektiğinde çözümlenir; hem bean’den veri okumak hem bean’e veri yazmak (iki yönlü bağlama) hem de metot çağırmak için kullanılır.
  • ${ifade} (Anlık / Immediate Değerlendirme — JSP/JSTL EL): Sayfa işlenirken/render edilirken derhâl değerlendirilir; yalnızca salt-okunur (read-only) erişim sağlar ve JSF form bileşenlerinin veri yazma/yaşam döngüsü bağlamasında kullanılmaz.

14.3. @ManagedBean Ek Açıklaması

@ManagedBean, sınıfı yönetilen bir bean olarak işaretler. İki önemli niteliği bulunur:

  • name niteliği: Bean’in erişim adını belirtir. Eğer name belirtilmezse yönetilen bean adı varsayılan olarak sınıf adının baş harfi küçük hâli olur (ör. HelloWorld sınıfı → helloWorld).
  • eager niteliği: eager = true ayarlanırsa yönetilen bean ilk defa çağrılmadan önce (uygulama başlangıcında) yaratılır; aksi durumda yalnızca istendiğinde yaratılan “tembel” (lazy) başlatma kullanılır. Tembel başlatma sunucu belleğini daha verimli kullanır (istek gelmeden belleği şişirmez), ancak ilk istekte yanıt süresini hafifçe uzatabilir.

14.3.1. Kapsam Ek Açıklamaları

Yönetilen bean’in bellekte ne kadar süre yaşayacağını belirler. Hiçbir kapsam belirtilmezse bean varsayılan olarak request kapsamına girer. Tablo 11’e göre kapsamlar ve ömürleri şöyledir:

Kapsam Ek Açıklaması Ömrü ve Açıklama
@RequestScoped Bean, HTTP istek–yanıtı devam ettiği sürece yaşar. Bir HTTP isteği üzerine oluşturulur ve ilgili HTTP yanıtı tamamlandığında yok edilir (imha edilir).
@NoneScoped Bean, yalnızca tek bir EL değerlendirmesi süresince yaşar; EL değerlendirmesinde yaratılır ve hemen ardından imha edilir.
@ViewScoped Bean, kullanıcı tarayıcı penceresinde/sekmesinde aynı JSF görünümüyle (XHTML arayüzüyle) etkileşime girdiği sürece yaşar; farklı bir görünüme geçildiğinde yok edilir.
@SessionScoped Bean, HTTP oturumu boyunca yaşar. Oturumdaki ilk istekte yaratılır; güvenli çıkış yapılmadığı sürece kullanıcı siteden çıksa bile varsayılan olarak genellikle 30 dakika boyunca oturum sonlanmaz.
@ApplicationScoped Bean, tüm web uygulaması çalıştığı sürece yaşar. İlk HTTP isteğinde (veya eager = true ise uygulama başladığında) yaratılır ve web uygulaması kapandığında yok olur.
@CustomScoped Bean, bu kapsam için oluşturulan özel Harita (Map) içinde girişi bulunduğu sürece yaşar.

14.3.2. @ManagedProperty Ek Açıklaması (Bağımlılık Enjeksiyonu)

JSF basit bir statik Bağımlılık Enjeksiyonu (Dependency Injection — DI) iskeletidir. @ManagedProperty kullanılarak bir yönetilen bean başka bir yönetilen bean’in özelliğine otomatik olarak enjekte edilir; böylece kod içinde manuel olarak messageBean = new Message(); yazmaya gerek kalmaz:

// Message.java
@ManagedBean(name = "message", eager = true)
@RequestScoped
public class Message {
    private String message = "Hello World!";
    public String getMessage() { return message; }
    public void setMessage(String message) { this.message = message; }
}

// HelloWorld.java
@ManagedBean(name = "helloWorld", eager = true)
@RequestScoped
public class HelloWorld {
    @ManagedProperty(value = "#{message}")
    private Message messageBean;
    private String message;

    public HelloWorld() { System.out.println("HelloWorld started!"); }
    public String getMessage() {
        message = messageBean.getMessage();
        return message;
    }
    public void setMessageBean(Message message) { this.messageBean = message; }
}

home.xhtml sayfasında <h:body>#{helloWorld.message}</h:body> çağrıldığında JSF, message bean’ini otomatik enjekte ederek ekranda “Hello World!” çıktısını üretir (Görsel 8).

14.4. Sayfa Navigasyonu

Navigasyon kuralları, bir düğmeye veya bağlantıya tıklandığında hangi görünümün gösterileceğini belirler. Bu kurallar faces-config.xml içinde ya da doğrudan yönetilen bean’lerde tanımlanabilir; JSF 2.0 ise XML tanımı gerektirmeyen kapalı/örtük navigasyon desteği sunar.

14.4.1. Örtük Navigasyon (Implicit Navigation)

JSF 2.0’ın otomatik görüntüleme sayfası çözümleyici mekanizmasıdır. Arayüz adını doğrudan bileşenin action niteliğine yazmak yeterlidir; etkileşimli tüm bileşenler <h:form> etiketi içinde yer almalıdır:

<h:form>
  <h3>JSF Sonucunu kullanarak</h3>
  <h:commandButton action="page2" value="Sayfa 2" />
</h:form>

Kullanıcı düğmeye tıkladığında JSF page2 adını otomatik olarak page2.xhtml dosyasına çözümler ve sayfayı açar. Aynı mekanizma bir yönetilen bean metodunun döndürdüğü metinle de çalışır:

@ManagedBean(name = "navigationController", eager = true)
@RequestScoped
public class NavigationController implements Serializable {
    public String moveToPage1() {
        return "page1"; // veya sayfa1.xhtml için "sayfa1"
    }
}

<h:form>
  <h:commandButton action="#{navigationController.moveToPage1}" value="Sayfa 1" />
</h:form>

14.4.2. Koşullu Navigasyon (Conditional Navigation)

Yönetilen bean’deki bir metoda parametre gönderilerek navigasyonun dinamik biçimde kontrol edilmesidir (Görsel 11):

@ManagedBean(name = "navigasyonKontrol", eager = true)
@RequestScoped
public class NavigasyonKontrol implements Serializable {
    public String showPage(int pageId) {
        if (pageId == 0) {
            return "home";
        }
        if (pageId == 1) {
            return "page1";
        } else if (pageId == 2) {
            return "page2";
        } else {
            return "home";
        }
    }
}
<h:body>
  <h3>Koşullu Navigasyon</h3>
  <h:form>
    <h:commandButton action="#{navigasyonKontrol.showPage(1)}" value="Sayfa 1" />
    <h:commandButton action="#{navigasyonKontrol.showPage(2)}" value="Sayfa 2" />
    <h:commandButton action="#{navigasyonKontrol.showPage(3)}" value="Ana Sayfa" />
  </h:form>
</h:body>

Örneğin “Sayfa 1” düğmesine tıklandığında JSF pageId = 1 parametresini navigasyonKontrol.showPage(1) metoduna iletir; metot "page1" döndürür ve JSF geçerli dizinde page1.xhtml dosyasını bularak görüntüler.

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Sık Sorulan Noktalar:
  1. JSF 1.2 vs JSF 2.0 bean kaydı: -> JSF 1.2’de faces-config.xml dosyasında <managed-bean> ile yapılırdı; JSF 2.0’dan itibaren @ManagedBean ek açıklaması kullanılır.
  2. @ManagedBean varsayılan ad ve eager kuralı: -> name verilmezse sınıf adının ilk harfi küçük hâli kullanılır; eager="true" ise ilk çağrıdan önce bean yaratılır (aksi durumda tembel başlatma).
  3. Varsayılan kapsam ve kapsam ömürleri: -> Kapsam belirtilmezse varsayılan @RequestScoped olur; @NoneScoped tek EL değerlendirmesi, @ViewScoped aynı XHTML görünümü, @SessionScoped oturum (varsayılan 30 dk), @ApplicationScoped uygulama ömrü boyunca yaşar.
  4. Örtük vs Koşullu Navigasyon: -> Yalnızca eylem niteliğine sayfa/metot adını koyarak otomatik çözümleme örtük navigasyon; metoda parametre vererek if-else ile yönlendirme koşullu navigasyondur.

3@ManagedBean ek açıklamasının işaret ettiği yönetilen bean nasıl anlaşılır?
  • A) Name özelliğinde belirtilen adla yönetilen bir bean’i işaretler. Name niteliği belirtilmezse, yönetilen bean adı varsayılan olarak tesadüfi bir ad olur.
  • B) Eager özelliğinde belirtilen numarayla yönetilen bir bean’i işaretler.
  • C) Name özelliğinde belirtilen adla yönetilen bir bean’i işaretler. Name niteliği belirtilmezse, yönetilen bean adı varsayılan olarak tam sınıf adı olur. Ancak baş harf her zaman küçük olacaktır.
  • D) Name özelliğinde belirtilen adla yönetilen bir bean’i işaretler. Name niteliği belirtilmezse, yönetilen bean adı varsayılan olarak tam sınıf adı olur. Ancak harfler her zaman büyük olacaktır.
  • E) @ManagedBean ek açıklama almaz. Web.xml dosyasında gerekli düzenlemeler yapılır.
Çözüm & Açıklama: Bölüm 14.3’e göre name belirtilmezse sınıf adı varsayılan bean adı olur ve baş harfi her zaman küçük yapılır (ör. HelloWorld → helloWorld). Doğru cevap C şıkkıdır.
4@ManagedBean ek açıklamasında eager niteliği ne işe yarar?
  • A) Belirtilen numarayla yönetilen bir bean işaretlenir.
  • B) Eğer “true” ise, ilk defa çağrılmadan önce yönetilen bean yaratılır, aksi takdirde sadece istendiğinde yaratılacak olan “tembel” başlatma kullanılır.
  • C) Eğer “view” ise, ilk defa çağrılmadan önce yönetilen bean yaratılır, aksi takdirde sadece istendiğinde yaratılacak olan “hızlı” başlatma kullanılır.
  • D) Eğer “request” ise, ilk defa çağrılmadan önce yönetilen bean yaratılır, aksi takdirde sadece istendiğinde yaratılacak olan “tembel” başlatma kullanılır.
  • E) Belirtilen isimle yönetilen bir bean adlandırılır.
Çözüm & Açıklama: Bölüm 14.3’te eager = "true" ise bean’in ilk çağrıdan önce oluşturulduğu, aksi durumda ise yalnızca istendiğinde yaratılan “tembel” (lazy) başlatmanın kullanıldığı anlatılmaktadır. Doğru cevap B şıkkıdır.
5@RequestScoped ek açıklaması ne anlama gelir?
  • A) Bean, birden fazla EL değerlendirmesi olduğu sürece yaşar. EL değerlendirmesinde yaratılır.
  • B) Bean, tek bir EL değerlendirmesi olduğu sürece yaşar. EL değerlendirmesinde imha edilir.
  • C) Bean, tek bir EL değerlendirmesi olduğu sürece yaşar. EL değerlendirmesinde yaratılır ve EL değerlendirmesinden hemen sonra imha edilir.
  • D) Bean, HTTP istek yanıtı devam ettiği sürece yaşar. Bir HTTP isteği üzerine oluşturulur ve HTTP isteği ile ilişkilendirilmiş HTTP yanıtı tamamlandığında imha edilir.
  • E) Bean, tek bir HTTP istek yanıtı olduğu sürece yaşar. http istek yanıtıyla yaratılır ve HTTP istek yanıtından hemen sonra imha edilir.
Çözüm & Açıklama: Tablo 11’de @RequestScoped kapsamı “Bean, HTTP istek yanıtı devam ettiği sürece yaşar. Bir HTTP isteği üzerine oluşturulur ve HTTP isteği ile ilişkilendirilmiş HTTP yanıtı tamamlandığında yok/imha edilir” şeklinde tanımlanır. Doğru cevap D şıkkıdır.

  • C) Bean, tek bir EL değerlendirmesi olduğu sürece yaşar. EL değerlendirmesinde yaratılır ve EL değerlendirmesinden hemen sonra imha edilir.
  • D) Bean, HTTP istek yanıtı devam ettiği sürece yaşar. Bir HTTP isteği üzerine oluşturulur ve HTTP isteği ile ilişkilendirilmiş HTTP yanıtı tamamlandığında imha edilir.
  • E) Bean, tek bir HTTP istek yanıtı olduğu sürece yaşar. HTTP istek yanıtıyla yaratılır ve HTTP istek yanıtından hemen sonra imha edilir.
Çözüm & Açıklama: Kitabın resmî cevap anahtarı C şıkkını vermektedir (basım hatası nedeniyle 5. sorunun şıkları tekrarlanmıştır). Ancak Tablo 11’deki gerçek @ViewScoped tanımı: “Bean, tarayıcı penceresinde/sekmesinde kullanıcı aynı JSF görünümüyle (bir xhtml arayüzüne bağlı bean) etkileşime girdiği sürece yaşar; farklı bir görünüme geçildiğinde yok edilir” şeklindedir (C şıkkındaki tanım aslında @NoneScoped’a aittir). Sınavlarda resmî anahtar C olarak kayıtlıdır.

  • C) Message yönetilen özelliği HelloWorld isimli başka bir özelliği kullanmaktadır.

Çözüm & Açıklama: Bölüm 14.3.2’de açıklandığı gibi HelloWorld yönetilen bean’i @ManagedProperty enjeksiyonu sayesinde Message isimli başka bir bean’i messageBean değişkeniyle kullanmaktadır. Doğru cevap E şıkkıdır.

9Aşağıdaki ara yüz sayfasında “Sayfa 1” isimli düğme tıklandığında sayfa1.xhtml’e gitmek için nasıl bir yönetilen bean’e ihtiyaç vardır?
<h:form> <h:commandButton action="#{navigationController.moveToPage1}" value="Sayfa 1" /> </h:form>
  • A) @ManagedBean(name = "moveToPage1", eager = true) @RequestScoped public class NavigationController implements Serializable { public String moveToPage1(){ return "sayfa1"; } }
  • B) @ManagedBean(name = "navigationController", eager = true) @RequestScoped public NavigationController implements Serializable { public String moveToPage1(){ return "moveTosayfa1"; } }
  • C) @ManagedBean(name = "navigationController", eager = true) @RequestScoped public class NavigationController implements Serializable { public String moveToPage1(){ return "sayfa1"; } }
  • D) @ManagedProperty(name = "navigation", eager = true) @RequestScoped public class NavigationController implements Serializable { public String moveToPage1(){ return "sayfa1"; } }
  • E) @ManagedBean(name = "navigation", eager = true) @RequestScoped public Navigation implements Serializable { public String moveToPage1(){ return "sayfa1"; } }
Çözüm & Açıklama: Arayüzde #{navigationController.moveToPage1} çağrıldığı için bean adı "navigationController", sınıf bildirimi geçerli (public class NavigationController) ve moveToPage1() metodunun dönüş değeri "sayfa1" olmalıdır (JSF bunu sayfa1.xhtml olarak çözer). Doğru cevap C şıkkıdır.

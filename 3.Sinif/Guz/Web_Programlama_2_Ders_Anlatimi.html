1. Ünite: İnternet ve Web Teknolojileri Temel Kavramlar

Ünitenin Amacı: İstemci taraflı (Client-Side) ve Sunucu taraflı (Server-Side) web programlama mimarilerini, web çatılarını (Web Frameworks), Microsoft .NET ekosisteminin tarihsel evrimini (.NET Framework, .NET Core, ASP.NET Core) ve çok katmanlı yazılım mimari desenlerini (N-Tier, Microservices, MVC) eksiksiz kavramaktır.

1.1. İstemci (Client-Side) vs. Sunucu (Server-Side) Mimarisi

Özellik İstemci Taraflı (Client-Side / Front-End) Sunucu Taraflı (Server-Side / Back-End)
Çalıştığı Ortam Kullanıcının web tarayıcısı (Chrome, Edge, Safari vb.) Uzak web sunucusu (IIS, Kestrel, Nginx, Apache)

Kaynak Kod Güvenliği Kodlar açıktır; "Kaynağı Görüntüle" ile herkes görebilir Kodlar gizlidir ve derlenmiştir (DLL); kullanıcı asla kaynak kodu göremez

1.2. .NET Ekosisteminin Evrimi: .NET Framework vs. .NET Core vs. ASP.NET Core

  • .NET Framework (2002-2019): Yalnızca Windows işletim sisteminde çalışan, monolitik ve Windows API'lerine bağımlı geleneksel Microsoft çatısıdır.
  • .NET Core (2016 - Günümüz): Microsoft'un tamamen sıfırdan yazdığı, Platformlar Arası (Cross-Platform: Windows, Linux, macOS), açık kaynak kodlu, yüksek performanslı ve modüler çatı.
  • ASP.NET Core: Modern bulut tabanlı ve internete bağlı web uygulamaları geliştirmek için tasarlanmış yüksek performanslı web çatısıdır. Dahili olarak Kestrel web sunucusu ve Bağımlılık Enjeksiyonu (Dependency Injection - DI) motoru ile gelir.

ASP.NET Core'un Temel Avantajları:

  1. Çoklu Platform (Cross-Platform): Geliştirilen uygulama Linux Docker konteynerlerinde veya macOS üzerinde sorunsuz çalışır.
  2. Aşırı Hız ve Hafiflik: TechEmpower bağımsız kıyaslama testlerinde dünyanın en hızlı web framework'leri arasındadır.
  3. Yerleşik Bağımlılık Enjeksiyonu (Built-in Dependency Injection): Harici kütüphaneye gerek kalmadan gevşek bağlı (loosely-coupled) mimari sağlar.
  4. Asenkron Programlama Desteği: async/await mimarisi ile sunucu iş parçacıkları (thread) bloke olmadan saniyede on binlerce eşzamanlı isteği karşılar.

1.3. Yazılım Mimari Modelleri (Architectural Patterns)

  • Monolitik Mimari: Tüm katmanların (arayüz, iş mantığı, veri erişimi) tek bir proje ve tek bir derlenebilir blok halinde çalıştığı geleneksel modeldir. Küçük projeler için hızlıdır ancak proje büyüdükçe bakımı zorlaşır.
  • N-Katmanlı (N-Tier) Mimari: Uygulamanın Sunum Katmanı (Presentation), İş Mantığı Katmanı (Business/BLL) ve Veri Erişim Katmanı (Data Access/DAL) olarak ayrılmasıdır.
  • Mikroservis Mimarisi (Microservices): Uygulamanın bağımsız olarak geliştirilen, dağıtılan ve ölçeklenen küçük servisler (Auth servisi, Sipariş servisi, Ödeme servisi) halinde REST API'lerle haberleşmesidir.
  • MVC (Model-View-Controller) Modeli: Arayüz ile iş mantığını birbirinden ayıran temel web tasarım desenidir.

2. Ünite: MVC Yapısı ve ASP.NET Core ile MVC Kullanımı

Ünitenin Amacı: Model-View-Controller mimarisinin üç temel ayağını, HTTP isteklerinin Controller ve Action metotları tarafından karşılanmasını, Program.cs dosyasındaki Middleware (Ara Yazılım) hattını ve URL Yönlendirme (Routing) mekanizmasını öğrenmektir.

2.1. MVC Mimarisi: Model, View, Controller

1. Model:

Uygulamanın verilerini ve iş kurallarını temsil eden C# sınıflarıdır (POCO - Plain Old CLR Objects). Veritabanındaki tabloların nesne tabanlı karşılıklarıdır (Örn: Product.cs, Customer.cs).

2. View:

Kullanıcının gördüğü HTML çıktısıdır. ASP.NET Core'da .cshtml uzantılı Razor dosyalarıdır. Controller tarafından gönderilen modeli alır ve kullanıcıya render eder.

3. Controller:

Kullanıcıdan gelen HTTP isteklerini karşılayan, modeli çağırıp işleyen ve hangi View'in döneceğine karar veren yönetici sınıftır. Microsoft.AspNetCore.Mvc.Controller temel sınıfından türer.

2.2. Controller ve Action Metotları

Controller içindeki dışarıdan HTTP ile çağrılabilen public metotlara Action Metodu denir. Action metotları genellikle IActionResult arayüzünü döner.

using Microsoft.AspNetCore.Mvc;

namespace WebApp.Controllers
{
    public class UrunController : Controller
    {
        // GET: /Urun/Index
        public IActionResult Index()
        {
            var urunler = new List { "Laptop", "Mouse", "Klavye" };
            return View(urunler); // Views/Urun/Index.cshtml dosyasını render eder
        }

        // GET: /Urun/Detay/5
        public IActionResult Detay(int id)
        {
            if (id <= 0) return NotFound(); // 404
            return View();
        }
    }
}

2.3. Program.cs ve Middleware (Ara Yazılım) Hattı

.NET 6/7/8 ile birlikte Startup.cs dosyası kaldırılarak tüm yapılandırma Program.cs dosyasında birleştirilmiştir.

  • Builder Aşaması (Servisler): builder.Services.AddControllersWithViews(); ile MVC servisleri Dependency Injection konteynerine eklenir.
  • App Aşaması (Middleware Pipeline): İsteklerin geçtiği boru hattıdır:
    1. app.UseHttpsRedirection(); (HTTP'den HTTPS'e yönlendirir)
    2. app.UseStaticFiles(); (wwwroot altındaki CSS, JS, resim dosyalarını sunar)
    3. app.UseRouting(); (URL yönlendirmesini eşler)
    4. app.UseAuthorization(); (Yetkilendirme kontrolü)
    5. app.MapControllerRoute(...); (Varsayılan rota şablonunu belirler)

Varsayılan Rota (Default Route):

"{{controller=Home}}/{{action=Index}}/{{id?}}"

Eğer URL'de hiçbir şey yazılmazsa Controller = Home, Action = Index, id ise opsiyoneldir (?).

3. Ünite: Layout Kavramı ve Razor View Engine

Ünitenin Amacı: HTML ile C# kodlarını kusursuz harmanlayan Razor sözdizimini (@), ortak site şablonunu oluşturan Layout (_Layout.cshtml) mimarisini, @RenderBody() ve @RenderSection() direktiflerini, _ViewStart ve _ViewImports dosyalarını öğrenmektir.

3.1. Razor View Engine ve '@' Sözdizimi

Razor; C# kodlarının HTML sayfaları içerisine akıcı ve okunabilir biçimde gömülmesini sağlayan şablon motorudur. @ karakteri ile C# kod bloğuna geçilir:

  • Tek satırlı ifade: <p>Bugünün Tarihi: @DateTime.Now.ToString("dd.MM.yyyy")</p>
  • Çok satırlı C# kod bloğu: 
    @{
    var mesaj = "AUZEF Web Programlama 2";
    int saat = DateTime.Now.Hour;
}
  • Koşul ve Döngüler: 
    @if (saat < 12) {
    <span>Günaydın!</span>
} else {
    <span>İyi günler!</span>
}

3.2. Layout Mimarisi (_Layout.cshtml) ve Direktifler

Bir web sitesindeki tüm sayfalarda ortak olan üst menü (header), alt bilgi (footer), stil dosyaları ve script etiketleri tek bir dosyada, _Layout.cshtml içinde tanımlanır.

1. @RenderBody() Direktifi:

Layout dosyasının tam ortasında yer alan ve çağrılan spesifik View'in (örneğin Home/Index.cshtml) HTML içeriğinin basılacağı yeri belirten ZORUNLU yer tutucudur. Her Layout dosyasında tam olarak bir adet @RenderBody() bulunmalıdır.

2. @RenderSection("Scripts", required: false) Direktifi:

Yalnızca belirli sayfalara özel JavaScript veya CSS dosyalarının şablonun belirli bir bölgesine (genellikle sayfa sonuna) enjekte edilmesini sağlar.

3. _ViewStart.cshtml Dosyası:

Views klasörünün kökünde yer alır. Tüm View'ler çalışmadan önce ilk bu dosya tetiklenir ve varsayılan Layout şablonunu belirler:

@{{
    Layout = "_Layout";
}}

4. _ViewImports.cshtml Dosyası:

Tüm View'lerde kullanılacak ortak using namespace'lerini ve Tag Helper kütüphanelerini tanımlar (Örn: @addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers).

4. Ünite: Form İşlemleri ve Model Bağlama (Model Binding)

Ünitenin Amacı: HTTP GET ve POST metotları arasındaki farkları, HTML formlarından sunucuya veri gönderme mekanizmasını, Model Binding'in form alanlarını C# sınıflarına otomatik eşleme sürecini ve veri kaynağı özniteliklerini ([FromForm], [FromQuery], [FromRoute]) öğrenmektir.

4.1. HTTP GET vs. HTTP POST

Özellik HTTP GET HTTP POST
Verinin Taşındığı Yer URL QueryString içinde (Örn: /Arama?kelime=kitap&sayfa=1) HTTP İstek Gövdesi (Request Body) içinde gizli taşınır
Görünürlük ve Güvenlik Veri adres çubuğunda açıktır; şifre ve kredi kartı için ASLA kullanılmaz Adres çubuğunda görünmez; güvenli ve gizlidir
Veri Boyutu Kısıtı URL uzunluk kısıtı vardır (yaklaşık 2048 karakter) Boyut sınırı pratik olarak yoktur (dosya ve resim yüklenebilir)
Kullanım Amacı Sunucudan veri sorgulamak, listelemek, aramak Sunucuda veri oluşturmak, güncellemek, kaydetmek

4.2. Model Bağlama (Model Binding) Mekanizması

ASP.NET Core Model Bağlama mekanizması; HTTP isteğiyle gelen heterojen verileri (QueryString, Form girdileri, Route verileri) otomatik olarak Action metodunun parametrelerine veya karmaşık bir C# model nesnesine dönüştürür.

// Model Sınıfı
public class UyeModel {
    public string Ad { get; set; }
    public string Email { get; set; }
    public int Yas { get; set; }
}

// Controller Action
[HttpPost]
public IActionResult Kaydet(UyeModel uye) {
    // Model Binding formdaki name="Ad", name="Email", name="Yas" 
    // alanlarını otomatik olarak UyeModel nesnesinin içine doldurur!
    if (ModelState.IsValid) {
        // veritabanına kaydet
        return RedirectToAction("Index");
    }
    return View(uye);
}

Model Bağlama Veri Kaynağı Öznitelikleri:

  • [FromQuery]: Verinin URL QueryString'den alınacağını belirtir.
  • [FromRoute]: Verinin URL rota yolundan (Route data, örn: /Urun/Detay/{id}) alınacağını belirtir.

6. Ünite: Etiket Yardımcıları (Tag Helper)

Ünitenin Amacı: ASP.NET Core Razor görünümlerinde sunucu taraflı kodların standart HTML etiketleri gibi doğal bir sözdizimiyle yazılmasını sağlayan Tag Helper (Etiket Yardımcısı) teknolojisini kavramak; geleneksel HTML Helper yöntemleriyle farklarını analiz etmek ve form, bağlantı, girdi denetimi bileşenlerini yetkinlikle yapılandırmaktır.

6.1. Tag Helper (Etiket Yardımcıları) Kavramı ve Çalışma Mantığı

ASP.NET Core MVC mimarisinde görünümlerin (View) oluşturulmasında en devrimsel yeniliklerden biri Tag Helper (Etiket Yardımcıları) yapısıdır. Klasik ASP.NET MVC sürümlerinde C# kodları ve sunucu taraflı kontroller, Razor görünümlerine @Html.TextBoxFor(), @Html.ActionLink() gibi C# metot çağrıları (HTML Helpers) şeklinde entegre edilmekteydi. Bu durum HTML kodunun okunabilirliğini bozmakta ve ön yüz (Front-End) geliştiricilerinin şablonlar üzerinde çalışmasını güçleştirmekteydi.

Tag Helper teknolojisi ise sunucu taraflı kodların doğrudan standart HTML etiketlerine özel öznitelikler (attributes) eklenmesi yoluyla çalışmasını sağlar. Tarayıcıya gönderilmeden önce sunucuda Razor Engine tarafından işlenir ve saf HTML5 çıktılarına dönüştürülür.

Temel Prensip: Bir Razor görünümünde Tag Helper kullanabilmek için dosyanın veya genel _ViewImports.cshtml dosyasının en başında @addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers direktifinin tanımlanmış olması zorunludur.

6.2. Tag Helper ile Geleneksel HTML Helper Karşılaştırması

Özellik Geleneksel HTML Helper (ASP.NET MVC) Modern Tag Helper (ASP.NET Core)
Yazım Sözdizimi C# metot çağrısı: @Html.ActionLink("Giriş", "Login", "Account") Doğal HTML etiketi: <a asp-controller="Account" asp-action="Login">Giriş</a>
HTML Uyumu HTML şablonunun hiyerarşik akışını bozar; CSS sınıfları için karmaşık anonim nesneler gerekir: new { @class = "btn btn-primary" } Doğrudan standart HTML class="btn btn-primary" özniteliği yazılır. Ön yüz araçları ve tasarımcılar zorlanmaz.
IntelliSense Desteği Sadece C# metot parametrelerinde tamamlama sağlar. HTML etiketleri ve model alanları için hem HTML hem C# çift yönlü IntelliSense desteği sunar.
Genişletilebilirlik Yeni C# Extension metotları yazmayı gerektirir. TagHelper sınıfından türetilen özel C# sınıfları ile özel HTML etiketleri (örn: <email mail-to="destek@site.com"></email>) tanımlanabilir.

6.3. Sık Kullanılan Standart Tag Helper Bileşenleri

1. Anchor Tag Helper (<a>)

Sayfalar arası bağlantı (hyperlink) oluştururken URL'yi elle (hardcoded) yazmak yerine MVC rota sistemini (Routing) dinamik olarak kullanır:

<!-- Belirli Controller ve Action'a yönlendiren rota parametreli bağlantı -->
<a asp-controller="Product" asp-action="Details" asp-route-id="@Model.Id" class="btn btn-info">
    Ürün Detayını Gör
</a>

<!-- Sayfa içi çapa (fragment) ve protokol belirleme -->
<a asp-controller="Home" asp-action="About" asp-fragment="ekip" asp-protocol="https">
    Hakkımızda / Ekibimiz
</a>

Sunucu bu etiketi derlediğinde rota tablosunu çözümleyerek <a href="/Product/Details/5" class="btn btn-info"> şeklinde saf bir HTML çıktısı üretir.

2. Form Tag Helper (<form>)

Form etiketinin gönderileceği hedefi belirler. En kritik özelliklerinden biri, CSRF (Cross-Site Request Forgery - Siteler Arası İstek Sahteciliği) saldırılarına karşı otomatik olarak gizli bir anti-forgery güvenlik belirteci (__RequestVerificationToken) eklemesidir:

<form asp-controller="Account" asp-action="Login" method="post">
    <!-- Arka planda otomatik eklenen güvenlik inputu: -->
    <!-- <input name="__RequestVerificationToken" type="hidden" value="CfDJ8..." /> -->
</form>

3. Input ve Label Tag Helper (<input> ve <label>)

asp-for özniteliği, girdi alanını modelin belirli bir özelliğine (property) bağlar. Modeldeki veri tipini otomatik analiz ederek uygun HTML5 type niteliğini üretir:

  • Eğer model özelliği bool ise type="checkbox"
  • Eğer string ve [DataType(DataType.Password)] ise type="password"
  • Eğer DateTime ise type="datetime-local" veya type="date"
  • Eğer int veya decimal ise type="number"
<div class="form-group">
    <label asp-for="Email" class="control-label"></label>
    <input asp-for="Email" class="form-control" />
    <span asp-validation-for="Email" class="text-danger"></span>
</div>

4. Select Tag Helper (<select>)

Açılır listelerin (dropdown) dinamik veri koleksiyonlarıyla doldurulmasını sağlar. asp-for seçilen değeri modele bağlarken, asp-items listelenecek elemanları (IEnumerable<SelectListItem> veya SelectList) bağlar:

<select asp-for="CategoryId" asp-items="Model.CategoryList" class="form-control">
    <option value="">-- Bir Kategori Seçiniz --</option>
</select>

5. Textarea Tag Helper (<textarea>)

Çok satırlı metin alanlarını modele bağlar. İki etiket arasına model değerini kendiliğinden basar:

<textarea asp-for="Description" rows="5" cols="40" class="form-control"></textarea>

6.4. Hazır Razor View Şablonları Oluşturma (Scaffolding Razor View)

Visual Studio ve .NET CLI araçları, bir model ve veri bağlamı (DbContext) temelinde otomatik CRUD (Create, Read, Update, Delete) görünümleri oluşturmak için Scaffolding (iskele kurma) mekanizması sunar.

  • List (Index): Tablo biçiminde tüm kayıtları listeleyen, Düzenle/Detay/Sil butonlarını içeren şablon.
  • Create: Yeni kayıt ekleme formu oluşturan, validation tag helper'ları barındıran şablon.
  • Edit: Mevcut kaydı güncellemek için gizli ID alanı ve girdi formları barındıran şablon.
  • Details: Tek bir kaydın tüm alanlarını salt okunur listeleyen şablon.
  • Delete: Kaydı silmeden önce kullanıcıdan onay isteyen özet ekran şablonu.

7. Ünite: Model Doğrulama (Model Validation)

Ünitenin Amacı: Kullanıcıdan alınan verilerin iş kurallarına, güvenlik ilkelerine ve veri tabanı kısıtlarına uygunluğunu denetleyen Model Doğrulama (Model Validation) mekanizmasını, Veri Açıklamaları (Data Annotations) özniteliklerini, istemci ve sunucu taraflı doğrulama farklarını ve hata mesajlarının Razor görünümlerinde sunulmasını derinlemesine öğrenmektir.

7.1. Model Doğrulama Kavramı ve Güvenlik Mantığı

Web uygulamalarında kullanıcıdan formlar, URL parametreleri veya JSON gövdeleri üzerinden veri kabul edilirken, "Kullanıcıdan gelen hiçbir girdiye güvenilemez" (Never trust user input) altın kuralı esastır. Hatalı, eksik veya kötü niyetli (SQL Injection, XSS) verilerin veri tabanına yazılmasını önlemek için iki aşamalı bir doğrulama katmanı kurgulanır:

  • İstemci Taraflı (Client-Side) Doğrulama: Kullanıcı henüz formu göndermeden (submit etmeden) web tarayısıcında JavaScript aracılığıyla çalışır. Sunucuya gereksiz istek gitmesini önler ve kullanıcıya anlık (real-time) geri bildirim sağlar. Ancak tarayıcıda JavaScript devre dışı bırakılabilir veya istekler Postman gibi araçlarla doğrudan sunucuya iletilebilir.
  • Sunucu Taraflı (Server-Side) Doğrulama: Veriler sunucuya ulaştığında Controller katmanında çalışır. Asla atlatılamaz ve sistem güvenliğinin ana omurgasını oluşturur.

7.2. Veri Açıklamaları (Data Annotations)

ASP.NET Core'da doğrulama kuralları, model sınıflarının özellikleri üzerine System.ComponentModel.DataAnnotations ad alanı altındaki öznitelikler (attributes) eklenerek tanımlanır:

Öznitelik (Annotation) Açıklama ve Amacı Örnek Kullanım
[Required] Alanın boş bırakılamayacağını, zorunlu olduğunu belirtir. [Required(ErrorMessage = "Ad alanı boş geçilemez!")]
[StringLength(max, Min)] Metinsel ifadenin alabileceği maksimum ve opsiyonel minimum uzunluğu sınırlar. [StringLength(50, MinimumLength = 3, ErrorMessage = "Ad 3-50 karakter olmalıdır.")]
[Range(min, max)] Sayısal değerlerin veya tarihlerin belirli bir aralıkta kalmasını zorunlu kılar. [Range(18, 65, ErrorMessage = "Yaşınız 18 ile 65 arasında olmalıdır.")]
[EmailAddress] Metnin geçerli bir e-posta formatında (örn: kullanici@alanadi.com) olmasını denetler. [EmailAddress(ErrorMessage = "Geçersiz e-posta formatı!")]
[Compare("OtherProp")] İki model özelliğinin değerlerinin birebir eşit olmasını denetler (şifre tekrarı gibi alanlarda). [Compare("Password", ErrorMessage = "Şifreler uyuşmuyor!")]
[RegularExpression("pattern")] Verinin özel bir düzenli ifadeye (Regex) uymasını sağlar (T.C. Kimlik No, telefon formatı vb.). [RegularExpression(@"^[0-9]{11}$", ErrorMessage = "T.C. No 11 haneli olmalıdır.")]
[DataType(DataType.Password)] Verinin tipini belirler, form oluşturulurken maskeli girdi (şifre alanı) oluşturulmasını sağlar. [DataType(DataType.Password)]

7.3. Sunucu Taraflı Doğrulama ve ModelState Kontrolü

Model bağlama (Model Binding) tamamlandığında ASP.NET Core tüm kuralları işletir ve sonucu ModelState nesnesi içerisine kaydeder. Controller aksiyonunda bu durum ModelState.IsValid mantıksal özelliği ile sorgulanır:

[HttpPost]
public IActionResult Register(UserRegisterViewModel model)
{
    // Özel iş kuralı doğrulaması (Custom Validation):
    if (model.Username == "admin")
    {
        ModelState.AddModelError("Username", "Bu kullanıcı adı sistem tarafından rezerve edilmiştir.");
    }

    if (!ModelState.IsValid)

8. Ünite: LINQ - Language Integrated Query (Dile Entegre Sorgu)

Ünitenin Amacı: .NET dillerinde bellek içi koleksiyonlar, XML dokümanları ve ilişkisel veritabanları üzerinde standart, tip güvenli (type-safe) ve derleme zamanı denetimli sorgular yazmayı sağlayan LINQ mimarisini, sorgu sözdizimlerini (Query Syntax vs. Method/Lambda Syntax), ertelenmiş (Deferred) ve anlık (Immediate) sorgu yürütme mekanizmalarını ve temel sorgu operatörlerini kavramaktır.

8.1. LINQ Mimarisi ve Avantajları

Geleneksel yazılım geliştirmede dizi ve koleksiyonlar için döngüler (foreach, for), veritabanları için SQL dizgileri, XML belgeleri için XPath gibi birbirinden tamamen farklı diller ve sözdizimleri kullanılmaktaydı. SQL sorguları metin (string) olarak yazıldığından sözdizimi hataları ancak çalışma zamanında (runtime) fark edilebiliyordu.

LINQ (Language Integrated Query), veri kaynağı ne olursa olsun C# dilinin doğal bir parçası olarak sorgu yazmayı mümkün kılan bir teknolojidir. Sağladığı başlıca avantajlar:

  • Tip Güvenliği (Type-Safety): Sorgulanan nesnelerin tipleri derleyici tarafından bilinir.
  • IntelliSense Desteği: Kod yazarken alan adları ve metotlar otomatik tamamlanır.
  • Derleme Zamanı Kontrolü (Compile-Time Checking): Alan adı hataları veya tip uyumsuzlukları anında derleme hatası verir.
  • Tek Tip Sözdizim: Nesneler (LINQ to Objects), veritabanları (LINQ to Entities / EF Core) ve XML (LINQ to XML) aynı felsefeyle sorgulanır.

8.2. LINQ Sorgularının Yürütülmesi: Ertelenmiş vs. Anlık Yürütme

LINQ sorgularının arka plandaki çalışma mantığı sınavlarda en çok test edilen akademik konulardan biridir:

Kavram Ertelenmiş Yürütme (Deferred / Lazy Execution) Anlık Yürütme (Immediate Execution)
Tanım Sorgu tanımlandığı satırda veritabanına veya koleksiyona gönderilmez; yalnızca sorgunun yürütme planı (IQueryable<T> veya IEnumerable<T>) hazırlanır. Sorgu yazıldığı anda anında bellekte veya veritabanında çalıştırılır ve gerçek veriler elde edilir.
Ne Zaman Çalışır? Veriler üzerinde bir foreach döngüsü başlatıldığında veya anlık yürütme metodu çağrıldığında çalışır. Metot çağrıldığı satırda anında yürütülür.
Tetikleyen Metotlar Where, Select, OrderBy, GroupBy, Take, Skip ToList(), ToArray(), Count(), Sum(), Average(), First(), Single()

8.3. LINQ Sorgu Sözdizimleri (Query Syntax vs. Method Syntax)

C#'ta LINQ sorguları iki farklı sözdizimiyle yazılabilir:

1. Sorgu Sözdizimi (Query Syntax - SQL Benzeri)

var sonuc = from o in ogrenciler
            where o.NotOrtalamasi >= 70
            orderby o.Ad ascending
            select o;

2. Metot Sözdizimi (Method / Fluent Syntax - Lambda İfadeli)

var sonuc = ogrenciler
            .Where(o => o.NotOrtalamasi >= 70)
            .OrderBy(o => o.Ad)
            .ToList();

Modern ASP.NET Core projelerinde genişletme metotları (Extension Methods) ve Lambda ifadeleri (x => x...) kullanan Metot Sözdizimi daha yaygın ve esnektir.

8.4. Sık Kullanılan LINQ Operatörleri ve Metotları

1. Filtreleme ve Sıralama Operatörleri

  • Where(koşul): Koleksiyondan belirli bir mantıksal koşulu sağlayan elemanları süzer: urunler.Where(u => u.Fiyat > 100)
  • OrderBy(alan): Küçükten büyüğe (artan - ascending) sıralar: urunler.OrderBy(u => u.Fiyat)
  • OrderByDescending(alan): Büyükten küçüğe (azalan - descending) sıralar.
  • ThenBy(alan) / ThenByDescending(alan): Birinci sıralamada eşit olan elemanları ikinci bir kritere göre sıralamak için zincirlenir.

2. Projeksiyon (Dönüştürme) ve Gruplama

  • Select(): Koleksiyondaki nesneleri yeni bir tipe (ViewModel veya anonim nesne new { ... }) dönüştürür: 
    var urunOzet = urunler.Select(u => new { u.Ad, u.Fiyat }).ToList();
  • GroupBy(): Belirli bir özelliğe göre elemanları gruplara ayırır (IGrouping<TKey, TElement>): 
    var gruplar = urunler.GroupBy(u => u.KategoriId);

3. Tekil Eleman Seçiciler (Kritik Sınav Konusu)

Metot Eleman Bulunamazsa Birden Fazla Eleman Varsa
First() Hata fırlatır (InvalidOperationException) İlk eşleşen elemanı döndürür.
FirstOrDefault() Varsayılan değeri (nesneler için null) döndürür. İlk eşleşen elemanı döndürür.
Single() Hata fırlatır (InvalidOperationException) Hata fırlatır (Tek bir kayıt olması zorunludur!).
SingleOrDefault() Varsayılan değeri (null) döndürür. Hata fırlatır!

4. Sayısal ve Mantıksal Toplama Metotları

  • Count(): Eleman sayısını döndürür.
  • Sum(), Average(), Min(), Max(): İlgili alanın toplamını, ortalamasını, minimum ve maksimum değerini hesaplar.
  • Any(koşul): Koşulu sağlayan en az bir eleman varsa true, yoksa false döner.
  • All(koşul): Tüm elemanlar koşulu sağlıyorsa true döner.

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Sık Sorulan Sorular:
  1. Ertelenmiş yürütmeyi (Deferred Execution) anlık yürütmeye dönüştüren metotlar nelerdir? -> ToList(), ToArray(), Count(), First() vb.
  2. Eşleşen kayıt olmadığında hata vermeden null dönmesi istenen arama işlemi için ne seçilmelidir? -> FirstOrDefault() veya SingleOrDefault() (tek kayıt garantisi varsa).
  3. Single() ile First() arasındaki fark nedir? -> First() eşleşenlerden ilkini alır, arkasında 100 tane daha olsa hata vermez. Single() ise birden fazla eşleşme olursa istisna (exception) fırlatır.

9. Ünite: Entity Framework Core (EF Core)

Ünitenin Amacı: İlişkisel veri tabanları ile nesne yönelimli programlama dünyası arasında köprü görevi gören ORM (Object Relational Mapping) kavramını, Entity Framework Core mimarisini, Code-First yaklaşımı ile veri modelleri, DbContext ve Migration süreçlerini ve temel CRUD (Create, Read, Update, Delete) veritabanı işlemlerini kavramaktır.

9.1. ORM (Object Relational Mapping) Kavramı ve Avantajları

Nesne yönelimli programlamada (OOP) veriler sınıflar (Class) ve nesneler (Object) üzerinden temsil edilirken; ilişkisel veritabanı yönetim sistemlerinde (RDBMS: SQL Server, PostgreSQL, MySQL) veriler tablolar (Table), satırlar (Row) ve sütunlar (Column) halinde saklanır. Bu iki dünya arasındaki yapısal uyumsuzluğa "Nesne-İlişkisel Empedans Uyumsuzluğu" (Object-Relational Impedance Mismatch) denir.

ORM (Nesne İlişkisel Eşleme), bu iki farklı mimari arasında otomatik bir çeviri katmanı kurarak geliştiricinin SQL sorguları yazmak yerine doğrudan C# sınıfları ve metotları ile veritabanı işlemleri yapmasını sağlayan bir yazılım mimarisidir.

ORM'nin Başlıca Faydaları:
  • Geliştirme hızını (produktiviteyi) büyük ölçüde artırır.
  • Tip güvenliği sağlar; derleyici hataları anında yakalar.
  • Parametrik sorgular üreterek SQL Injection (SQL Enjeksiyonu) açıklarını kendiliğinden engeller.
  • Veritabanı bağımsızlığı sağlar; veritabanı SQL Server'dan PostgreSQL'e değiştirildiğinde kodların büyük kısmı aynen çalışır.

9.2. Entity Framework Core (EF Core) Mimarisi

Entity Framework Core, Microsoft'un .NET Core için sıfırdan geliştirdiği, açık kaynaklı, hafif (lightweight), genişletilebilir ve çapraz platform (Windows, Linux, macOS) destekli modern ORM aracıdır.

Projeye dahil edilmesi için gerekli temel NuGet paketleri:

  • Microsoft.EntityFrameworkCore: Çekirdek EF Core motoru.
  • Microsoft.EntityFrameworkCore.SqlServer: SQL Server sağlayıcısı (Provider).
  • Microsoft.EntityFrameworkCore.Tools: Migration ve veritabanı yönetim komutları (Package Manager Console için).

9.3. Code-First Yaklaşımı ve Adımları

EF Core'da en popüler ve modern yaklaşım Code-First (Önce Kod) yaklaşımıdır. Bu yöntemde veritabanı tabloları SQL ile önceden tasarlanmaz; önce C# sınıfları yazılır ve EF Core bu sınıflardan yola çıkarak veritabanını ve tablolarını otomatik oluşturur.

9.4. EF Core ile Temel CRUD İşlemleri

// 1. CREATE (Ekleme)
var yeniUrun = new Product { Name = "Laptop", Price = 25000, CategoryId = 1 };
_context.Products.Add(yeniUrun);
_context.SaveChanges(); // SQL INSERT çalıştırılır.

// 2. READ (Okuma)
var urun = _context.Products.FirstOrDefault(p => p.Id == 1);

// 3. UPDATE (Güncelleme)
if (urun != null)
{
    urun.Price = 27500;
    _context.SaveChanges(); // EF Core Change Tracker değişikliği algılar ve SQL UPDATE çalıştırır.
}

// 4. DELETE (Silme)
if (urun != null)
{
    _context.Products.Remove(urun);
    _context.SaveChanges(); // SQL DELETE çalıştırılır.
}

10. Ünite: Web API (Application Programming Interface)

Ünitenin Amacı: Dağıtık sistemlerin, tek sayfa uygulamalarının (SPA: React, Angular, Vue) ve mobil istemcilerin (Android, iOS) sunucuyla veri alışverişi yapmasını sağlayan Web API mimarisini, SOAP ile REST protokollerinin farklarını, HTTP durum kodlarını, RESTful CRUD işlemlerini ve ASP.NET Core Web API geliştirme standartlarını kavramaktır.

10.1. Web API Kavramı ve Modern Mimarilerdeki Rolü

Geleneksel web uygulamalarında sunucu istemciye HTML, CSS ve JavaScript çıktısı gönderir. Ancak günümüz dünyasında aynı iş mantığına web tarayıcılarının yanı sıra akıllı telefonlar, tabletler, IoT cihazları ve harici kurumsal servisler de erişmek zorundadır. Bu nedenle sunucunun kullanıcı arayüzü (HTML) üretmek yerine yalnızca saf veri (genellikle JSON formatında) sunması ihtiyacı doğmuştur.

Web API (Web Uygulama Programlama Arayüzü), HTTP protokolü üzerinden farklı platformların ve istemcilerin birbiriyle dil ve cihaz bağımsız şekilde iletişim kurmasını sağlayan web servisleridir.

10.2. SOAP vs. REST Mimarisi Karşılaştırması

Kriter SOAP (Simple Object Access Protocol) REST (Representational State Transfer)
Doğası Katı kuralları olan bir protokoldür. HTTP standartlarına dayanan hafif bir mimari stildir.
Veri Formatı Sadece XML formatını destekler. Ağırlıklı olarak JSON, ayrıca XML, metin vb. destekler.
Sözleşme / Tanım WSDL (Web Services Description Language) kullanır. Sözleşme şart değildir; modern standartta OpenAPI / Swagger kullanılır.
Performans & Yük XML etiketleri nedeniyle veri paketi büyüktür, bant genişliğini fazla tüketir. JSON hafif (lightweight) olduğundan çok hızlıdır, mobil uyumludur.
Önbellekleme (Caching) HTTP üzerinden POST ile çalıştığından önbellekleme zordur. HTTP GET istekleri tarayıcı ve ara sunucularda kolayca önbelleğe alınabilir.

10.3. HTTP Metotları ve RESTful CRUD Eşleştirmesi

REST mimarisinde her bir varlık (Resource) benzersiz bir URL (URI) ile tanımlanır ve işlemler HTTP eylemleri ile ifade edilir:

HTTP Metodu CRUD Karşılığı Örnek URI İşlem Açıklaması Idempotent (Özdeş)?
GET Read (Oku) /api/products veya /api/products/5 Verileri listeler veya tek bir kaydı getirir. Sunucuda durum değiştirmez (Safe). Evet
POST Create (Oluştur) /api/products İstek gövdesindeki (Body) verilerle yeni bir kayıt oluşturur. Hayır
PUT Update (Güncelle) /api/products/5 Belirtilen kaydın tüm alanlarını baştan sona günceller/üzerine yazar. Evet
PATCH Partial Update (Kısmi Güncelle) /api/products/5 Kaydın yalnızca gönderilen belirli alanlarını (örn: sadece fiyat) günceller. Hayır
DELETE Delete (Sil) /api/products/5 Belirtilen kaydı sistemden siler. Evet

10.4. HTTP Durum Kodları (Status Codes)

İstemciye dönen yanıtta işlemin sonucu standart HTTP durum kodları ile bildirilir:

  • 2xx Başarılı Kodlar:
    • 200 OK: İstek başarıyla işlendi ve yanıt gövdesinde veri döndü.
    • 201 Created: Yeni bir kaynak başarıyla oluşturuldu (Genellikle POST sonucunda döner ve Location başlığı barındırır).
    • 204 No Content: İstek başarılı oldu ancak dönecek bir gövde yok (Genellikle DELETE veya PUT sonucunda döner).
  • 4xx İstemci Hata Kodları:
    • 400 Bad Request: İstek formatı veya model doğrulaması geçersiz (Eksik/hatalı veri).
    • 401 Unauthorized: Kimlik doğrulama başarısız (Giriş yapılmamış veya token geçersiz).
    • 403 Forbidden: Kimlik doğrulanmış ancak kullanıcının bu kaynağa erişim yetkisi yok.
    • 404 Not Found: İstenen URI veya kaynak sunucuda bulunamadı.
  • 5xx Sunucu Hata Kodları:
    • 500 Internal Server Error: Sunucuda beklenmeyen bir yazılımsal istisna (Unhandled Exception) meydana geldi.
    • 503 Service Unavailable: Sunucu aşırı yük veya bakım nedeniyle geçici olarak hizmet veremiyor.

10.5. ASP.NET Core ile Web API Controller Geliştirme

Web API Controller sınıfları, klasik MVC Controller'larından farklı olarak Controller yerine ControllerBase sınıfından türetilir (çünkü View desteğine ihtiyaç duymazlar) ve sınıfın üstüne [ApiController] özniteliği eklenir:

[Route("api/[controller]")]
[ApiController]
public class ProductsController : ControllerBase
{
    private readonly AppDbContext _context;

    public ProductsController(AppDbContext context)
    {
        _context = context;
    }

    // GET: api/Products
    [HttpGet]
    public async Task<ActionResult<IEnumerable<Product>>> GetProducts()
    {
        return await _context.Products.ToListAsync();
    }

    // GET: api/Products/5
    [HttpGet("{id}")]
    public async Task<ActionResult<Product>> GetProduct(int id)
    {
        var product = await _context.Products.FindAsync(id);
        if (product == null)
            return NotFound(); // 404 döner

        return Ok(product); // 200 döner
    }

    // POST: api/Products
    [HttpPost]
    public async Task<ActionResult<Product>> PostProduct(Product product)
    {
        _context.Products.Add(product);
        await _context.SaveChangesAsync();

        // 201 Created döner ve oluşturulan nesnenin adresini header'a ekler:
        return CreatedAtAction(nameof(GetProduct), new { id = product.Id }, product);
    }

    // DELETE: api/Products/5
    [HttpDelete("{id}")]
    public async Task<IActionResult> DeleteProduct(int id)
    {
        var product = await _context.Products.FindAsync(id);
        if (product == null)
            return NotFound();

        _context.Products.Remove(product);
        await _context.SaveChangesAsync();

        return NoContent(); // 204 döner
    }
}

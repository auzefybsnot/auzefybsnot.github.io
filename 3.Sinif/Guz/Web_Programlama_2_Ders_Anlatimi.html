1. İnternet ve web aynı şey değil

Günlük dilde ikisini aynı anlamda kullanırız ama kitap ayrım yapar. İnternet yoldur, web o yolda taşınan içeriklerden biridir.

Kelimesi kelimesine İnternet: Dünya çapında birbirine bağlı cihazların oluşturduğu küresel bir ağ sistemi. Görevi basittir: veriyi bir yerden başka bir yere taşımak. Web (World Wide Web, www): İnternet üzerinden erişilen metin sayfaları, dijital fotoğraflar, müzik, video, animasyon gibi bilgi topluluğu. Bu bilgiyle iletişim HTTP protokolü ile, genelde web tarayıcıları üzerinden kurulur. Protokol: Makinelerin ve programların bilgi alışverişine izin veren, mesaj biçimleri ve prosedürler için kurallar kümesi. Alıcının mesajı anlaması için iletişimdeki her makine bu kurallara uymalıdır.
Günlük hayattan İnternet bir karayolu ağı, web ise o yollarda dolaşan kargo paketleri gibidir. Aynı yollarda e-posta (SMTP), dosya aktarımı (FTP) gibi başka "araçlar" da dolaşır. Web sayfası istediğinde kullanılan "araç" HTTP'dir.

3. Web framework (web çerçevesi)

Kelimesi kelimesine Web çerçeveleri: Yazılım ve web geliştiricileri için hazır olan bir dizi kaynak ve araç. Çok çeşitli önceden yazılmış bileşenler, kod parçacıkları ve uygulama şablonları sunar.

Bu bileşenleri sıfırdan yeniden yazmak mümkündür ama zahmetli ve zaman alıcıdır. Kitabın saydığı özellikler:

  • Çoğu açık kaynaklı ve ücretsizdir; uygulamaları kolay ve hızlı oluşturur.
  • Geliştiriciyi tekrarlayan koddan kurtarır, daha verimli çalıştırır.
  • Gelişmiş güvenlik özellikleriyle gelir; sorun bulununca yama yayımlanır.
  • Çeşitli veri tabanlarına kolay bağlanmayı sağlayan entegrasyon özelliği vardır.
"Hangisi yanlıştır?" tuzağı "Web frameworkler olmadan web programlama gerçekleştirilemez" → YANLIŞ. Framework işi hızlandırır ve standartlaştırır; zorunlu değildir.

4. Ön yüz (front-end) ve arka yüz (back-end)

Bir web uygulamasının iki yüzü vardır. İkisi birbiriyle sürekli konuşur:

HTML
HyperText Markup Language (Köprü Metni İşaretleme Dili). Sayfanın iskeletini kurar. Köprü metni sayfalar arası bağlantıyı, işaretleme dili sayfa yapısını tanımlar.
CSS
Cascading Style Sheets (Basamaklı Stil Şablonu). Görünen bileşenleri şekillendirir, renklendirir, boyutlandırır, konumlandırır. Dosya uzantısı .css.
JavaScript
Sayfaya dinamiklik kazandıran, tarayıcıyı kontrol eden, sunucuyla asenkron konuşabilen betik dil.

Ön yüz çerçeveleri: Bootstrap ve SemanticUI görsel tasarıma odaklanır; Vue, React, Angular veri akışını yönetir; jQuery, Ember.js, Backbone.js da kullanılır.

5. .NET Framework → .NET Core → .NET 5

Kelimesi kelimesine .NET Framework: Microsoft'un yazılım geliştirme platformu. Masaüstü, web, web servisi ve mobil uygulamalar tek çatı altında. Dil bağımsızlığı ve birlikte çalışabilirlik sağlar (VB.NET, C# dahil 25'ten fazla dil). Bu platformla geliştirilen uygulamalar Windows üzerinde çalışır. İlk sürüm Şubat 2002, son sürüm 4.8 (2019). .NET Core: Microsoft'un ücretsiz, açık kaynaklı ve platform bağımsız (Windows, macOS, Linux) yeni sürümü. Mobil, masaüstü, web, bulut, IoT, makine öğrenimi, mikro hizmet, oyun… C#, F#, Visual Basic destekler. İlk sürüm .NET Core 1.0 (Haziran 2016). .NET 5 (Kasım 2020): Core 3.1'den sonra, .NET Framework sürümleriyle karışmasın diye "4" atlanıp adı .NET 5 oldu. Tek temel sınıf kütüphanesiyle tüm .NET uygulamalarını birleştiren platform.

Namespace (isim alanı): Benzer amaçlı sınıfların mantıksal olarak bir arada tanımlanmasıdır (Java'daki package karşılığı). Koda using ile eklenir. Örneğin System temel veri türlerini (Byte, Char, Int32, String…), System.IO dosya/dizin sınıflarını içerir.

using System;

.NET Core sürümleri sırasıyla: 1.0, 1.1, 2.0, 2.1, 2.2, 3.0, 3.1 → .NET 5. ".NET Core 4.1" diye bir sürüm yoktur (kitabın bölüm sorusu).

6. ASP.NET Core

ASP.NET, 2002'de .NET Framework'ün parçası olarak yayımlandı. Öncesinde Windows'ta çalışan ASP (Active Server Page) adlı dinamik betik dil vardı. ASP.NET Framework altında Web Forms, ASP.NET MVC, Web API, SignalR seçenekleri vardı. ASP.NET Core'da ise MVC ve API modelleri birleşik sunulur; gRPC ve SignalR devam eder; Web Forms yoktur, yerine Blazor ve Razor Pages gelmiştir.

MVC Yapısı ve ASP.NET Core ile MVC Kullanımı

Dersin iskeleti bu ünite. Visual Studio kurulumu, yeni ASP.NET Core MVC projesi, proje klasörleri (wwwroot, Program.cs, Startup.cs…), Model–View–Controller bileşenlerinin sorumlulukları, routing (yönlendirme), MVC yaşam döngüsü ve Controller, View, Model'in ASP.NET Core'da nasıl oluşturulduğu.

Önce şunu oturtalım Sınavda bu üniteden gelen soruların çoğu bir URL verip "hangi Controller, hangi Action?" diye sorar. Kural tek:
http://localhost:PORT/Controller/Action/id
1) URL'de "Controller" son eki yazılmaz; sınıfın adı ise mutlaka …Controller ile biter: /Ogrenci → OgrenciController.
2) Action yazılmamışsa Index, controller da yazılmamışsa Home çalışır: {controller=Home}/{action=Index}/{id?}.
3) Action = Controller'ın public metodu.
4) Arayüz = View (.cshtml) · Veri ve iş mantığı = Model (.cs) · İsteği karşılayan = Controller (.cs).

1. Araçlar ve kurulum

  • Visual Studio: GUI, web, konsol, mobil, bulut uygulamaları geliştirmek için Entegre Geliştirme Ortamı (IDE). Visual Studio Code ise ondan daha hafif, gelişmiş özellikleri olmayan bir alternatiftir.
  • Visual Studio Community: Microsoft'un öğrenme (ticari olmayan) amaçlı ücretsiz sürümü. Professional ve Enterprise ücretlidir.
  • Kurulumda iş yükleri seçilir; veri tabanı işlemleri için bağımsız bileşenlerden SQL Server Express 2016 LocalDB seçili olmalıdır.
  • Visual Studio'da Razor Pages, MVC ve Web API gibi birçok ASP.NET Core şablonu vardır; kitap MVC kullanır.

Yeni proje oluşturma

  1. Yeni proje oluştur (veya File > New > Project) → ASP.NET Core Web Application.
  2. Project Name, Location (nereye kaydedileceği) ve Solution (projeler arası ilişkiler) belirlenir.
  3. Şablon olarak Model-View-Controller seçilir, Create ile proje oluşur.
  4. Çalıştırmak için F5 ya da araç çubuğunda IIS Express'in yanındaki yeşil ok.
Kelimesi kelimesine IIS (Internet Information Services): Microsoft'un Windows'ta çalışan web sunucusu. IIS Express onun geliştiriciler için hafif, bağımsız sürümüdür. Proje çalıştırıldığında IIS Express varsayılan olarak rastgele bir port numarası seçer. İstenirse Project > Properties > Debug kısmından değiştirilir. 4. Routing (yönlendirme)

ASP.NET Core MVC'nin güçlü bir URL eşleme bileşeni vardır: sunucudaki dosyaların düzeninden bağımsız, anlaşılır ve SEO için uygun URL'ler tanımlanır. Gelen HTTP isteklerini eşleştirmekten ve uygulamanın yürütülebilir uç noktalarına göndermekten sorumludur. Routing Startup.cs'te yapılandırılır:

routes.MapRoute(name: "Default",
    template: "{controller=Home}/{action=Index}/{id?}");

Anlamı: URL'de controller yoksa Home, action yoksa Index kullanılır; id? soru işareti yüzünden boş olabilir. Buna kural tabanlı yönlendirme denir.

  1. Solution Explorer'da Controllers klasörüne sağ tık → Add > Controller.
  2. Add New Scaffolded Item penceresinde MVC Controller – Empty.
  3. İsim "Controller" son ekiyle biter: OgrenciController. Dosya OgrenciController.cs olur (.cs = C# sınıfı).

public class OgrenciController : Controller
{
    public string Index(int id)
    {
        return "Merhaba Öğrenciler ID=" + id;

public class OgrenciController : Controller
{
    public ActionResult Bilgi()
    {
        return View();   // Views/Ogrenci/Bilgi.cshtml aranır
    }
}
  1. Views'a sağ tık → Ogrenci adında klasör.
  2. Ogrenci klasörüne sağ tık → Add > View → Razor View – Empty → Bilgi.cshtml.
  3. İçine <b>Öğrenci Bilgileri</b> yaz; /Ogrenci/Bilgi çağrılınca görünür.

View adı yerine dosya yolu verilecekse uzantı yazılır: return View("Views/Home/About.cshtml");

Layout Kavramı ve Razor View Engine

Sitenin her sayfasında tekrar eden iskeleti tek yerde toplayan Layout, hangi sayfanın hangi layout'u kullanacağını söyleyen _ViewStart.cshtml, View içinde C# yazmamızı sağlayan Razor görünüm motoru, @ söz dizimi, yorum satırları, koşullu ifadeler (if, else if, switch) ve döngüler (for, foreach, while, do-while).

Önce şunu oturtalım Bu ünitenin soruları iki tiptir: dosya/klasör adı ve "bu Razor kodu ekrana ne basar?"
1) Layout: Views/Shared/_Layout.cshtml (alt çizgili, .cshtml).
2) Tüm view'lere layout atamak: _ViewStart.cshtml → @{ Layout = "_Layout"; }. View içeriği layout'ta @RenderBody()'nin yerine oturur.
3) Varsayılan view engine Razor; .cshtml içindeki dil C#.
4) HTML → C# geçişi @; çok satırlı kod @{ … }; Razor yorumu @* … *@; C# içinden HTML'e @:
5) Çıktı sorularında Razor yalnızca @'den sonra gelen ifadeyi hesaplar, gerisini düz metin basar.

1. Layout kavramı

Çoğu web uygulamasında sayfadan sayfaya geçerken aynı kalan bölümler vardır: üst bilgi (header), sol menü, alt bilgi (footer). Bunları her sayfaya tekrar yazmak yerine bir şablona koyarız.

Kelimesi kelimesine Layout (düzen–şablon görünümü): Tekrarlanan kodlamayı ortadan kaldıran, kolay bakımla geliştirme hızını artıran; uygulamanın birden çok sayfasında tutarlı ve ortak bir site görünümü tanımlayan yapı. Diğer view'ler gibi .cshtml uzantılıdır. Tüm view'lerle paylaşıldığı için Views klasörü altındaki Shared klasöründe durur. Proje oluşturulunca varsayılan adı _Layout.cshtml'dir.

Varsayılan _Layout.cshtml içinde tüm proje için Bootstrap ve jQuery kütüphaneleri dahil edilmiştir (dosyalar wwwroot'tadır), <nav> ile üst menü, <footer> ile telif bilgisi vardır. Kalbi ise şu satırdır:

@RenderBody()

Bir Controller'daki action bir View çağırdığında, View'in ürettiği HTML layout'taki RenderBody() alanına yerleşir.

Hangi view hangi layout'u kullanır?

Ortak bir _ViewStart.cshtml dosyasında (tüm view'ler için) ya da her view'in içinde şu kodla belirtilir:

@{
    Layout = "_Layout";
}
Kitabın kendi şablon örneği Shared klasörüne _LayoutDeneme.cshtml adında boş bir view eklenir; içine header, sol menü, içerik ve footer'dan oluşan bir tablo yazılır, içerik hücresine @RenderBody() konur: 
<!DOCTYPE html>
<html>
<head>
    <meta name="viewport" content="width=device-width" />
    <title>@ViewBag.Title</title>
</head>
<body>
  <table border="1" style="width:1024px; height:768px;">
    <tr><td colspan="2"><h3>Header Bölümü</h3></td></tr>
    <tr>
      <td style="width:150px"><h3>Sol Menü</h3></td>
      <td style="width:600px">@RenderBody()</td>
    </tr>
    <tr><td colspan="2"><h3>Footer Bölümü</h3></td></tr>
  </table>
</body>
</html>
Sonra _ViewStart.cshtml'de @{ Layout = "_LayoutDeneme"; } yazılır; proje artık bu şablonla çalışır.
Tuzaklar • Layout dosyasında kesin olarak bulunmayan: Model sınıfı tanımları. HTML, menü, CSS/JS referansları bulunur.
• "Tüm view'lerde layout ayarı" → _ViewStart.cshtml (Layout.cshtml, Index.cshtml, Default.cshtml değil).
• Klasör: View/Shared (Model/Shared, Controller/Shared, View/Default çeldiricidir).
• Varsayılan ad _Layout.cshtml; alt çizgisiz "Layout.cshtml" ya da ".cs" uzantılı şıklar yanlıştır.

2. Razor View Engine (görünüm motoru)

View'lerin HTML göstermesi gerekir, ama bazen içine programlama dili kodu da yazmak isteriz (bir değişkeni basmak, bir döngüyle liste üretmek). View engine, bu kodları HTML'e dönüştürür; Controller'daki bir action tarafından çağrıldığında HTML yanıtı üretmekten sorumludur.

Kelimesi kelimesine Razor View Engine, ASP.NET Core uygulamaları için varsayılan View Engine'dir. .NET Framework'teki Aspx, Spark gibi motorlar ASP.NET Core'da tamamen yerini Razor'a bırakmıştır. Razor, görünüm dosyalarında Razor işaretlemesini arar, bunları parse ederek HTML yanıtını üretir. Razor dosyaları genellikle .cshtml uzantılıdır ve içinde C# kullanılır.
HTML + C# kodu (.cshtml)→Razor View Engine→Saf HTML→Tarayıcı

Form İşlemleri ve Model Bağlama

Kullanıcıdan veri almanın ana yolu olan HTML formları, form elemanları (input tipleri, select, textarea), GET ile POST farkı, action ve method öz niteliklerinin varsayılanları, gönderilen veriyi Controller'da Request.Form / Request.Query ile almak ve bunu otomatikleştiren model bağlama (model binding).

Önce şunu oturtalım Bu ünite sınavda en çok soru getiren ünitelerden biri. Şu tabloyu ezberlersen çoğu soru bedava:
1) Formu gönderen: <input type="submit"> · tekli seçim radio · çoklu seçim checkbox · gizli veri hidden · type yazılmazsa text
2) method yazılmazsa → GET · action yazılmazsa → formun bulunduğu sayfaya
3) URL'de ?ad=deger görüyorsan → GET (query string) · veri gövdede, URL temiz → POST
4) GET verisi: HttpContext.Request.Query["name"] · POST verisi: HttpContext.Request.Form["name"]
5) POST'u karşılayan action'ın üstüne [HttpPost] yazılır.
6) Model bağlama: form elemanının name'i ile modelin özellik adı aynı olmalı (büyük/küçük harf önemsiz).

1. Form nedir?

Web formları, kullanıcı ile web sitesi arasındaki ana etkileşim noktalarından biridir: kayıt, login, güncelleme, yorum, ödeme… Kullanıcıdan alınan veriler işlenmek ve depolanmak üzere web sunucusuna gönderilir. Bu iş HTTP istek-yanıt paradigmasına dayanır. Form kontrolleri istenen formatta veri girişi için programlanabilir (form doğrulama) ve görme engelliler için açıklayıcı etiketlerle eşleştirilebilir.

Form, <form> ve </form> etiketleri arasına form elemanları yerleştirilerek oluşturulur.

Ünite 5

Durum Yönetimi ve View'e Veri Aktarımı

HTTP'nin durumsuz (stateless) olması yüzünden kullanıcıyı sayfadan sayfaya "hatırlama" ihtiyacı. İstemci taraflı teknikler (query string, hidden field, cookie) ve sunucu taraflı teknik (session). Ardından Controller'dan View'e veri taşımanın dört yolu: ViewBag, ViewData, TempData ve model (@model).

Önce şunu oturtalım 1) HTTP durumsuzdur: her istek öncekilerden habersiz, sanki ilk kezmiş gibi işlenir.
2) İstemcide tutulan: Cookie, Hidden field, Query string → görülebilir, değiştirilebilir, hassas veri konmaz.
3) Sunucuda tutulan: Session → daha güvenli; kullanıcı adı, yetki gibi bilgiler burada.
4) Cookie: renk, tema, dil gibi tercihler. Yazma Response.Cookies.Append(ad, değer), okuma Request.Cookies[ad].
5) Session: HttpContext.Session.SetString(ad, değer) · ayar Startup.cs: AddSession() + UseSession().
6) İkisi için namespace: Microsoft.AspNetCore.Http.
7) @ViewBag.Ad (nokta) · @ViewData["Ad"] (anahtar) · @Model.Ozellik (büyük M).

1. Durumsuz protokol ve durum yönetimi

Kelimesi kelimesine Durumsuz (stateless) protokol: Her istek, kendisinden önce yürütülen istekler hakkında hiçbir bilgi olmadan bağımsız yürütülür. Örnek: HTTP, UDP, DNS. Durum bilgili (stateful) protokol: Örnek: FTP, TCP, SMTP. Durum (state): Uygulamanın kullanıcı hakkında bildikleri (kim, uygulamada nerede, tercihleri neler) ve kullanıcının uygulamayla mevcut etkileşimi. Durum yönetimi (state management): Kullanıcıya özgü verinin sayfalar arasında iletilmesi ihtiyacı.

Durumsuzluk, istemci-sunucu arasında taşınan veri miktarını azaltır ve sözleşmeyi basitleştirir. Ama sunucu, aynı kullanıcı ikinci sayfayı istediğinde onun kim olduğunu bilmez. Bu yüzden birtakım teknikler gerekir:

2. İstemci taraflı durum yönetimi

Bilgi istemcinin makinesinde ya da sayfanın kendisinde saklanır; sunucu kaynağı kullanılmaz. Ama veri istemcide olduğu için manipüle edilebilir; önemli verileri burada tutmak tercih edilmez.

Query String
URL'nin sonuna eklenen dize; veri taşımanın en basit yolu. & ile birden çok değer. Adres çubuğunda görülüp düzenlenebildiği için güvenli değildir; URL'de karakter sınırı vardır.
Hidden Field
<input type="hidden"> ile gönderilen veriler; bir sonraki istekte geri gönderilir. Çok sayfalı formlarda yaygın. Sayfa kaynağında görülür, Postman ile değiştirilebilir; bu yüzden sunucuda yeniden doğrulanmalıdır.
Cookie (çerez)
Sunucunun tarayıcıya gönderdiği küçük veri parçaları; istemcide metin dosyası olarak saklanır. Her istekte sunucuya gittiği için küçük tutulmalı; çoğu tarayıcı 4096 bayt ile sınırlar. Kişiselleştirme ve arka plan rengi gibi tercihler için kullanılır.
Cookie'nin dezavantajları → hangi veri konmaz? Kullanıcı çerezleri devre dışı bırakabilir, silebilir, değiştirebilir. Bilgisayara erişen herkes görebilir. Bu yüzden şifre, yetki, veri tabanı / sunucu bilgileri çereze konmaz; renk, tema, dil, listeleme sayısı konabilir.

ASP.NET Core'da cookie

using Microsoft.AspNetCore.Http;

// yaz (sunucu → tarayıcı)
HttpContext.Response.Cookies.Append("CookieName", "value");

// oku (tarayıcının gönderdiği istekten)
var name = HttpContext.Request.Cookies["CookieName"];

// ömür ve etki alanı: 3. parametre CookieOptions
var cookieOpt = new CookieOptions
{
    Expires = DateTime.Now.AddMinutes(10),
    Domain = ".test.com"
};
HttpContext.Response.Cookies.Append("CookieName", item.UserColor, cookieOpt);

Son örnek, 10 dakika sonra kendini yok eden, test.com etki alanında geçerli bir çerez oluşturur. CookieOptions'ta Secure, Path gibi başka özellikler de vardır.

Response mu Request mi? Append mi Add mi? Çerez oluşturmak = cevapla tarayıcıya göndermek → Response.Cookies.Append. Çerez okumak = gelen istekten almak → Request.Cookies["ad"]. Request.Cookies.Append, Response.Cookies.Add, Request.Query(...) şıkları yanlıştır.

3. Sunucu taraflı durum yönetimi: Session

Veriler sunucuda saklandığı için daha güvenlidir; her istekte sunucuya gönderilmesi gerekmediği için performansı da daha iyidir.

Kelimesi kelimesine Web oturumu: Kullanıcının ilk sayfaya gelip siteden ayrıldığı ana kadar geçen süre. Her kullanıcıya ilk ziyarette benzersiz bir oturum kimliği (Session ID) atanır. Aynı makinede farklı tarayıcılar ayrı oturum sayılır; oturumlar tarayıcılar arasında paylaşılmaz. Session değişkenleri, web sunucusunun o kullanıcı için tuttuğu bellek değişkenleri gibidir (sunucudaki bir klasör, prosesin hafızası ya da veri tabanı). Sitenin kullanıcı hakkında "kısa süreli belleği"dir: kullanıcı adı, yetki seviyesi vb. Session ID, istemciye çerez olarak, sunucunun bildiği bir anahtarla şifrelenerek gönderilir. Varsayılan zaman aşımı 20 dakika.

Session'ı etkinleştirme (kitabın adımları)

  2. Startup.cs → ConfigureServices metoduna services.AddSession();

  4. Controller'a using Microsoft.AspNetCore.Http;

public class User
{

    public string UserPass { get; set; }
    public string UserColor { get; set; }
}

public IActionResult Login(User usr)
{
    foreach (var item in Users)
    {
        if (item.UserName == usr.UserName && item.UserPass == usr.UserPass)
        {
            HttpContext.Session.SetString("SessionUser", item.UserName);
            var cookieOptions = new CookieOptions
            {
                Expires = DateTime.Now.AddSeconds(150)
            };
            HttpContext.Response.Cookies.Append("UsrColor", item.UserColor, cookieOptions);
            return View("Giris");
        }
    }
    ViewBag.msj = "Hatalı Kullanıcı";
    return View("Index");
}

public IActionResult Icerik()
{
    if (HttpContext.Session.GetString("SessionUser") is null)
        return View("Index");     // login değilse geri gönder
    return View();
}

Etiket Yardımcıları (Tag Helper)

Razor dosyalarında HTML elemanlarını sunucu tarafında üreten, modele bağlanabilen asp-* nitelikli etiketler. Avantajları, @addTagHelper / _ViewImports, Anchor, Form, Input, Label, Textarea, Select tag helper'ları, .NET türü → input tipi eşleşmesi, CSRF koruması ve hazır view şablonları (Scaffolding: Create, Edit, Delete, Details, List, Empty).

Önce şunu oturtalım 1) Tag helper'lar normal HTML gibi yazılır, başına @ konmaz; niteliklerin önünde asp- vardır.
2) Link: <a asp-controller="Haber" asp-action="HbrOku">
3) Modele bağlamak: asp-for (input, label, textarea, select) · hata mesajı: asp-validation-for (span)
4) Form tag helper varsayılan metodu POST; CSRF için asp-antiforgery → hidden bir __RequestVerificationToken üretir.
5) bool → checkbox · string → text · DateTime → datetime-local · byte/int/double → number
6) Etiket metnini değiştirmek: [Display(Name = "...")] · Tüm view'lerde etkinleştirme: _ViewImports.cshtml
7) Şablonlar: yeni kayıt formu Create · düzenleme Edit · silme Delete · ayrıntı Details · liste List · boş Empty

1. Tag helper nedir?

Kelimesi kelimesine Tag Helper (Etiket Yardımcısı): ASP.NET Core ile gelen, MVC Razor motorunda HTML elemanı oluşturmayı kolaylaştıran sunucu taraflı bileşenler. Razor dosyalarında HTML ögeleri oluşturur ve işler. Gramer olarak HTML etiketine benzer ama C# yardımıyla oluşturulur. asp-* ön eki, etiketin tag helper kullandığını bildirir. Eski HTML Helper'ların (@Html.TextBoxFor(...), hâlâ kullanılabilir) daha akıcı söz dizimli mantıksal halefidir.
Aynı iş, iki yol

@ ile C#'a geçilirStandart HTML gibi görünür, @ gerekmez

Yerleşik tag helper'lar kullanılmadan önce @addTagHelper yönergesiyle tanıtılmalıdır: tek bir view'de ya da tüm view'ler için _ViewImports.cshtml dosyasında.

@addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers

2. Anchor (bağlantı) tag helper

Standart <a> etiketini genişletir. Nitelikler asp- ile başlar:

asp-controller
URL'yi oluşturacak controller adı. Yazılmazsa view'i oluşturan controller kullanılır.
asp-action
Action metot adı. Yazılmazsa varsayılan action çalışır.
asp-route
URL için kullanılacak yolun (route) adı.
<a asp-controller="Ogrenci" asp-action="Kaydet" class="orn_class">Tıkla</a>
<!-- üretilen HTML -->
<a href="/Ogrenci/Kaydet" class="orn_class">Tıkla</a>
Ters yazma tuzağı <a href="/Haber/HbrOku"> → asp-controller="Haber" asp-action="HbrOku". Niteliklerin sırası önemli değildir, değerlerin hangi niteliğe yazıldığı önemlidir. asp-controller="HbrOku" asp-action="Haber" yanlıştır; linkte asp-for kullanılmaz.

3. Form tag helper

<form asp-action="Kaydet" asp-controller="Ogrenci">
   …
</form>

<form action="/Ogrenci/Kaydet" method="post">

</form>

Model Doğrulama (Model Validation)

Kullanıcıdan gelen veriye neden güvenmeyiz, istemci taraflı ve sunucu taraflı doğrulama farkı, doğrulama öznitelikleri (Required, Range, EmailAddress, Compare, StringLength…), hata mesajlarını gösteren asp-validation-for, jQuery doğrulama kütüphaneleri, ModelState.IsValid ve kitabın baştan sona öğrenci kayıt uygulaması.

Önce şunu oturtalım 1) Tüm kullanıcı girdileri güvenilmez kabul edilir → doğrulama hem istemci hem sunucu tarafında yapılmalı.
2) İstemci taraflı: tag helper'lar + jQuery (jquery.validate, unobtrusive). Hızlı ama atlatılabilir.
3) Sunucu taraflı: if (ModelState.IsValid).
4) Hata mesajı: <span asp-validation-for="Alan">.
5) Öznitelikler System.ComponentModel.DataAnnotations'ta; hepsi köşeli parantezle özelliğin hemen üstüne yazılır: [Required], [Range(1, 6)], [EmailAddress], [CreditCard], [Compare("Sifre")], [MinLength(10)]…
6) Mesaj: ErrorMessage = "…".

1. Veri doğrulama neden gerekli?

Kelimesi kelimesine Veri doğrulama: Kullanıcıdan gelen değerlerin beklenen veri türünde, izin verilen aralıkta olduğundan ve gerekli tüm verilerin mevcut olduğundan emin olmak. Genel yaklaşım: tüm kullanıcı girdileri güvenilmezdir. Kasıtlı açık arayanlar da, yanlışlıkla hatalı veri girenler de vardır. Veri işlenmeden önce kontrol edilmelidir.

Kontrolün iki kısmı vardır: (1) verinin istenen kısıtlamalar içinde olup olmadığını denetlemek (veri bütünlüğünü korumanın en önemli yolu), (2) hata varsa geri bildirimle kullanıcının sorunu fark edip düzeltmesine yardım etmek.

2. Model doğrulama

Kelimesi kelimesine Model doğrulama: Uygulama tarafından alınan verilerin modele bağlanmaya uygun olmasını sağlama süreci. Sıra: önce model bağlama (HTTP isteğindeki değerler action parametresine eşlenir), ardından model doğrulama yapılır. Uymayan değerler için hata mekanizması kullanıcıyı uyarır.

3. İstemci taraflı model doğrulama

ASP.NET Core istemci doğrulamasını kolaylaştıran kütüphane içerir. Şu üç kütüphane bu sırayla projeye dahil edilmelidir: jQuery → jquery.validate → jquery.validate.unobtrusive.

  • jQuery, Views/Shared/_Layout.cshtml'de zaten eklidir: <script src="~/lib/jquery/dist/jquery.min.js"></script>
  • Diğer ikisi Views/Shared/_ValidationScriptsPartial.cshtml içindedir. Tercih edilen yaklaşım, bu dosyayı doğrulama yapılacak view'e eklemektir.
<label asp-for="KullaniciAdi" class="control-label"></label>
<input asp-for="KullaniciAdi" class="form-control" />
<span asp-validation-for="KullaniciAdi" class="text-danger"></span>

@section Scripts {
    @{await Html.RenderPartialAsync("_ValidationScriptsPartial");}
}

Hata mesajını gösterecek tag helper (<span> vb.) modele asp-validation-for ile bağlanır ve genelde ilgili input'un hemen arkasına yazılır. Html.RenderPartialAsync, _ValidationScriptsPartial'ı partial view (bir view'in başka bir view içinde kullanılması) olarak ekler. Formun en üstündeki <div asp-validation-summary="ModelOnly"> ise özet hata alanıdır.

4. Sunucu taraflı model doğrulama

Model bağlayıcı, bağlama ve doğrulama sonucuyla ModelState nesnesini günceller. ModelState, model bağlama ve model doğrulama alt sistemlerinden gelen hataları temsil eder; her özellik için değerleri ve hataları izler. Doğrulama başarısız olursa model bağlayıcı hata fırlatmaz; ModelState'i hata listesiyle günceller ve action çağrılmadan önce IsValid'i false yapar.

if (ModelState.IsValid)
{
    // Model geçerli. İstenen işlem gerçekleştirilebilir
}
else
{
    // Doğrulama başarısız. Kullanıcıya hata mesajı verdirilmeli
}

public class OgrenciController : Controller

LINQ – Language Integrated Query (Dile Entegre Sorgu)

Farklı veri kaynaklarını (koleksiyonlar, SQL, XML…) aynı söz dizimiyle sorgulamayı sağlayan LINQ. Avantajları, sorgunun üç adımı, lambda (=>), ertelenmiş ve anlık yürütme, Query syntax ile Method syntax ve sık kullanılan operatörler: Where, OrderBy, GroupBy, Select, Contains, Any, All, Count, Max, Min, Sum, Average, First, FirstOrDefault.

Önce şunu oturtalım Bu üniteden gelen soruların neredeyse hepsi "bu kod ne döndürür?" sorusudur. Her metodun ne tür değer döndürdüğünü bil:
1) Any / All / Contains → true/false (sayı değil!). Any = en az biri, All = hepsi.
2) Count, Max, Min, Sum, Average → sayı. Parametresiz Count = toplam eleman.
3) First → ilk eşleşen; bulamazsa hata fırlatır. FirstOrDefault → bulamazsa varsayılan değer (int için 0, nesne için null).
4) && = VE (ikisi de), || = VEYA (biri yeter). Sınav bunu tuzak olarak kullanıyor.
5) from … where … select = Query syntax · .Where(x => …) = Method syntax.
6) LINQ = Language Integrated Query; namespace System.Linq.

1. LINQ nedir, neden var?

Sorgu, bir veri kaynağından veri talep eden ifadedir. Her kaynağın kendi sorgu dili vardır: ilişkisel veri tabanı için SQL, XML için XQuery… Her kaynak için yeni dil öğrenmek zahmetlidir; geleneksel sorgular tür denetimi ve IntelliSense olmadan, düz string olarak yazılır.

Kelimesi kelimesine LINQ (Language-Integrated Query, Dile Entegre Sorgu): Sorgu yeteneklerinin doğrudan C# diline entegrasyonuna dayanan bir dizi teknolojinin adı. Çeşitli veri kaynakları ve biçimleri arasında verilerle çalışmak için tutarlı bir model sunar. SQL veri tabanları, ADO.NET DataSet'ler, XML dokümanları ve IEnumerable / IEnumerable<T> destekleyen .NET koleksiyonları üzerinde aynı sorgu ifadesi kalıpları kullanılabilir.

2. Bir LINQ sorgusunun üç adımı

LINQ kullanmak için using System.Linq; eklenir. Her sorgu üç eylemden oluşur: veri kaynağına erişim → sorgu ifadesini oluşturma → sorguyu işletme.

    from sayi in sayilar

// 3. Sorgunun işletilmesi
foreach (int deger in SayiQuery)

1. ORM (Object Relational Mapping)

Veri tabanı, verilerin elektronik olarak depolandığı, gelişmiş sorgular yapılabilen yapılandırılmış bilgi topluluğudur; genelde bir DBMS (veri tabanı yönetim sistemi) ile kontrol edilir. 5. Kitaplık uygulaması (Code-First)

Yazarlar ve kitapları için Yazarlar ve Kitaplar tablolarını Code-First ile oluşturan bir MVC projesi. İlişki: bir yazarın birden çok kitabı olabilir; Kitaplar'daki YazarID foreign key'dir.

Adım 1 — Veri modeli

public class Kitap
{
    [Key]  // yazılmasa da KitapID'de "ID" olduğu için primary key olurdu
    public int KitapID { get; set; }

    [Required]
    [MaxLength(100)]
    [Display(Name = "Kitap Adı")]
    public string KtapAdi { get; set; }

    public int YazarID { get; set; }   // Yazar'daki PK ile aynı ad ve tip → foreign key
    public Yazar Yazar { get; set; }   // reference navigation property
}

public class Yazar
{
    public int YazarID { get; set; }

    [Required, MaxLength(100), Display(Name = "Yazar Ad")]
    public string YazarAd { get; set; }

    [Required, MaxLength(100), Display(Name = "Yazar Soyad")]
    public string YazarSoyad { get; set; }

    public ICollection<Kitap> Kitaplar { get; set; }  // collection navigation property
}

Navigation property (gezinme özelliği): Varlıklar arası ilişkiyi tanımlayan, veri tabanında karşılığı olan bir türe eşlenemeyen özellik (Kitap'taki Yazar, Yazar'daki Kitaplar). Koleksiyon gezinme özelliğine sahip olan asıl varlık (Yazar), başvuru gezinme özelliğine sahip olan bağımlı varlıktır (Kitap).

Adım 2 — DbContext

DbContext, veri tabanı ile veri modelleri arasındaki koordinasyonu sağlayan sınıftır. Sorumlulukları (Şekil 15): veri tabanı bağlantısını yönetme, varlıkları ve ilişkilerini yapılandırma, verileri okuma/oluşturma/güncelleme/silme, değişiklik izleme, önbelleğe alma, transaction yönetimi. Kullanmak için DbContext'ten türeyen ve her varlık için DbSet<TEntity> içeren bir sınıf yazılır:

using Microsoft.EntityFrameworkCore;

public class KitaplikContext : DbContext
{
    public DbSet<Kitap> Kitaplar { get; set; }
    public DbSet<Yazar> Yazarlar { get; set; }

    protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
    {
        optionsBuilder.UseSqlServer(
            @"Server=(localdb)\mssqllocaldb;Database=Kitaplik;Trusted_Connection=True;");
    }
}
UseSqlServer
SQL Server sağlayıcısına bağlanan uzantı (extension) metodu; kullanılabilmesi için Microsoft.EntityFrameworkCore.SqlServer yüklü olmalı. Her DbContext tek bir sağlayıcı kullanır.
Connection string
Veri kaynağı bilgisi: Server = DB sunucusu (burada hafif SQL Server LocalDB), Database = oluşacak veri tabanının adı, Trusted_Connection=True = Windows kimlik doğrulaması. Ayrı kurulu SQL Server için Server=.\

Adım 4 — Controller'da kullanmak

public class YazarController : Controller
{
    private KitaplikContext k = new KitaplikContext();

    public IActionResult Index()
    {
        var m = k.Yazarlar.ToList();   // tablodaki tüm yazarlar
        return View(m);                // List şablonlu Index view'ine
    }

    public IActionResult Create() { return View(); }

    [HttpPost]
    public IActionResult Create(Yazar y)
    {
        if (ModelState.IsValid)
        {
            k.Add(y);
            k.SaveChanges();
            return RedirectToAction("Index");
        }
        ViewBag.msj = "Hata !!! Kayıt Eklenemedi";
        return View(y);
    }

    public IActionResult Details(int? id)
    {
        if (id == null) return NotFound();
        var yazar = k.Yazarlar.Include(x => x.Kitaplar)
                              .FirstOrDefault(x => x.YazarID == id);
        if (yazar == null) return NotFound();
        return View(yazar);
    }
}
  • DbSet, IQueryable'dan türediği için üzerinde LINQ kullanılır: from yazar in k.Yazarlar where yazar.YazarID == 1 select yazar. LINQ'i SQL'e çevirmek sağlayıcının işidir.
  • Include, sonuca dahil edilecek gezinme özelliğini iletir (yazarın kitapları da gelir); using Microsoft.EntityFrameworkCore; gerekir.
  • İki Create metodu var: biri formu gösterir (GET), diğeri [HttpPost] ile kaydeder → aşırı yükleme.

1. API ve Web API

Kelimesi kelimesine API (Application Programming Interface, Uygulama Programlama Arayüzü): Programcıların bir uygulamanın, işletim sisteminin veya diğer hizmetlerin belirli özelliklerine ya da verilerine erişmesine izin veren, bir dizi işleve sahip arayüz. Web API: Bir web sitesinin verilerini bir bilgisayar için anlaşılır hâle getiren araç. HTTP protokolü üzerinde çalışan uygulamaların işlevselliğini genişletmek için kullanılan kavram. Her web API aynı zamanda uzak API'dir; her uzak API web API değildir.

Neden gerekli? Bir web uygulaman var, sonra aynı veri tabanını kullanan Android ve iOS uygulamaları ekliyorsun. Üçü de veri tabanıyla doğrudan konuşursa iş mantığı üç kez yazılır (kod tekrarı, hata riski, her değişikliği üç yerde yapmak). Çözüm, araya veri tabanıyla konuşan tek bir uygulama koymak: Web API.

7. ASP.NET Core Web API

API, mevcut bir MVC projesinin içinde ya da baştan ASP.NET Core Web API olarak bağımsız bir hizmet katmanı şeklinde oluşturulabilir. Controllers'a sağ tık → Add Controller → MVC yerine API seçilir; "read/write actions" şablonu tüm metotları hazır getirir:

[Route("api/[controller]")]
[ApiController]
public class ApiDenemeController : ControllerBase
{
    // GET: api/ApiDeneme
    [HttpGet]
    public IEnumerable<string> Get()
    {
        return new string[] { "value1", "value2" };
    }

    // GET api/ApiDeneme/5
    [HttpGet("{id}")]
    public string Get(int id) { return "value"; }

    // POST api/ApiDeneme
    [HttpPost]
    public void Post([FromBody] string value) { }

    // PUT api/ApiDeneme/5
    [HttpPut("{id}")]
    public void Put(int id, [FromBody] string value) { }

    // DELETE api/ApiDeneme/5
    [HttpDelete("{id}")]
    public void Delete(int id) { }
}
ControllerBase
API controller'lar varsayılan olarak ControllerBase'den türer. Controller sınıfı, ControllerBase'den miras alır ve view desteği için ek üyeler içerir. API'ler ayrı çalıştığı için ControllerBase daha uygundur.
[ApiController]
Controller'ın web API isteklerine yanıt verdiğini gösterir; kullanıma hazır doğrulama ve model bağlama sağlar. Her action'da ModelState.IsValid kontrolü gerekmez; doğrulama hatası otomatik HTTP 400 döndürür.
[Route("api/[controller]")]
[controller], çalışma zamanında controller'ın adıyla ("Controller" eki olmadan) değişir: ApiDenemeController → /api/ApiDeneme.
[FromBody]
Değeri isteğin gövdesinden (request body) alır.

Yanıt, istemcinin isteğine göre biçimlenir (örnekte JSON); API çağrılınca nesneyi saran bir ObjectResult oluşur. API'ler geliştiricilerin sık kullandığı Postman ile test edilir.

Kitabın YazarApiController'ı (EF Core ile)

[Route("api/[controller]")]
[ApiController]
public class YazarApiController : ControllerBase
{
    KitaplikContext k = new KitaplikContext();

    [HttpGet]                         // GET api/YazarApi → tümü
    public List<Yazar> Get()
    {
        return k.Yazarlar.ToList();
    }

    [HttpGet("{id}")]                 // GET api/YazarApi/1 → tek kayıt (yoksa 204)
    public Yazar Get(int id)
    {
        return k.Yazarlar.FirstOrDefault(x => x.YazarID == id);
    }

    [HttpPost]                        // POST, JSON gövdede → ekle (200)
    public void Post([FromBody] Yazar y)
    {
        k.Yazarlar.Add(y);
        k.SaveChanges();
    }

    [HttpPut("{id}")]                 // PUT api/YazarApi/13 → güncelle
    public IActionResult Put(int id, [FromBody] Yazar y)
    {
        var y1 = k.Yazarlar.FirstOrDefault(x => x.YazarID == id);
        if (y1 is null) return NotFound();      // 404
        y1.YazarAd = y.YazarAd;
        y1.YazarSoyad = y.YazarSoyad;
        k.Update(y1);
        k.SaveChanges();
        return Ok();                             // 200
    }

    [HttpDelete("{id}")]              // DELETE api/YazarApi/13 → sil
    public ActionResult Delete(int id)
    {
        var y1 = k.Yazarlar.FirstOrDefault(s => s.YazarID == id);
        if (y1 is null) return NotFound();
        k.Remove(y1);
        k.SaveChanges();
        return Ok();
    }
}

  2. GET …/api/Yazarapi/1 → [HttpGet("{id}")] ile URL'deki 1, id parametresine model bağlamayla eşlenir.
  3. GET …/api/Yazarapi/10 → böyle kayıt yok, null döner → 204 İçerik Yok.
  4. POST → Postman'de Body'ye JSON, header Content-Type: application/json → kayıt eklenir, 200 OK.
  5. PUT / DELETE …/api/Yazarapi/13 → güncellenir / silinir; kayıt yoksa 404.

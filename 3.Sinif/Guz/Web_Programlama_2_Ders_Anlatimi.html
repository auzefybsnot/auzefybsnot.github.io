1. Ünite: İnternet ve Web Teknolojileri Temel Kavramlar

Ünitenin Amacı: İnternet ve World Wide Web (WWW) kavramlarının tarihsel gelişimini (Web 1.0, Web 2.0, Web 3.0), İstemci (Front-End / Client-Side) ve Sunucu (Back-End / Server-Side) programlama yaklaşımlarını, Web Framework kavramını, Microsoft .NET ekosisteminin evrimini (.NET Framework, .NET Core, .NET 5+ ve ASP.NET Core) ve temel yazılım mimari modellerini (MVC, Katmanlı, Mikroservis vb.) kapsamlı biçimde kavramaktır.

1.1. İnternet, Web Kavramları ve Web'in Tarihsel Evrimi

İnternet, dünya çapında birbirine bağlı cihazların oluşturduğu küresel bir ağ sistemidir ve temel görevi veriyi bir noktadan başka bir noktaya taşımaktır. Kökeni 1965 yılında askeri bir proje olan ARPANET'e dayanır ve ağ üzerindeki haberleşme TCP/IP (Transmission Control Protocol / Internet Protocol) protokolü üzerinden gerçekleşir.

Web (World Wide Web - WWW) ise internet altyapısı üzerinden erişilen metin sayfaları, görseller, ses ve video dosyaları gibi bilgi topluluğudur. Ağ üzerindeki web kaynaklarının görüntülenmesi ve istemci-sunucu iletişimi, Tim Berners-Lee tarafından CERN'de tanımlanan HTTP (HyperText Transfer Protocol) protokolü ve HTML (HyperText Markup Language) dili aracılığıyla web tarayıcıları (Mosaic, Chrome, Edge, Firefox vb.) üzerinden gerçekleştirilir.

Dönem Aşama Temel Karakteristik Teknolojiler ve Örnekler
1990'lar Web 1.0 (Salt Okunur Web) Kullanıcıların yorum veya geri bildirim yapamadığı, yalnızca sunulan bilgiyi okuyabildiği statik ve tek yönlü web ortamıdır. Statik HTML sayfaları, sınırlı etkileşim.
2000'ler Web 2.0 (Katılımcı / Sosyal Web) Kullanıcı katılımını, iş birliğini ve içerik üretimini teşvik eden dinamik ve çift yönlü etkileşim dönemidir. İstemcide AJAX, JS kütüphaneleri; sunucuda PHP, Python, Ruby, Java (J2EE), .NET Framework; Facebook, YouTube, Wiki.
2010 ve Sonrası Web 3.0 (Semantik Web) "Okuma-yazma-yürütme" yaklaşımıyla verilerin Yapay Zekâ ve Makine Öğrenimi ile yorumlanarak kişiye özgü içerik sunulduğu akıllı web dönemidir. Semantik veri, Yapay Zekâ, Bulut API'ler; Apple Siri, Google Bulut API.

1.2. Web Framework Kavramı, Front-End ve Back-End Geliştirme

Web Framework (Web Çerçevesi), yazılım ve web geliştiriciler için önceden yazılmış bileşenler, kod parçacıkları ve uygulama şablonları sunan hazır araç ve kaynak bütünüdür. Framework kullanılmadan da web programlama yapılabilir; ancak çerçeveler tekrarlayan kod yazımını önler, zamandan tasarruf sağlar, güvenlik yamaları sunar ve ORM aracılığıyla veritabanı entegrasyonunu kolaylaştırır.

1.3. .NET Ekosisteminin Evrimi: .NET Framework, .NET Core ve ASP.NET Core

.NET Framework (2002–2019), Microsoft tarafından geliştirilen, 25'ten fazla dili (C#, VB.NET, F#) destekleyen ancak yalnızca Windows işletim sisteminde çalışan geleneksel yazılım çatısıdır (son sürüm 4.8). Temel sınıf kütüphaneleri mantıksal olarak isim alanları (namespace) altında gruplanır (örn. using System;, using System.IO;) ve Java'daki paket (package) yapısına karşılık gelir.

.NET Core (2016–Günümüz) ise sıfırdan tasarlanan, açık kaynaklı ve platform bağımsız yeni nesil .NET platformudur. 1.0, 1.1, 2.0, 2.1, 2.2, 3.0 ve 3.1 sürümlerinin ardından, .NET Framework 4.x ile karışmaması için 4.x sürümü atlanmış ve Kasım 2020'de tüm .NET platformlarını tek çatı altında birleştiren .NET 5 (devamında .NET 6, 7, 8) yayımlanmıştır.

ASP.NET Core'un Temel Avantajları ve Yenilikleri:

  1. Çapraz Platform (Cross-Platform): Windows, Linux ve macOS üzerinde çalışır; IIS, Kestrel, Apache veya Nginx sunucularında barındırılabilir.
  2. Açık Kaynak Kod Esnekliği: Kaynak kodları Microsoft tarafından GitHub üzerinde açık olarak yayımlanır ve ücretsizdir.
  3. Yüksek Performans ve Bulut Uyumu: Hafiftir, bellek kullanımı düşüktür ve bulut maliyetlerini azaltır; async/await desteğiyle yüksek eşzamanlılık sağlar.
  4. Mikroservis Mimarisi Uyumu: Bağımsız geliştirilip dağıtılabilen modüler servisler için idealdir.
  5. Birleşik Web Modeli ve Dahili DI: Klasik .NET Framework'teki Web Forms yerine Razor Pages ve Blazor gelmiş; ASP.NET Core MVC ve Web API tek çatı altında birleştirilmiştir. Ayrıca yerleşik Dependency Injection (DI), SignalR ve gRPC desteği sunar.

1.4. Yazılım Mimari Modelleri (Software Architectural Patterns)

Mimari modeller, yazılım sistemlerinin yapısal bileşimini ve bileşenler arası etkileşim kurallarını belirleyen, geniş kapsamlı ve yeniden kullanılabilir çözümlerdir:

Mimari Model Yapısı ve Kullanım Amacı
MVC (Model-View-Controller) Uygulamayı Model (veri/iş mantığı), View (görünüm) ve Controller (denetleyici) olarak üç mantıksal bileşene ayırır; sunum katmanını iş mantığından ayırır.
Layered (Katmanlı / N-Tier) Her katmanın bir üst katmana hizmet verdiği hiyerarşik yapıdır (Presentation, Application, Business Logic, Data Access).
Client-Server (İstemci-Sunucu) Birden çok istemcinin isteklerini dinleyen ve hizmet sağlayan merkezi bir sunucudan oluşur.
Monolitik vs. Mikroservis Monolitik mimaride tüm modüller tek blokta derlenirken; Mikroservis mimarisinde bağımsız dağıtılan küçük iş servisleri REST/gRPC ile haberleşir.
Diğer Mimari Desenler Master-Slave (çok iş parçacıklı paralel iş dağıtımı), Peer-to-Peer (eşler arası: DNS, BitTorrent), Event-Bus (olay kanalı üzerinden asenkron mesajlaşma), Blackboard (ortak veri yapısı), Interpreter (JS gibi betik yorumlama), Broker (dağıtık bileşen koordinasyonu).

2.2. Startup.cs / Program.cs ve Middleware (Ara Yazılım) Hattı

ASP.NET Core uygulamasında gelen her HTTP isteği (Request) ve dönen yanıt (Response), Middleware (Ara Yazılım) adı verilen sıralı yazılım bileşenlerinden oluşan bir boru hattından (Application Pipeline) geçer. .NET 5 dönemini anlatan ders kitabında yapılandırma iki dosyada bölünmüştür: Program.cs host'u başlatırken, Startup.cs içinde ConfigureServices() metodu servisleri (Dependency Injection) ekler ve Configure() metodu Middleware sırasını kurar.

.NET 6, 7 ve 8+ sürümlerinde ise Startup.cs kaldırılmış, her iki aşama tek bir Program.cs dosyasında (Minimal Hosting Model) birleştirilmiştir:

var builder = WebApplication.CreateBuilder(args);

// 1. Builder (Servis Kaydı / eski ConfigureServices) Aşaması:
builder.Services.AddControllersWithViews(); // MVC servislerini DI konteynerine ekler

var app = builder.Build();

// 2. Middleware Pipeline (eski Configure) Aşaması - SIRA KRİTİKTİR:
if (!app.Environment.IsDevelopment())
{
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}

app.UseHttpsRedirection(); // HTTP isteklerini HTTPS'e yönlendirir
app.UseStaticFiles();      // wwwroot altındaki CSS/JS/resim dosyalarını sunar
app.UseRouting();          // Gelen URL'yi rota tablosuyla eşleştirir
app.UseAuthentication();   // Kimlik doğrulama (kimsin?)
app.UseAuthorization();    // Yetkilendirme (yetkin var mı?)

// 3. Varsayılan Rota (Endpoint) Tanımı:
app.MapControllerRoute(
    name: "default",
    pattern: "{controller=Home}/{action=Index}/{id?}");

app.Run();
Sınav Notu (Middleware Sırası): İstek boru hattında bileşenlerin eklenme sırası çalışma sırasını belirler. Örneğin statik dosyalar (UseStaticFiles) yönlendirmeden önce kısa devre yaptırılarak performans kazanılır; UseRouting() ise mutlaka UseAuthorization() ve MapControllerRoute() öncesinde çağrılmalıdır.

2.3. MVC Bileşenleri ve Yaşam Döngüsü (Lifecycle)

MVC deseni sorumlulukları üç bağımsız bileşene ayırarak sürdürülebilir ve test edilebilir kod üretir:

  • Model (.cs): Uygulamanın verilerini, durumunu ve iş mantığını (business logic) temsil eden C# sınıflarıdır (Örn: Ogrenci.cs, Product.cs).
  • View (.cshtml): Kullanıcı arabirimini (HTML) oluşturmaktan sorumludur. Razor View Engine ile C# verilerini HTML'e dönüştürür; minimum mantıksal işlem içermelidir.
  • Controller (.cs): MVC yapısında kullanıcıdan gelen HTTP isteklerini karşılayan ilk giriş noktasıdır. Microsoft.AspNetCore.Mvc.Controller sınıfından miras alır, Model ile çalışır ve kullanıcıya hangi View'in (veya sonucun) döneceğine karar verir.

MVC Yaşam Döngüsü: İstemci HTTP isteği gönderir → Web sunucusu (IIS/Kestrel) isteği alır → Routing mekanizması URL'yi çözer → İlgili Controller ve Action metodu çalıştırılır → Model verileri işlenir → Uygun View Razor motorunca HTML'e çevrilir ve HTTP yanıtı olarak tarayıcıya döndürülür.

2.4. Controller, Action Metotları ve URL Yönlendirme (Routing)

ASP.NET Core'da tüm Controller sınıfları Controllers klasörü altında tanımlanır ve adları mutlaka "Controller" son ekiyle biter (örn. OgrenciController); ancak URL'de bu son ek yazılmaz. Controller sınıfı içerisindeki dışarıdan HTTP ile çağrılabilen public metotlara Action Metodu denir.

Önemli Kural: Action metotlar mutlaka public olmalıdır; static ve aşırı yüklenmiş (overloaded) metotlar action metot olamazlar. Action metotları esnek dönüş tipleri için genellikle IActionResult (veya ActionResult) döner: View() (ViewResult), Json() (JsonResult), Content() (ContentResult), Redirect(), NotFound(), File().

using Microsoft.AspNetCore.Mvc;
using System.Collections.Generic;

namespace WebApp.Controllers
{
    public class UrunController : Controller
    {
        // Convention Route: GET /Urun veya /Urun/Index
        public IActionResult Index()
        {
            var urunler = new List<string> { "Laptop", "Mouse", "Klavye" };
            return View(urunler); // Views/Urun/Index.cshtml dosyasını döndürür
        }

        // Convention Route: GET /Urun/Detay/5
        public IActionResult Detay(int id)
        {
            if (id <= 0) return NotFound(); // HTTP 404
            return View();
        }

        // Attribute Routing Örneği: GET /katalog/ozel/12
        [Route("katalog/ozel/{kod:int}")]
        public IActionResult OzelUrun(int kod)
        {
            return Content($"Ürün Kodu: {kod}", "text/plain");
        }
    }
}

Varsayılan URL Kalıbı (Convention-Based Routing):

Varsayılan rota şablonu "{controller=Home}/{action=Index}/{id?}" biçimindedir. URL'de değer belirtilmezse varsayılan Controller HomeController, varsayılan Action Index olur; id? ise opsiyonel parametredir.

Gelen URL Controller Action id Parametresi

http://localhost:3000/Ogrenci OgrenciController Index null
http://localhost:3000/Ogrenci/OgrGetir OgrenciController OgrGetir null
http://localhost:3000/Ogrenci/Index/100 OgrenciController Index 100

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Sık Sorulan Sorular:
  1. Varsayılan rota sıralaması nedir? -> Controller / Action / Parametre ({controller=Home}/{action=Index}/{id?}).
  2. Model, Controller ve View dosyalarının uzantıları nelerdir? -> Model ve Controller C# sınıfı olduğu için .cs; View ve Layout ise .cshtml uzantılıdır.
  3. Action metotlar için hangi kısıtlama geçerlidir? -> Yalnızca public metotlar action olabilir; private, static veya aşırı yüklenmiş metotlar action olamaz.
  4. Statik dosyalar nerede tutulur ve port nasıl seçilir? -> CSS/JS/resimler wwwroot klasöründe durur; IIS Express varsayılan olarak rastgele port seçer.

3. Ünite: Layout Kavramı ve Razor View Engine

Ünitenin Amacı: Tüm sayfalarda tutarlı ve tekrar kullanılabilir arayüz sağlayan Layout (_Layout.cshtml) mimarisini, @RenderBody(), @RenderSection(), _ViewStart.cshtml, _ViewImports.cshtml, Partial View ve ViewComponent yapılarını, ayrıca HTML içine C# kodları gömmeyi sağlayan Razor View Engine sözdizimini, koşullu ifadeleri ve döngüleri kavramaktır.

3.1. Layout Mimarisi (_Layout.cshtml, _ViewStart ve _ViewImports)

Web uygulamalarında üst menü (header / nav), sol menü, alt bilgi (footer) ve ortak CSS/JavaScript (Bootstrap, jQuery) referansları sayfalar boyunca sabit kalır. Kod tekrarını önleyen ve bakımı kolaylaştıran bu ortak şablon yapısına Layout denir. Bir Layout oluşturulurken yapılması gereken ilk şey Layout şablonuna karar vermektir.

Layout dosyası da bir Razor görünümü olduğu için uzantısı .cshtml'dir ve projedeki tüm view'lerle paylaşıldığı için Views/Shared/_Layout.cshtml konumunda yer alır. Bir Layout dosyasında HTML iskeleti, menüler, CSS/JS kütüphane referansları bulunabilir; ancak Model sınıfı tanımları kesinlikle bulunmaz.

  • @RenderBody(): Layout içerisinde çağrılan asıl içerik görünümünün (ör. Home/Index.cshtml) HTML çıktısının yerleştirileceği zorunlu alandır. Her Layout'ta tam olarak bir tane bulunur.
  • @RenderSection("Scripts", required: false): Yalnızca belirli sayfalara özgü script veya stil bloklarının (@section Scripts { ... }) şablonun belirli bir yerine enjekte edilmesini sağlar.
  • _ViewStart.cshtml: Views klasörünün kökünde bulunur. Her View render edilmeden önce otomatik çalışarak tüm sayfalarda geçerli olacak varsayılan Layout'u belirler (@{ Layout = "_Layout"; }). Tekil bir sayfada kapatmak için Layout = null; yazılır.
  • _ViewImports.cshtml: Tüm View'lerde kullanılacak ortak @using ad alanlarını ve @addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers direktifini merkezi olarak tanımlar.
<!-- Views/Shared/_Layout.cshtml temel iskeleti -->
<!DOCTYPE html>
<html lang="tr">
<head>
    <title>@ViewData["Title"] - AUZEF MVC</title>
    <link rel="stylesheet" href="~/css/site.css" />
</head>
<body>
    <header><nav>Ortak Üst Menü</nav></header>
    <main>
        @RenderBody() <!-- İçerik View'i buraya basılır -->
    </main>
    <footer>Ortak Alt Bilgi</footer>
    @await RenderSectionAsync("Scripts", required: false)

</html>

Partial View ve ViewComponent ile Modüler Tasarım:

Layout dışında sayfa içi tekrar eden parçalar iki mekanizma ile modülerleştirilir: Partial View (Views/Shared/_MenuPartial.cshtml), yalnızca HTML/Razor parçasını <partial name="_MenuPartial" /> veya @await Html.PartialAsync("_MenuPartial") ile çağırır; kendi bağımsız veri sorgusu yoktur. ViewComponent ise kendi C# sınıfına (ViewComponent sınıfından türeyen ve InvokeAsync() metodu içeren) ve kendi Default.cshtml görünümüne sahip mini bir Controller gibidir (sepet özeti, dinamik kategori menüsü vb.) ve @await Component.InvokeAsync("SepetOzet") ile çağrılır.

3.2. Razor View Engine ve '@' Sözdizimi

.NET Framework dönemindeki Aspx ve Spark motorları ASP.NET Core'da yerini varsayılan görünüm motoru olan Razor View Engine'e bırakmıştır. Razor, .cshtml dosyalarındaki HTML ile C# kodlarını sunucuda işleyerek (parse) tarayıcıya saf HTML çıktısı üretir. HTML'den C# koduna geçiş @ sembolü ile yapılır.

Yapı Sözdizimi Açıklama ve Dikkat Edilecek Nokta
Tek Satır İfade @DateTime.Now.ToString() @ işaretinden hemen sonraki C# ifadesi değerlendirilir ve değeri HTML'e yazılır.
Açık (Explicit) İfade @(x + y) vs @x + y @x + y yazılırsa Razor sadece @x'i C# sayar, + y'yi düz metin basar! Hesaplama için @(x + y) şarttır.
Çok Satırlı Kod Bloğu @{ var x = 7; ... } Değişken tanımlama, atama ve çok satırlı C# işlemleri için @{ ... } bloğu kullanılır.
C# İçine HTML / Metin <p>...</p> veya @: metin C# kod bloğu içinde HTML etiketi doğrudan veya etiketsiz düz metin @: operatörü ile yazılır.
Yorum / Açıklama @* Razor yorumu *@ @* ... *@ sunucuda atılır, sayfa kaynağında görünmez. <!-- ... --> HTML yorumudur (kaynakta görünür); // ve /* */ sadece @{ } içinde geçerlidir.

3.3. Razor İçinde Koşullu İfadeler ve Döngüler

.cshtml görünümlerinde C# söz dizimine uygun biçimde if / else if / else, switch-case karar yapıları ile for, foreach, while ve do-while döngüleri doğrudan kullanılabilir:

4. Ünite: Form İşlemleri ve Model Bağlama (Model Binding)

Ünitenin Amacı: Kullanıcı ile sunucu arasındaki temel etkileşim aracı olan HTML formlarının yapısını ve form elemanlarını (input, select, textarea), HTTP GET ve POST yöntemleri arasındaki farkları, Controller içinde manuel veri okumayı (Request.Query / Request.Form), Model Binding mekanizmasını, kaynak özniteliklerini ve DataAnnotations doğrulama temellerini kavramaktır.

4.1. HTML Form Yapısı ve Form Elemanları

Web formları <form action="..." method="..."> ... </form> etiketleri arasında tanımlanır ve View (.cshtml) dosyaları içinde yer alır. Bir formdaki verinin sunucuya gidebilmesi için her elemanın mutlaka bir name niteliğine sahip olması gerekir; sunucuya veriler name=değer çiftleri olarak iletilir.

  • action niteliği: Formun gönderileceği hedef URL'yi belirtir (örn. \Ogrenci\Kaydet). Tanımlanmazsa varsayılan olarak formun tanımlı olduğu aynı sayfaya gönderilir.
  • method niteliği: Gönderim yöntemini (GET veya POST) belirler. Saf HTML <form> etiketinde method yazılmazsa varsayılan yöntem GET'tir. (Not: Ünite 6'da göreceğiniz Form Tag Helper <form asp-action="..."> ise varsayılan olarak POST kullanır.)
Form Elemanı / Tip Kullanım Amacı ve Sınav Detayı
<input type="text"> Tek satırlı metin girişidir. <input> etiketinde type niteliği yazılmazsa varsayılan tip text'tir.
<input type="radio"> Aynı name değerine sahip birçok seçenek arasından yalnızca bir tek seçenek seçtirmek için kullanılır.
<input type="checkbox"> Sunulan seçenekler içerisinden birden fazla seçim yapılabilmesini sağlayan onay kutusudur.
<input type="hidden"> Sayfada kullanıcıya görünmeyen gizli veriler taşır; ancak "Kaynağı Görüntüle" ile görülebilir ve Postman vb. ile manipüle edilebilir.
<input type="submit"> Form içerisindeki verileri belirlenen action adresine göndermeyi tetikleyen butondur.
<select> ve <textarea> <select><option> açılır liste oluşturur; <textarea rows="..." cols="..."> çok satırlı metin girişi sağlar.

4.2. HTTP GET vs. HTTP POST ve Manuel Veri Okuma

Özellik HTTP GET HTTP POST
Verinin Taşındığı Yer URL'nin sonundaki Query String içinde (/Haber/Detay?HbrId=100&sayfa=2) HTTP İstek Gövdesi (Request Body) içinde taşınır; URL'de görünmez.
Güvenlik ve Gizlilik Adres çubuğunda açıktır, tarayıcı geçmişinde kalır ve kullanıcıca değiştirilebilir (manipüle edilebilir). URL'de ve geçmişte görünmez; şifre ve hassas form verileri için tercih edilir.
Boyut ve Dosya Yükleme URL uzunluk sınırı vardır (maksimum ~2048 karakter); dosya yüklenemez. Pratik boyut sınırı yoktur; resim ve dosya yükleme (upload) yapılabilir.
Controller Özniteliği [HttpGet] (Action metotlarında varsayılan HTTP fiilidir) [HttpPost] (Tarayıcı adres çubuğundan GET ile çağrılırsa HTTP 405 hatası verir!)
Manuel Okuma Yöntemi HttpContext.Request.Query["name_degeri"] HttpContext.Request.Form["name_degeri"]
Dikkat Edilecek Nokta: Manuel veri okurken Response değil Request nesnesi kullanılır ve köşeli parantez içine input'un type değeri değil name değeri yazılır! Örneğin <input name="ad" type="text"> GET ile gönderildiğinde HttpContext.Request.Query["ad"] ile okunur.

4.3. Model Bağlama (Model Binding), Kaynak Öznitelikleri ve Doğrulama

Model Binding (Model Bağlama), HTTP isteğinden (Route, QueryString, Form Body, Header) gelen ad/değer çiftlerini geliştiricinin manuel Request.Form/Request.Query kodu yazmasına gerek kalmadan otomatik olarak Action metodunun basit parametrelerine veya karmaşık bir Model nesnesine dönüştürme işlemidir.

Eşleşme, form elemanının/parametrenin adı (name) ile Model sınıfının public özelliklerinin ({ get; set; } properties) adının uyuşmasıyla (büyük/küçük harf duyarsız) gerçekleşir. Metotlar model bağlamaya katılmaz. Formda karşılığı gönderilmeyen özellikler ise veri tipinin varsayılan değerini alır (ör. int için 0, string için null).

using System.ComponentModel.DataAnnotations;
using Microsoft.AspNetCore.Mvc;

// 1. Model Sınıfı (DataAnnotations Doğrulama Kuralları ile)
public class Ogrenci
{
    [Required(ErrorMessage = "Öğrenci adı zorunludur.")]
    [StringLength(50, MinimumLength = 2)]
    public string OgrAd { get; set; }

    [Required(ErrorMessage = "Soyad zorunludur.")]
    public string OgrSoyad { get; set; }

    public string OgrNo { get; set; }

    [Range(18, 65, ErrorMessage = "Yaş 18-65 aralığında olmalıdır.")]
    public int OgrYas { get; set; }
}

// 2. Controller Action'ları
public class OgrenciController : Controller
{
    // GET: /Ogrenci/Kaydet/5?ders=Web2
    [HttpGet]
    public IActionResult Detay([FromRoute] int? id, [FromQuery] string ders)
    {
        return Content($"ID: {id}, Ders: {ders}");
    }

    // POST: Formdaki name="OgrAd", name="OgrSoyad" alanları ogr nesnesine bağlanır
    [HttpPost]
    public IActionResult Kaydet([FromForm] Ogrenci ogr)
    {
        if (!ModelState.IsValid)
        {
            return View(ogr); // Doğrulama hatası varsa formu hatalarla geri göster
        }
        return RedirectToAction("Index");
    }
}

Model Bağlama Kaynak Öznitelikleri (Binding Sources):

  • [FromRoute]: Veriyi yalnızca URL rota segmentlerinden alır (ör. /Home/Kaydet/5 içindeki id).
  • [FromQuery]: Veriyi yalnızca URL QueryString'den (?ogrAd=Hasan) alır.
  • [FromForm]: Veriyi HTML Form POST gövdesinden (application/x-www-form-urlencoded veya multipart/form-data) alır.
  • [FromBody]: Veriyi JSON/XML formatındaki istek gövdesinden (özellikle Web API'lerde) okur.

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Sık Sorulan Sorular:
  1. Saf HTML <form> etiketinde action ve method yazılmazsa ne olur? -> Action boşsa formun tanımlı olduğu sayfaya; method boşsa varsayılan olarak GET ile gönderilir.
  2. GET ve POST ile gelen form verisi Controller'da manuel nasıl alınır? -> GET için HttpContext.Request.Query["name"], POST için HttpContext.Request.Form["name"].
  3. Model bağlamada bir sınıfın hangi üyeleri bağlanabilir? -> Yalnızca { get; set; } tanımlı özellikler (properties) bağlanır; metotlar bağlanmaz.
  4. [HttpPost] action'ı adres çubuğundan çağrılırsa ne olur? -> Tarayıcı GET isteği attığı için HTTP 405 Method Not Allowed hatası oluşur.

5. Ünite: Durum Yönetimi (State Management) ve View'e Veri Aktarımı

Ünitenin Amacı: HTTP protokolünün durumsuz (stateless) yapısını ve bu yapıyı aşmak için kullanılan İstemci Taraflı (Query String, Hidden Fields, HTTP Cookies) ve Sunucu Taraflı (Session) durum yönetimi tekniklerini; ayrıca Controller'dan View'e veri taşımada kullanılan ViewBag, ViewData, TempData ve güçlü tipli ViewModel (@model) yaklaşımlarını kavramaktır.

5.1. Durum Yönetimi: Stateless Protokoller, İstemci vs. Sunucu

Ağ protokolleri Durumsuz (Stateless: HTTP, UDP, DNS) ve Durum Bilgili (Stateful: FTP, TCP, SMTP) olmak üzere ikiye ayrılır. HTTP durumsuz bir protokoldür; yani sunucu, gelen her isteği öncekilerden tamamen bağımsız ve ilk kez geliyormuş gibi değerlendirir. Kullanıcı girişi, sepet bilgisi veya tema tercihi gibi verilerin sayfalar arası korunabilmesi için Durum Yönetimi (State Management) teknikleri kullanılır.

Teknik Taraf Saklandığı Yer ve Sınır Güvenlik ve İdeal Kullanım
Query String İstemci URL sonu (?user=ali&limit=10); & ile ayrılır, ~2048 karakter sınırı. Adres çubuğunda görünür ve değiştirilebilir; sayfalama, arama filtreleri için kullanılır.
Hidden Fields İstemci Form içi <input type="hidden" name="UserId" value="10"> Sayfa kaynağını görüntüle ile okunur, Postman ile değiştirilebilir; sunucuda tekrar doğrulanmalıdır.
HTTP Cookies (Çerez) İstemci Kullanıcı bilgisayarında metin dosyası; tarayıcı limiti 4096 bayt. Kullanıcı silebilir/değiştirebilir! Renk, tema, dil tercihi gibi hassas olmayan veriler tutulur (şifre, yetki, DB bilgisi konmaz).
Session (Oturum) Sunucu Sunucu belleği/DB; istemcide yalnızca şifreli Session ID çerezi durur. Varsayılan zaman aşımı 20 dk. Güvenli ve performanslıdır; kullanıcı adı, yetki seviyesi gibi oturum boyunca korunacak hassas veriler için idealdir.

5.2. Cookie (Çerez) ve Session (Oturum) Uygulaması

ASP.NET Core MVC'de hem Cookie hem de Session işlemleri için Controller veya View'e mutlaka Microsoft.AspNetCore.Http namespace'i eklenmelidir. Kitapta (.NET 5) Session'ı etkinleştirmek için Startup.cs içindeki ConfigureServices metoduna services.AddSession(); ve Configure metoduna app.UseSession(); eklenir (modern .NET 6/7/8+'da aynı iki çağrı Program.cs içindedir).

using Microsoft.AspNetCore.Http;
using Microsoft.AspNetCore.Mvc;
using System.Text.Json;

public class HomeController : Controller
{
    public IActionResult TercihVeOturum()
    {
        // 1. COOKIE YAZMA (Response üzerinden Append edilir!)
        var cookieOpt = new CookieOptions
        {
            Expires = DateTime.Now.AddMinutes(10),
            HttpOnly = true
        };
        HttpContext.Response.Cookies.Append("tema", "pixel", cookieOpt);

        // 2. COOKIE OKUMA (Request üzerinden okunur!)
        string tema = HttpContext.Request.Cookies["tema"];

        // 3. SESSION YAZMA ve OKUMA (ISession: SetString, SetInt32, GetString, GetInt32)
        HttpContext.Session.SetString("SessionUser", "can");
        HttpContext.Session.SetInt32("YetkiSeviyesi", 1);

        // Karmaşık nesneler JSON'a serileştirilerek saklanır (System.Text.Json)
        var sepet = new List<string> { "Kitap", "Kalem" };
        HttpContext.Session.SetString("Sepet", JsonSerializer.Serialize(sepet));

        string aktifKullanici = HttpContext.Session.GetString("SessionUser");
        return View();
    }
}

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Sık Sorulan Sorular:
  1. Hangi ağ protokolleri durumsuzdur (stateless)? -> HTTP, UDP, DNS durumsuz; FTP, TCP, SMTP durum bilgilidir.
  2. Cookie ve Session için zorunlu namespace ve kurulum? -> Microsoft.AspNetCore.Http. Kitap kurulumunda Startup.cs'te services.AddSession(); ve app.UseSession(); yazılır.

6. Ünite: Etiket Yardımcıları (Tag Helper)

Ünitenin Amacı: ASP.NET Core Razor görünümlerinde sunucu taraflı kodların standart HTML etiketleri gibi doğal bir sözdizimiyle yazılmasını sağlayan Tag Helper (Etiket Yardımcısı) teknolojisini kavramak; geleneksel HTML Helper yöntemleriyle farklarını analiz etmek ve form, bağlantı, girdi denetimi bileşenlerini yetkinlikle yapılandırmaktır.

6.1. Tag Helper (Etiket Yardımcıları) Kavramı ve Çalışma Mantığı

ASP.NET Core MVC mimarisinde görünümlerin (View) oluşturulmasında en devrimsel yeniliklerden biri Tag Helper (Etiket Yardımcıları) yapısıdır. Klasik ASP.NET MVC sürümlerinde C# kodları ve sunucu taraflı kontroller, Razor görünümlerine @Html.TextBoxFor(), @Html.ActionLink() gibi C# metot çağrıları (HTML Helpers) şeklinde entegre edilmekteydi. Bu durum HTML kodunun okunabilirliğini bozmakta ve ön yüz (Front-End) geliştiricilerinin şablonlar üzerinde çalışmasını güçleştirmekteydi.

Tag Helper teknolojisi ise sunucu taraflı kodların doğrudan standart HTML etiketlerine özel öznitelikler (attributes) eklenmesi yoluyla çalışmasını sağlar. Tarayıcıya gönderilmeden önce sunucuda Razor Engine tarafından işlenir ve saf HTML5 çıktılarına dönüştürülür.

Temel Prensip: Bir Razor görünümünde Tag Helper kullanabilmek için dosyanın veya genel _ViewImports.cshtml dosyasının en başında @addTagHelper *, Microsoft.AspNetCore.Mvc.TagHelpers direktifinin tanımlanmış olması zorunludur.

6.2. Tag Helper ile Geleneksel HTML Helper Karşılaştırması

Özellik Geleneksel HTML Helper (ASP.NET MVC) Modern Tag Helper (ASP.NET Core)
Yazım Sözdizimi C# metot çağrısı: @Html.ActionLink("Giriş", "Login", "Account") Doğal HTML etiketi: <a asp-controller="Account" asp-action="Login">Giriş</a>
HTML Uyumu HTML şablonunun hiyerarşik akışını bozar; CSS sınıfları için karmaşık anonim nesneler gerekir: new { @class = "btn btn-primary" } Doğrudan standart HTML class="btn btn-primary" özniteliği yazılır. Ön yüz araçları ve tasarımcılar zorlanmaz.
IntelliSense Desteği Sadece C# metot parametrelerinde tamamlama sağlar. HTML etiketleri ve model alanları için hem HTML hem C# çift yönlü IntelliSense desteği sunar.
Genişletilebilirlik Yeni C# Extension metotları yazmayı gerektirir. TagHelper sınıfından türetilen özel C# sınıfları ile özel HTML etiketleri (örn: <email mail-to="destek@site.com"></email>) tanımlanabilir.

6.3. Sık Kullanılan Standart Tag Helper Bileşenleri

1. Anchor Tag Helper (<a>)

Sayfalar arası bağlantı (hyperlink) oluştururken URL'yi elle (hardcoded) yazmak yerine MVC rota sistemini (Routing) dinamik olarak kullanır:

<!-- Belirli Controller ve Action'a yönlendiren rota parametreli bağlantı -->
<a asp-controller="Product" asp-action="Details" asp-route-id="@Model.Id" class="btn btn-info">
    Ürün Detayını Gör
</a>

<!-- Sayfa içi çapa (fragment) ve protokol belirleme -->
<a asp-controller="Home" asp-action="About" asp-fragment="ekip" asp-protocol="https">
    Hakkımızda / Ekibimiz
</a>

Sunucu bu etiketi derlediğinde rota tablosunu çözümleyerek <a href="/Product/Details/5" class="btn btn-info"> şeklinde saf bir HTML çıktısı üretir.

2. Form Tag Helper (<form>)

Form etiketinin gönderileceği hedefi belirler. En kritik özelliklerinden biri, CSRF (Cross-Site Request Forgery - Siteler Arası İstek Sahteciliği) saldırılarına karşı otomatik olarak gizli bir anti-forgery güvenlik belirteci (__RequestVerificationToken) eklemesidir:

<form asp-controller="Account" asp-action="Login" method="post">
    <!-- Arka planda otomatik eklenen güvenlik inputu: -->
    <!-- <input name="__RequestVerificationToken" type="hidden" value="CfDJ8..." /> -->
</form>

3. Input ve Label Tag Helper (<input> ve <label>)

asp-for özniteliği, girdi alanını modelin belirli bir özelliğine (property) bağlar. Modeldeki veri tipini otomatik analiz ederek uygun HTML5 type niteliğini üretir:

  • Eğer model özelliği bool ise type="checkbox"
  • Eğer string ve [DataType(DataType.Password)] ise type="password"
  • Eğer DateTime ise type="datetime-local" veya type="date"
  • Eğer int veya decimal ise type="number"
<div class="form-group">
    <label asp-for="Email" class="control-label"></label>
    <input asp-for="Email" class="form-control" />
    <span asp-validation-for="Email" class="text-danger"></span>
</div>

4. Select Tag Helper (<select>)

Açılır listelerin (dropdown) dinamik veri koleksiyonlarıyla doldurulmasını sağlar. asp-for seçilen değeri modele bağlarken, asp-items listelenecek elemanları (IEnumerable<SelectListItem> veya SelectList) bağlar:

<select asp-for="CategoryId" asp-items="Model.CategoryList" class="form-control">
    <option value="">-- Bir Kategori Seçiniz --</option>
</select>

5. Textarea Tag Helper (<textarea>)

Çok satırlı metin alanlarını modele bağlar. İki etiket arasına model değerini kendiliğinden basar:

<textarea asp-for="Description" rows="5" cols="40" class="form-control"></textarea>

6.4. Hazır Razor View Şablonları Oluşturma (Scaffolding Razor View)

Visual Studio ve .NET CLI araçları, bir model ve veri bağlamı (DbContext) temelinde otomatik CRUD (Create, Read, Update, Delete) görünümleri oluşturmak için Scaffolding (iskele kurma) mekanizması sunar.

  • List (Index): Tablo biçiminde tüm kayıtları listeleyen, Düzenle/Detay/Sil butonlarını içeren şablon.
  • Create: Yeni kayıt ekleme formu oluşturan, validation tag helper'ları barındıran şablon.
  • Edit: Mevcut kaydı güncellemek için gizli ID alanı ve girdi formları barındıran şablon.
  • Details: Tek bir kaydın tüm alanlarını salt okunur listeleyen şablon.
  • Delete: Kaydı silmeden önce kullanıcıdan onay isteyen özet ekran şablonu.

7. Ünite: Model Doğrulama (Model Validation)

Ünitenin Amacı: Kullanıcıdan alınan verilerin iş kurallarına, güvenlik ilkelerine ve veri tabanı kısıtlarına uygunluğunu denetleyen Model Doğrulama (Model Validation) mekanizmasını, Veri Açıklamaları (Data Annotations) özniteliklerini, istemci ve sunucu taraflı doğrulama farklarını ve hata mesajlarının Razor görünümlerinde sunulmasını derinlemesine öğrenmektir.

7.1. Model Doğrulama Kavramı ve Güvenlik Mantığı

Web uygulamalarında kullanıcıdan formlar, URL parametreleri veya JSON gövdeleri üzerinden veri kabul edilirken, "Kullanıcıdan gelen hiçbir girdiye güvenilemez" (Never trust user input) altın kuralı esastır. Hatalı, eksik veya kötü niyetli (SQL Injection, XSS) verilerin veri tabanına yazılmasını önlemek için iki aşamalı bir doğrulama katmanı kurgulanır:

  • İstemci Taraflı (Client-Side) Doğrulama: Kullanıcı henüz formu göndermeden (submit etmeden) web tarayısıcında JavaScript aracılığıyla çalışır. Sunucuya gereksiz istek gitmesini önler ve kullanıcıya anlık (real-time) geri bildirim sağlar. Ancak tarayıcıda JavaScript devre dışı bırakılabilir veya istekler Postman gibi araçlarla doğrudan sunucuya iletilebilir.
  • Sunucu Taraflı (Server-Side) Doğrulama: Veriler sunucuya ulaştığında Controller katmanında çalışır. Asla atlatılamaz ve sistem güvenliğinin ana omurgasını oluşturur.

7.2. Veri Açıklamaları (Data Annotations)

ASP.NET Core'da doğrulama kuralları, model sınıflarının özellikleri üzerine System.ComponentModel.DataAnnotations ad alanı altındaki öznitelikler (attributes) eklenerek tanımlanır:

Öznitelik (Annotation) Açıklama ve Amacı Örnek Kullanım
[Required] Alanın boş bırakılamayacağını, zorunlu olduğunu belirtir. [Required(ErrorMessage = "Ad alanı boş geçilemez!")]
[StringLength(max, Min)] Metinsel ifadenin alabileceği maksimum ve opsiyonel minimum uzunluğu sınırlar. [StringLength(50, MinimumLength = 3, ErrorMessage = "Ad 3-50 karakter olmalıdır.")]

8. Ünite: LINQ - Language Integrated Query (Dile Entegre Sorgu)

Ünitenin Amacı: .NET dillerinde bellek içi koleksiyonlar, XML dokümanları ve ilişkisel veritabanları üzerinde standart, tip güvenli (type-safe) ve derleme zamanı denetimli sorgular yazmayı sağlayan LINQ mimarisini, sorgu sözdizimlerini (Query Syntax vs. Method/Lambda Syntax), ertelenmiş (Deferred) ve anlık (Immediate) sorgu yürütme mekanizmalarını ve temel sorgu operatörlerini kavramaktır.

8.1. LINQ Mimarisi ve Avantajları

Geleneksel yazılım geliştirmede dizi ve koleksiyonlar için döngüler (foreach, for), veritabanları için SQL dizgileri, XML belgeleri için XPath gibi birbirinden tamamen farklı diller ve sözdizimleri kullanılmaktaydı. SQL sorguları metin (string) olarak yazıldığından sözdizimi hataları ancak çalışma zamanında (runtime) fark edilebiliyordu.

LINQ (Language Integrated Query), veri kaynağı ne olursa olsun C# dilinin doğal bir parçası olarak sorgu yazmayı mümkün kılan bir teknolojidir. Sağladığı başlıca avantajlar:

  • Tip Güvenliği (Type-Safety): Sorgulanan nesnelerin tipleri derleyici tarafından bilinir.
  • IntelliSense Desteği: Kod yazarken alan adları ve metotlar otomatik tamamlanır.
  • Derleme Zamanı Kontrolü (Compile-Time Checking): Alan adı hataları veya tip uyumsuzlukları anında derleme hatası verir.
  • Tek Tip Sözdizim: Nesneler (LINQ to Objects), veritabanları (LINQ to Entities / EF Core) ve XML (LINQ to XML) aynı felsefeyle sorgulanır.

8.2. LINQ Sorgularının Yürütülmesi: Ertelenmiş vs. Anlık Yürütme

LINQ sorgularının arka plandaki çalışma mantığı sınavlarda en çok test edilen akademik konulardan biridir:

Kavram Ertelenmiş Yürütme (Deferred / Lazy Execution) Anlık Yürütme (Immediate Execution)
Tanım Sorgu tanımlandığı satırda veritabanına veya koleksiyona gönderilmez; yalnızca sorgunun yürütme planı (IQueryable<T> veya IEnumerable<T>) hazırlanır. Sorgu yazıldığı anda anında bellekte veya veritabanında çalıştırılır ve gerçek veriler elde edilir.
Ne Zaman Çalışır? Veriler üzerinde bir foreach döngüsü başlatıldığında veya anlık yürütme metodu çağrıldığında çalışır. Metot çağrıldığı satırda anında yürütülür.
Tetikleyen Metotlar Where, Select, OrderBy, GroupBy, Take, Skip ToList(), ToArray(), Count(), Sum(), Average(), First(), Single()

8.3. LINQ Sorgu Sözdizimleri (Query Syntax vs. Method Syntax)

C#'ta LINQ sorguları iki farklı sözdizimiyle yazılabilir:

1. Sorgu Sözdizimi (Query Syntax - SQL Benzeri)

var sonuc = from o in ogrenciler
            where o.NotOrtalamasi >= 70
            orderby o.Ad ascending
            select o;

2. Metot Sözdizimi (Method / Fluent Syntax - Lambda İfadeli)

var sonuc = ogrenciler
            .Where(o => o.NotOrtalamasi >= 70)
            .OrderBy(o => o.Ad)
            .ToList();

Modern ASP.NET Core projelerinde genişletme metotları (Extension Methods) ve Lambda ifadeleri (x => x...) kullanan Metot Sözdizimi daha yaygın ve esnektir.

8.4. Sık Kullanılan LINQ Operatörleri ve Metotları

1. Filtreleme ve Sıralama Operatörleri

  • Where(koşul): Koleksiyondan belirli bir mantıksal koşulu sağlayan elemanları süzer: urunler.Where(u => u.Fiyat > 100)
  • OrderBy(alan): Küçükten büyüğe (artan - ascending) sıralar: urunler.OrderBy(u => u.Fiyat)
  • OrderByDescending(alan): Büyükten küçüğe (azalan - descending) sıralar.
  • ThenBy(alan) / ThenByDescending(alan): Birinci sıralamada eşit olan elemanları ikinci bir kritere göre sıralamak için zincirlenir.

2. Projeksiyon (Dönüştürme) ve Gruplama

  • Select(): Koleksiyondaki nesneleri yeni bir tipe (ViewModel veya anonim nesne new { ... }) dönüştürür: 
    var urunOzet = urunler.Select(u => new { u.Ad, u.Fiyat }).ToList();
  • GroupBy(): Belirli bir özelliğe göre elemanları gruplara ayırır (IGrouping<TKey, TElement>): 
    var gruplar = urunler.GroupBy(u => u.KategoriId);

3. Tekil Eleman Seçiciler (Kritik Sınav Konusu)

Metot Eleman Bulunamazsa Birden Fazla Eleman Varsa
First() Hata fırlatır (InvalidOperationException) İlk eşleşen elemanı döndürür.
FirstOrDefault() Varsayılan değeri (nesneler için null) döndürür. İlk eşleşen elemanı döndürür.
Single() Hata fırlatır (InvalidOperationException) Hata fırlatır (Tek bir kayıt olması zorunludur!).
SingleOrDefault() Varsayılan değeri (null) döndürür. Hata fırlatır!

4. Sayısal ve Mantıksal Toplama Metotları

  • Count(): Eleman sayısını döndürür.
  • Sum(), Average(), Min(), Max(): İlgili alanın toplamını, ortalamasını, minimum ve maksimum değerini hesaplar.
  • Any(koşul): Koşulu sağlayan en az bir eleman varsa true, yoksa false döner.
  • All(koşul): Tüm elemanlar koşulu sağlıyorsa true döner.

Sınav İpuçları ve Kritik Noktalar

Sınavlarda Sık Sorulan Sorular:
  1. Ertelenmiş yürütmeyi (Deferred Execution) anlık yürütmeye dönüştüren metotlar nelerdir? -> ToList(), ToArray(), Count(), First() vb.
  2. Eşleşen kayıt olmadığında hata vermeden null dönmesi istenen arama işlemi için ne seçilmelidir? -> FirstOrDefault() veya SingleOrDefault() (tek kayıt garantisi varsa).
  3. Single() ile First() arasındaki fark nedir? -> First() eşleşenlerden ilkini alır, arkasında 100 tane daha olsa hata vermez. Single() ise birden fazla eşleşme olursa istisna (exception) fırlatır.

9. Ünite: Entity Framework Core (EF Core)

Ünitenin Amacı: İlişkisel veri tabanları ile nesne yönelimli programlama dünyası arasında köprü görevi gören ORM (Object Relational Mapping) kavramını, Entity Framework Core mimarisini, Code-First yaklaşımı ile veri modelleri, DbContext ve Migration süreçlerini ve temel CRUD (Create, Read, Update, Delete) veritabanı işlemlerini kavramaktır.

9.1. ORM (Object Relational Mapping) Kavramı ve Avantajları

Nesne yönelimli programlamada (OOP) veriler sınıflar (Class) ve nesneler (Object) üzerinden temsil edilirken; ilişkisel veritabanı yönetim sistemlerinde (RDBMS: SQL Server, PostgreSQL, MySQL) veriler tablolar (Table), satırlar (Row) ve sütunlar (Column) halinde saklanır. Bu iki dünya arasındaki yapısal uyumsuzluğa "Nesne-İlişkisel Empedans Uyumsuzluğu" (Object-Relational Impedance Mismatch) denir.

ORM (Nesne İlişkisel Eşleme), bu iki farklı mimari arasında otomatik bir çeviri katmanı kurarak geliştiricinin SQL sorguları yazmak yerine doğrudan C# sınıfları ve metotları ile veritabanı işlemleri yapmasını sağlayan bir yazılım mimarisidir.

ORM'nin Başlıca Faydaları:
  • Geliştirme hızını (produktiviteyi) büyük ölçüde artırır.
  • Tip güvenliği sağlar; derleyici hataları anında yakalar.
  • Parametrik sorgular üreterek SQL Injection (SQL Enjeksiyonu) açıklarını kendiliğinden engeller.
  • Veritabanı bağımsızlığı sağlar; veritabanı SQL Server'dan PostgreSQL'e değiştirildiğinde kodların büyük kısmı aynen çalışır.

9.2. Entity Framework Core (EF Core) Mimarisi

Entity Framework Core, Microsoft'un .NET Core için sıfırdan geliştirdiği, açık kaynaklı, hafif (lightweight), genişletilebilir ve çapraz platform (Windows, Linux, macOS) destekli modern ORM aracıdır.

Projeye dahil edilmesi için gerekli temel NuGet paketleri:

  • Microsoft.EntityFrameworkCore: Çekirdek EF Core motoru.
  • Microsoft.EntityFrameworkCore.SqlServer: SQL Server sağlayıcısı (Provider).
  • Microsoft.EntityFrameworkCore.Tools: Migration ve veritabanı yönetim komutları (Package Manager Console için).

9.3. Code-First Yaklaşımı ve Adımları

EF Core'da en popüler ve modern yaklaşım Code-First (Önce Kod) yaklaşımıdır. Bu yöntemde veritabanı tabloları SQL ile önceden tasarlanmaz; önce C# sınıfları yazılır ve EF Core bu sınıflardan yola çıkarak veritabanını ve tablolarını otomatik oluşturur.

Adım 1: Entity (Varlık) Sınıflarını Tanımlama

public class Category
{
    public int Id { get; set; } // Varsayılan olarak Primary Key kabul edilir.
    
    [Required]
    [StringLength(50)]
    public string Name { get; set; }
    
    // Bire-Çok (1-N) İlişki için Gezinme Özelliği (Navigation Property):
    public virtual ICollection<Product> Products { get; set; }
}

public class Product
{
    public int Id { get; set; }
    
    [Required]
    [StringLength(100)]
    public string Name { get; set; }

    public int CategoryId { get; set; }
    public virtual Category Category { get; set; }
}

9.4. EF Core ile Temel CRUD İşlemleri

// 1. CREATE (Ekleme)
var yeniUrun = new Product { Name = "Laptop", Price = 25000, CategoryId = 1 };
_context.Products.Add(yeniUrun);
_context.SaveChanges(); // SQL INSERT çalıştırılır.

// 2. READ (Okuma)
var urun = _context.Products.FirstOrDefault(p => p.Id == 1);

// 3. UPDATE (Güncelleme)
if (urun != null)
{
    urun.Price = 27500;
    _context.SaveChanges(); // EF Core Change Tracker değişikliği algılar ve SQL UPDATE çalıştırır.
}

// 4. DELETE (Silme)
if (urun != null)
{
    _context.Products.Remove(urun);
    _context.SaveChanges(); // SQL DELETE çalıştırılır.
}

10. Ünite: Web API (Application Programming Interface)

Ünitenin Amacı: Dağıtık sistemlerin, tek sayfa uygulamalarının (SPA: React, Angular, Vue) ve mobil istemcilerin (Android, iOS) sunucuyla veri alışverişi yapmasını sağlayan Web API mimarisini, SOAP ile REST protokollerinin farklarını, HTTP durum kodlarını, RESTful CRUD işlemlerini ve ASP.NET Core Web API geliştirme standartlarını kavramaktır.

10.1. Web API Kavramı ve Modern Mimarilerdeki Rolü

Geleneksel web uygulamalarında sunucu istemciye HTML, CSS ve JavaScript çıktısı gönderir. Ancak günümüz dünyasında aynı iş mantığına web tarayıcılarının yanı sıra akıllı telefonlar, tabletler, IoT cihazları ve harici kurumsal servisler de erişmek zorundadır. Bu nedenle sunucunun kullanıcı arayüzü (HTML) üretmek yerine yalnızca saf veri (genellikle JSON formatında) sunması ihtiyacı doğmuştur.

Web API (Web Uygulama Programlama Arayüzü), HTTP protokolü üzerinden farklı platformların ve istemcilerin birbiriyle dil ve cihaz bağımsız şekilde iletişim kurmasını sağlayan web servisleridir.

10.2. SOAP vs. REST Mimarisi Karşılaştırması

Kriter SOAP (Simple Object Access Protocol) REST (Representational State Transfer)
Doğası Katı kuralları olan bir protokoldür. HTTP standartlarına dayanan hafif bir mimari stildir.
Veri Formatı Sadece XML formatını destekler. Ağırlıklı olarak JSON, ayrıca XML, metin vb. destekler.
Sözleşme / Tanım WSDL (Web Services Description Language) kullanır. Sözleşme şart değildir; modern standartta OpenAPI / Swagger kullanılır.
Performans & Yük XML etiketleri nedeniyle veri paketi büyüktür, bant genişliğini fazla tüketir. JSON hafif (lightweight) olduğundan çok hızlıdır, mobil uyumludur.
Önbellekleme (Caching) HTTP üzerinden POST ile çalıştığından önbellekleme zordur. HTTP GET istekleri tarayıcı ve ara sunucularda kolayca önbelleğe alınabilir.

10.3. HTTP Metotları ve RESTful CRUD Eşleştirmesi

REST mimarisinde her bir varlık (Resource) benzersiz bir URL (URI) ile tanımlanır ve işlemler HTTP eylemleri ile ifade edilir:

GET Read (Oku) /api/products veya /api/products/5 Verileri listeler veya tek bir kaydı getirir. Sunucuda durum değiştirmez (Safe). Evet
POST Create (Oluştur) /api/products İstek gövdesindeki (Body) verilerle yeni bir kayıt oluşturur. Hayır

10.4. HTTP Durum Kodları (Status Codes)

İstemciye dönen yanıtta işlemin sonucu standart HTTP durum kodları ile bildirilir:

  • 2xx Başarılı Kodlar:
    • 200 OK: İstek başarıyla işlendi ve yanıt gövdesinde veri döndü.
    • 201 Created: Yeni bir kaynak başarıyla oluşturuldu (Genellikle POST sonucunda döner ve Location başlığı barındırır).
    • 204 No Content: İstek başarılı oldu ancak dönecek bir gövde yok (Genellikle DELETE veya PUT sonucunda döner).
  • 4xx İstemci Hata Kodları:
    • 400 Bad Request: İstek formatı veya model doğrulaması geçersiz (Eksik/hatalı veri).
    • 401 Unauthorized: Kimlik doğrulama başarısız (Giriş yapılmamış veya token geçersiz).
    • 403 Forbidden: Kimlik doğrulanmış ancak kullanıcının bu kaynağa erişim yetkisi yok.
    • 404 Not Found: İstenen URI veya kaynak sunucuda bulunamadı.
  • 5xx Sunucu Hata Kodları:
    • 500 Internal Server Error: Sunucuda beklenmeyen bir yazılımsal istisna (Unhandled Exception) meydana geldi.
    • 503 Service Unavailable: Sunucu aşırı yük veya bakım nedeniyle geçici olarak hizmet veremiyor.

10.5. ASP.NET Core ile Web API Controller Geliştirme

Web API Controller sınıfları, klasik MVC Controller'larından farklı olarak Controller yerine ControllerBase sınıfından türetilir (çünkü View desteğine ihtiyaç duymazlar) ve sınıfın üstüne [ApiController] özniteliği eklenir:

[Route("api/[controller]")]
[ApiController]
public class ProductsController : ControllerBase
{
    private readonly AppDbContext _context;

    public ProductsController(AppDbContext context)
    {
        _context = context;
    }

    // GET: api/Products
    [HttpGet]
    public async Task<ActionResult<IEnumerable<Product>>> GetProducts()
    {
        return await _context.Products.ToListAsync();
    }

    // GET: api/Products/5
    [HttpGet("{id}")]
    public async Task<ActionResult<Product>> GetProduct(int id)
    {
        var product = await _context.Products.FindAsync(id);
        if (product == null)
            return NotFound(); // 404 döner

        return Ok(product); // 200 döner
    }

    // POST: api/Products
    [HttpPost]
    public async Task<ActionResult<Product>> PostProduct(Product product)
    {
        _context.Products.Add(product);
        await _context.SaveChangesAsync();

        // 201 Created döner ve oluşturulan nesnenin adresini header'a ekler:
        return CreatedAtAction(nameof(GetProduct), new { id = product.Id }, product);
    }

    // DELETE: api/Products/5
    [HttpDelete("{id}")]
    public async Task<IActionResult> DeleteProduct(int id)
    {
        var product = await _context.Products.FindAsync(id);
        if (product == null)
            return NotFound();

        _context.Products.Remove(product);
        await _context.SaveChangesAsync();

        return NoContent(); // 204 döner
    }
}
